# 성장용 계정 기반 · 2026-10-11

사용자 목표는 이름/설정만 보관하는 계정이 아니라, 승리로 받은 재화와 캐릭터 성장을 다음 접속에도 이어가는 것이다. 기준 `9db17ff`; 기존 자동 게스트＋선택 이메일 OTP 구조를 확장한다. 실제 Supabase 프로젝트와 운영 메일은 아직 미연결이다.

## 구현과 임시 규칙

별도 `?account=1&growth=1`에서 승수·코인·포인트·보유품·표시 아이템·플레이어 힘 단계를 연결했다. 두 query가 각각 한 번 있고 다른 query가 없어야 켜진다. 무기 고정/연구 입구와 일반판은 성장에서 제외한다. 원본 halfsword는 수정하거나 신규 열람하지 않았다.

임시 규칙은 1승10코인, 3승마다1포인트, 힘 단계당 근력 계수+2%(최대5단계). 힘은 다음 경기 시작에 기존 Fighter.strength에 절대값으로 적용하며 일시정지/재시작으로 중첩하지 않는다. 직접 피해량+2%나 무기별 밸런스 검증을 뜻하지 않는다. 첫 상점 상품은30코인짜리 여행자의 인장: 보유·표시/해제만 지원하는 장식이며 전투 무기/방어구 구매는 아직 없다. 일반판 수치 확정/승격이 아니다.

서버 정책·상품표가 가격/보상을 정하고 사용자별 행 잠금으로 거래를 직렬화한다. 직접 쓰기는 막고 본인 UID의 RPC만 허용한다. 요청 UUID＋내용을 기억해 같은 요청 재전송은 중복 지급/차감하지 않고 내용이 다르면 거절한다. 경기 표는 서버 발급, 미완료 이전 표는 다음 시작으로 폐기, 패배/동시 사망/중도 재시작에는 승리 보상 없음. 완료된 표의 같은 결과 재전송은 다음 표가 시작돼도 허용한다.

브라우저는 UID별 캐시/미전송 큐와 토큰을 사용한다. 성공 응답 유실 후 동일 UUID 재시도, 계정 변경 후 늦은 응답 무시, 너무 이른 결과만 PT425로 지연 재시도한다. 느린 경기 등록과 직후 결과/다음 시작은 순서대로 처리한다. 서버 등록에 실패한 경기는 연습으로 표시한다.

서버 미연결 상태는 Web Locks로 기기 내 거래를 직렬화하는 **기기 성장 연습**이다. 이 재화/강화는 실제 계정으로 이월하지 않는다. Auth UID와 성장 시험 공간 `halfsword-codex-growth-trial`은 분리되며 이름/설정의 앱 ID는 유지한다.

## 필요한 외부 연결

[휴대폰용 연결 안내](https://yoonjl-svg.github.io/halfsword-codex/growth-setup.html): 운영자 소유 Supabase 프로젝트 생성, 공개 Project URL/publishable key 제공, 새 프로젝트용 SQL 한 번 실행, 익명 가입/이메일 연결 설정. 비밀 키/DB 비밀번호를 채팅이나 공개 파일에 넣지 않는다. 기존 schema가 있으면 progression.sql만 추가한다. 운영 이메일 발송은 별도 SMTP 설정과 실제 OTP 검증이 필요하다.

공개 연습판과 SQL/이식 패키지를 전달해도 라이브 계정 개통 완료는 아니다. 외부 연결 후 실제 두 계정의 분리, 동시 요청, 이메일 연결 UID 유지/복구, 다른 기기 이어하기를 확인해야 한다. PWA 원본 적용/설치 확인도 별도다.

## 실패와 한계

초기 브라우저 시험은 getter인 alive에 대입해 사망을 주입하려다 무효였다. 이를 실제 die 함수 호출로 교체했다. 해당 실패를 자연 전투나 보상 코드 결함의 증거로 사용하지 않는다.

빠른 결과에서 등록 handle을 먼저 취소하면 결과가 누락될 수 있었다. 더 나아가 느린 begin 응답을 기다리는 동안 다음 begin이 서버에 도착하면 이미 끝난 경기 표를 버릴 수 있었다. 등록/결과 직렬 큐와 공통 flush promise로 교정하고 두 지연 회귀를 추가했다. 이미 폐기된 경기를 보상으로 되살리지 않는다.

서버가 검증하는 것은 거래/소유권/중복이지 경기 승패 자체가 아니다. 승리는 클라이언트 보고이므로 서버 심판·치팅 방지·유료 재화·랭킹/거래 운영 준비 완료로 보지 않는다. 미전송 승리 결과는 저장된 요청만 복구하며 페이지가 끝나기 전에 결과가 저장되지 않은 경우까지 보장하지 않는다.
