# 첫 화면을 바탕으로 만든 앱 아이콘 — 2026-10-17

사용자 요청: “우리 게임 첫화면을 토대로 앱 아이콘 새로 만들자. 나무 밑동에 검 박히고 낙엽 떨어지는 그 그래픽을 그대로 잘 쓰거나 응용하면 좋을 듯해. **그거는 만들면 우화에게 바로 전달.**” 이 작업은 완성 후 즉시 전달하도록 명시적으로 승인받았다.

## 기준과 변경

받는 쪽 최신 main `d5fca2f0da066e064878578099438b838ea81f73`에서 전달 가지 `codex/app-icon-handoff-20261017`를 만들고 이번 아이콘만 얹었다. 발행 직전 원격 main을 다시 확인한다. 결과 SHA와 메시지 SHA는 발행 영수증에서 고정한다.

실제 첫 화면 `docs/screenshots/start_pixel_sword/title-desktop.png`를 참조해 생성 도구로 응용했다. 원본 캔버스에서 직접 잘라낸 이미지라고 주장하지 않는다. 나무 뿌리 옆에 비스듬히 꽂힌 롱소드와 낙엽, 기존의 갈색·올리브·베이지 픽셀 색감을 이어간다. 글자·외곽 액자 없이 검을 크게 배치했다. 낙엽은 정적 아이콘에 그린 것이며 앱 아이콘 자체가 애니메이션되는 것은 아니다.

## 파일과 연결

- `public/icons/icon-192.png`, `icon-512.png`: 일반 앱 아이콘.
- `public/icons/icon-maskable-512.png`: 같은 불투명 정사각형 이미지. 검의 손잡이/칼끝이 중앙 안전 원 안에 있고 주변 나뭇잎·풍경은 잘려도 된다.
- `public/icons/apple-touch-icon.png`:180×180. `index.html`의 선언도180×180으로 맞췄다.
- `public/icons/favicon-32.png`, `favicon-64.png`: 탭용. 남아 있는 `px32.png`, `px32_mask.png`도 새 그림으로 맞춰 옛 방패 그림을 재사용하지 않게 했다.
- `index.html`: 아이콘3링크·manifest링크에 `?v=tree-sword-20261017`을 붙임. 그 외 내용은 수신판 그대로.
- `public/manifest.webmanifest`: 아이콘3주소에 같은 버전 질의값만 추가. 수신판 앱 이름 **Stillness**, `id`, `start_url`, `scope`, 표시 방향/색 유지.
- `public/encounters/app-icon-20261017/master.png`:1254×1254 생성 원본. 같은 폴더 `index.html`은 정사각·원형·실제 작은 크기 검토 페이지.
- `tools/content/export_app_icon_20261017.mjs`: 원본에서 최근접 표본으로 플랫폼 크기를 내보내는 도구. 창작 수정이나 픽셀 재생성이 아닌 규격 출력이다.
- 이 폴더: 생성 입력/프롬프트, 파일 해시/규격, 이전 아이콘, 화면 검사 결과와 스크린샷.

정사각 원본을 그대로 저장하며 둥근 모서리/원형은 OS가 표시할 때 적용한다. 기기별 OS 아이콘 캐시 때문에 기존 설치물의 즉시 갱신까지 보장하지 않는다. 새 링크와 manifest 갱신을 제공하되 사용자 저장 삭제나 PWA 강제 재설치 코드는 넣지 않았다.

## 검증

수신 기준에서 `npm run build` 성공. 실제 빌드 결과를 HTTP로 열어 manifest의192/512/512 규격, maskable 목적, apple180 선언/실제 이미지, favicon주소, 이름/시작주소를 확인했다. 모든8출력은 완전 불투명이며 해시를 보존했다. 390px/900px 검토 화면 로딩·넘침 없음, JavaScript 오류0. 원형/둥근 모서리 및32·64px 실제 표시를 시각 검토했다. [검증 JSON](verification.json), [900px 검토 화면](preview-900.png), [390px 검토 화면](preview-390.png), [출력 해시](exports.json).

실물 iPhone 홈 화면 설치·기존 설치물 갱신은 검사하지 않았다. 게임 물리·기력·유파·보법·프로필·계정/저장을 바꾸지 않았으며 전투 관문은 이 아이콘 변경의 검증으로 불필요하게 재실행하지 않았다. 수신판의 최근 동방 막기 보정도 그대로 보존한다.

## 이식과 되돌림

메시지에 고정한 최신 수신 기준→전달 결과 범위를 적용한다. main이 더 진행됐으면 같은 아이콘 파일과 위 최소 링크 변경만 옮기고 manifest의 앱 이름/시작주소는 받는 쪽 값을 유지한다. 우리 main 전체 병합은 필요 없다. 되돌림은 전달 커밋을 revert한다. 저장 형식 변경 없음.

이번 즉시 발송 대상은 **앱 아이콘**이다. 프로필 액자3안과 흘림 연구는 각각 사용자가 정한 별도 전달 조건을 유지한다.
