# 빠른 결과물 중심 개발 계획

**최신 사용자 판정:** [준비 자세·손 실패 일지](../strike/ready_grip_20261004.md). 새 손/소매 후보는 사람 손 외형을 충족하지 못해 철회하고 직전 공개 소스로 복귀했다. B 시작 생성·첫 입력 교정은 별도로 공개 전달했고 청강검·세이버·레이피어 모바일 입력/재시작을 확인했다. [전달 영수증](../strike/ready_grip_release.json)이 실제 상태의 기준이다. 기하학PASS를 손 형태 수락으로 쓰지 않는다. 일반 제어 승격은 없다.

**엄지 후속 정정:** 사용자 청강검 제보에 따라 [쥔 손 엄지 뿌리·관절·끝 방향](../strike/hand_opposition_20261004.md)을 수정·공개 확인했다. 앞선 거울/물리 검사는 해부학 수락이 아니었다. 일반 손 표시만 정정하고 한손 제어 기본값은 유지한다. 실제 공개 확인은 이번 영수증 기준이다.

갱신: **2026-10-04 KST**. 사용자 지시에 따라 기존 48시간 창을 **24시간 창**, 담당자 작업량 14–23시간을 **6–10시간 목표**로 압축한다. 기존 1–2주 우선순위 묶음은 **3–7일 실행 창**으로 재편한다. 이는 개발 목표이며 측정된 속도 향상이나 전체 물리 완성 약속이 아니다. 활성 작업의 실제 시간을 기록해 다음 창에서 수정한다.

첫 결과물은 폰에서 비교할 수 있는 작은 개선이다. 힘을 실은 베기, 무거운 검의 관성, 급한 방향 전환의 몸 부담과 빈틈을 살린다. 빠른 정지·작은 오차 자체를 사실감 점수로 삼지 않는다. 전신 연구의 완전 종료를 플레이판 전달의 선행 조건으로 두지 않는다.

우선순위 변경: 사용자가 제보한 **한손 팔 고정·역수처럼 보이는 자세(R0)**를 먼저 처리한다. [원인·선택형 비교](../strike/onehand_manual_round1.md)를 기준으로 실제 폰 판정을 마친 뒤 기존 R1로 이동한다.

**10/04 후속:** 사용자가 B를 “나아졌어”라고 평가했다. 청강검 B의 시작 목표 하향과 엄지 없는 손 외형을 먼저 수정·전달한다. [첫 자세·엄지 손 일지](../strike/initial_pose_and_hands_20261004.md)가 재현 입구다. 일반 무기15종·시험1종 첫 자세 검사에서 모노호시자오와 라이트세이버의 시작 흔들림이 남아 있어 전체 정상으로 선언하지 않는다. 엄지 외형은 일반 적용, 수평 시작 명령은 선택형 B에만 적용하며 팔 제어 일반 승격은 아직 없다.

## 비용과 실험 규칙

1. **30–45분에 첫 판정, 90분에 계속/기각 결정.** 한 회차는 질문1개·변경1개. 실패한 스칼라 제동 예측/gain·관절 교체·projected 지지·budgeted 절삭을 다시 권하지 않는다.
2. 첫 선별은 무기2종×기준/후보 **4실행**부터 시작한다. 개입/소스/입력 동등성은 기존 계측으로 확인한다. 긍정 효과 뒤에만 중단·재입력·알려진 부상/접촉 반례로 넓힌다. 실제 안전/동등성 의문이 있으면 필요한 검사를 추가한다.
3. 기존 원자료·교정·실패 trace·검증된 기준선을 재사용한다. 바뀐 소스/엔진/입력 계약만 다시 검사한다. 관찰 off는 새 계측의 비간섭 검증에 사용하고 변하지 않은 계측에 습관적으로 반복하지 않는다. 동일 궤적 반복을 새 독립 표본으로 세지 않는다.
4. 무거운 헤드리스와 화면 녹화를 동시에 돌려 제한 시간을 넘기지 않는다. 공통 소스는 배치 중 고정하고 통합은 순차 처리한다. 브라우저는 목적 효과가 남은 후보의 입력/화면을 보완한다. 문서 변경에 물리 회귀를 반복하지 않는다.
5. [실험일지 계약](../strike/EXPERIMENT_LOGGING.md)에 따라 **짧은 요약1개 + 수치/해시 JSON + 저장소 밖 원자료**를 남긴다. [실험 색인](../strike/EXPERIMENT_INDEX.md)에서 찾는다. 계획·일일 노트에는 결론과 링크만 넣는다.
6. 실제 개발 시간과 첫 플레이판까지의 시간을 기록한다. 실행 수를 성과 점수로 쓰지 않는다. 2배 이상 압축은 목표이며 실제 배수는 같은 범위의 측정 뒤에만 보고한다.

## 다음 승인 작업 · 재개 위치

**현재 R0:** [선택형 일지](../strike/onehand_manual_round1.md)와 [폰 A/B](https://yoonjl-svg.github.io/halfsword-codex/feature-lab.html#onehand-comparison)의 세이버·청강검·레이피어를 실제 공개 전달했다. 손 조작을 자세표가 완전히 덮어쓰던 경로와 raw 최대도달 포화를 분리했고 swivel2종은 후퇴로 제외했다. 후속 두 AI 실제 접촉6회에서 청강검 후보의 기립 복귀를 관찰했다. 팔/다리 절상은 그 뒤 발생했으므로 부상 후 복귀 근거로 묶지 않는다. down/마무리는 미관측이다. 레이피어 추종, 실제 마무리, 인간 부상 후 조작·화면 수락은 일반 승격 전 관문이다. 다음은 사용자 A/B의 팔/칼 방향·조작감 판정과 해당 반례를 좁게 처리한다. 미관측 마무리를 찾는 seed 전수 탐색과 실패 swivel 재시험은 하지 않는다.

**R0 판정 뒤 R1 예상45–75분:** 기존 연구 엔진의 팔꿈치 native 모터·중력 보상 공유 한도를 게임 harness에서 좁게 비교한다. 기존 API 교정과 실패 상태를 먼저 사용하며 엔진 차이와 실제 한도 개입을 구분한다. npm 엔진 전체 교체·메이저 일반 승격은 아직 없다. 사용자가 제보한 수정의 수락 전에 새 연구를 우선하지 않는다.

**이번 전달 뒤 첫 재개 과제 · 30–45분:** 모노호시자오·라이트세이버의 첫2초 흔들림 원인을 보존된 native/화면에서 좁힌다. 무거운 칼의 의도된 처짐과 제어 진동을 구별하고, 시작 명령/상태 연결의 작은 결함만 우선 검토한다. 힘·감쇠·관성 기본값 일괄 조정으로 가리지 않는다. 실제 원인/목적 효과가 없으면 시간 한도에서 기록하고 R1로 이동한다.

실행 종료 시 마지막 산출물/판정/다음 과제만 갱신한다. 원자료 해시·명령·실패 경계는 해당 실험일지에 남긴다.
