## 유보했던 두 검증의 판정 · 10/07 KST

사용자가 유보한 재베기 위력·잔여 회전 검증의 재개와 완료를 지시했다. 최신 일반판 `f395a13`을 기준으로 두 과제를 병렬 진행했다. 현재 검술 보정 v2·회복/재베기/타격 공통 적용·팔다리 절단 ON을 유지한다.

- **[재베기 뒤 실제 타격](../strike/recut_power_20261007.md):** 롱소드·청강검에서 제한기가 개입한 뒤 수동 재베기로 생존 상대를 벤 것을 확인했다. 손 이동이 끝난75–108ms 뒤의 관성 진행 구간이다. 검사한 재베기 속도·검 에너지 차이는 근소했으며, 청강검의 후속 골반 타격 감소에는 선행 위팔 절상과 타점·궤적 변화가 함께 있었다. 모든 타격의 피해 불변을 뜻하지 않으며 근력/피해 배율을 임의로 보상하지 않는다.
- **[잔여 회전](../strike/spin_followup_20261007.md):** 놓은 뒤 증가한 표본은 준비 자세 복귀 중이었고2초 연장에서 안정됐다. 세이버의 큰 최고치는 머리 접촉1step에서 발생해 다음step에 감소했다. 신체 접촉에도 기존 손아귀 제한을 적용한 후보는 이미 발생한 회전각을 고치지 못하고 소산 근사만 넓히므로 일반 적용하지 않는다.
- **중력:** 일반값9.81과 기존 +15%/+25% 비교판을 유지한다. 같은 높이 자유 낙하의 속도는 약7%/12%, 낙하 에너지는15%/25% 증가한다. 무거운 물체의 추가 에너지 절대량은 크지만 증가율은 같으며, 손에 쥔 공격의 피해·기립은 근력·관절·날 정렬·접촉의 영향도 받는다.

메모로 남았던 두 검증은 결과와 적용 여부까지 판정했다. 다음 개발은3단계의 실제 접촉·저항·상처 전달 일관성에서 재현 가능한 결함 한 건을 좁게 처리한다. 특정 표본 통과를 전체 물리·인간 동작 완성으로 바꾸지 않는다. [이번 기록과 폰 계획 전달](../strike/deferred_followup_release.json)에 실제 공개 상태를 남긴다.

아래의 유보 유지 지시는 이번 사용자 재개 지시 이전의 역사다.

## 단계 구분과 종료 계획 정정 · 10/06

**2단계가 남은 이유에는 일정 관리 오류가 있다.** 5회 목표를 해결·통합 전달 일정으로 제시했지만 실제 진행은 조사/후보 판정 묶음에 머물렀고 마지막 통합 장면도 확보하지 못했다. 검사 횟수를 채운 것은 목표 달성의 대체가 아니다. 같은 근거로 다시 몇 회면 끝난다고 약속하지 않는다.

[원래 중장기 계획](https://github.com/yoonjl-svg/halfsword-codex/blob/b0d861f1b2a75b3242d22dcb9af6e37135d66299/docs/codex_team/ACTIVE_PLAN.md#중장기-방향)의 단계 번호와 P-01~P-06을 구별한다. **2단계는 전신 타격과 빈틈, P번호는 전체 개발에 걸친 여섯 물리 과제다.** 최근 계획에서 이를 혼용해3·4단계 범위도2단계의 미완료 사유로 넣었다. 아래 구분을 현재 보고 기준으로 정정한다. 전체 여섯 과제와 최근 약속한 통합 전달은 그대로 추적하며, 구분 정정으로 완료 처리하지 않는다.

**2단계의 실제 남은 종료 작업:** (1) 알려진 재베기 목표 급변/무기 급회전의 수정 또는 공개 범위의 명확한 처리, (2) 현재v2의 한손/양손·주요 베기 방향·무장 유지 부상에서 협응/제동/재입력 대표 검증, (3) 최근5회 계획에서 약속한 회복B+반작용B의 실제 회복 후 수동 타격과 모바일 통합 전달. 기존 통과 결과는 재사용한다. 보류 항목이 남으면 완성 범위를 명시하고 전체 완료로 쓰지 않는다.

모든 native 관절의 힘·일을 아직 읽지 못했다는 사실은 계측 한계이며 그 자체가 게임 오류는 아니다. 전신 물리를 완전히 입증했다는 주장에는 추가 근거가 필요하지만, 그 전체 연구를 작은 개선판 공개의 선행 조건으로 올리지 않는다. 의도된 관성/지연을 없애거나 실패한 지지·절삭 후보를 되살리지 않는다.

**이번 점검은 계획 정정이며 게임 수정/2단계 종료가 아니다.** 실제 결함 수정과 대표 검증이 남아 있으므로 이번 한 턴에 전체 종료를 확약할 근거는 없다. 다음 구현의 첫60–90분은 재베기 결함 수정과 실제 회복 입력 구간 확보를 독립적으로 진행하고, 결과로 통합 전달 가능 여부를 판단한다. 근거가 부족하면 새 전체 완료 일정을 단정하지 않는다. 신규 메이저 일반 적용은 구체적인 결과 뒤 사용자 확인, 이미 승인된 변경은 재승인하지 않는다.

3·4단계는2단계의 모든 연구가 끝날 때까지 멈춰 두지 않는다. 의존성이 없는 작업은 병행한다. **현재 중장기 계획에서 독립된5단계는 확정하지 않았다.** 저장소 최상위README의 옛5~7단계(픽셀 스타일·콘텐츠·멀티플레이)는 초기 제품 로드맵의 역사이며, 현재 승인된 다음 일정으로 자동 적용하지 않는다.

## 비용과 실험 규칙

1. **30–45분에 첫 판정, 90분에 계속/기각 결정.** 한 회차는 질문1개·변경1개. 실패한 스칼라 제동 예측/gain·관절 교체·projected 지지·budgeted 절삭을 다시 권하지 않는다.
2. 첫 선별은 무기2종×기준/후보 **4실행**부터 시작한다. 개입/소스/입력 동등성은 기존 계측으로 확인한다. 긍정 효과 뒤에만 중단·재입력·알려진 부상/접촉 반례로 넓힌다. 실제 안전/동등성 의문이 있으면 필요한 검사를 추가한다.
3. 기존 원자료·교정·실패 trace·검증된 기준선을 재사용한다. 바뀐 소스/엔진/입력 계약만 다시 검사한다. 관찰 off는 새 계측의 비간섭 검증에 사용하고 변하지 않은 계측에 습관적으로 반복하지 않는다. 동일 궤적 반복을 새 독립 표본으로 세지 않는다.
4. 무거운 헤드리스와 화면 녹화를 동시에 돌려 제한 시간을 넘기지 않는다. 공통 소스는 배치 중 고정하고 통합은 순차 처리한다. 브라우저는 목적 효과가 남은 후보의 입력/화면을 보완한다. 문서 변경에 물리 회귀를 반복하지 않는다.
5. [실험일지 계약](../strike/EXPERIMENT_LOGGING.md)에 따라 **짧은 요약1개 + 수치/해시 JSON + 저장소 밖 원자료**를 남긴다. [실험 색인](../strike/EXPERIMENT_INDEX.md)에서 찾는다. 계획·일일 노트에는 결론과 링크만 넣는다.
6. 실제 개발 시간과 첫 플레이판까지의 시간을 기록한다. 실행 수를 성과 점수로 쓰지 않는다. 2배 이상 압축은 목표이며 실제 배수는 같은 범위의 측정 뒤에만 보고한다.
