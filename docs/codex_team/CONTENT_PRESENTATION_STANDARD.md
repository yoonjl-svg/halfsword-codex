# 캐릭터·스테이지 공개 형식 — 포크 이후에도 유지

2026-10-14 사용자 명시 선호: **새 스테이지와 캐릭터를 보여주는 웹페이지 방식, 전체 캐릭터 정면 도감의 방식과 형식을 앞으로도 계속 사용한다.** 새 포크·컨텍스트 압축·담당자 변경으로 폐기하지 않는다. 스타일을 새로 설계하기 전에 이 문서를 읽는다. 캐릭터 목록·수치·옛 설정까지 고정하라는 뜻은 아니다.

## 1. 새 캐릭터와 무대를 보여주는 페이지

- 휴대폰에서 바로 열리는 독립 웹페이지를 먼저 제공한다. 채팅 첨부 이미지에만 의존하지 않는다. 최종 답변에는 클릭할 수 있는 공개 페이지 링크를 넣는다.
- **이름과 짧은 분위기 설명 → 큰 실제 게임 화면 → 대련하기 버튼 → 캐릭터 정면/디테일 → 무대의 특징적인 풍경·오브제·소리 → 도감/일반 여정 링크**를 기본 흐름으로 삼는다. 내용에 맞게 일부를 생략하되 사진보다 설명이 앞서 길어지지 않게 한다.
- 무대는 실제 플레이 시점의 대표 사진, 공간의 깊이가 드러나는 풍경 사진, 공들인 특징 한두 곳의 확대 사진을 보여준다. 캐릭터는 정면 전신을 우선하고 옆·뒤·장식을 필요에 따라 더한다. 여러 캐릭터는 카드로 병렬 배치하고 휴대폰에서는 세로로 쌓는다. 부가 사진은 ‘다른 각도 보기’로 접을 수 있다.
- 실제 게임 렌더를 사용한다. 별도 캐릭터 관찰 장면은 그렇게 설명한다. 콘셉트 그림·문헌 참고 사진·미구현 제안은 실제 구현 사진과 구분한다. 촬영을 위해 카메라만 바꾸는 것과 플레이 중 자세를 구별한다.
- 큰 사진은 원본을 열 수 있게 한다. 전후 비교 요청에는 같은 구도·조명·축척을 유지하고 이전판 사진/링크를 남긴다. 이전판으로 들어가는 링크를 유지한다면 실제 이전 외형을 여는지 확인한다.
- 어두운 차콜/갈색 바탕, 밝은 본문, 절제한 금색 계열 강조, 넓은 사진과 짧은 캡션을 기본으로 한다. 무대별 분위기에 맞춰 색을 조금 조절하되 페이지의 사용법은 일관되게 둔다. 과도한 UI 장식보다 게임 외형을 돋보이게 한다.
- 대련 버튼은 해당 무대·상대·검토할 무기로 직접 들어간다. 임시 상대, 시안, 별도 테스트판 여부를 짧게 밝힌다. 기술 로그·해시·내부 실험 명칭은 개발 문서로 보낸다.
- 자연·적막·인공물과 자연물의 대비, 그 무대에서 들리는 소리를 짧게 소개한다. 역사적 장소나 대사를 썼으면 출처와 창작 각색 범위를 표시한다. 공통 페이지라는 이유로 새 오디오 플레이어나 기능을 매번 만들 필요는 없다.

## 2. 캐릭터 정면 도감

- 모든 현행 외형을 **정적 사진 한 페이지**에 모은다. 3D 엔진이나 계정을 불러오지 않는 가벼운 비교 도구다. 사진 링크는 JavaScript 없이도 열린다.
- 동일한 정면 정사영 카메라·조명·축척·발밑 기준선, 공통 휴식 팔 자세로 촬영한다. 캐릭터별 키를 임의로 같게 맞추거나 얼굴이 예뻐 보이도록 신체를 변형하지 않는다. 형상·장식·의상 소품은 유지한다. 손에 든 무기와 무기 후광은 빼고 무기 이름을 캡션에 쓴다.
- 기본 사진은 **720×960 WebP, 세로 3:4, 잘리지 않는 전신**. 관찰용 조명·자세의 사진임을 설명한다. 전투 중 조명·자세와 같다고 주장하지 않는다.
- ‘모아 보기 / 크게 보기’를 유지한다. 기본 열 수는 좁은 화면3/2, 600px 이상4/3, 1050px 이상6/4. 작은 화면에서도 글자와 전신을 비교할 수 있게 한다.
- 번호·이름·칭호·나이(불명 포함)·무기를 짧게 표시한다. 플레이어·시안·동일 인물의 다른 모습은 명확히 구분하고, 확대에는 출신 정보를 더한다.
- 확대 창에는 이전/다음 순환, 위치 번호, 닫기, 원본 사진 열기, 키보드 방향키/Escape, 배경 클릭 닫기, 스크롤 잠금과 원래 초점 복귀를 유지한다.
- **인원수와 이름은 현재 자료에서 계산한다.** 옛18인/17인 같은 숫자를 규칙으로 굳히지 않는다. 최신 사용자 명명·삭제 결정을 반영한다. 사용자가 제외한 세르파를 옛 템플릿에서 되살리지 않는다.
- 원본 출처 커밋/외형 버전·이미지 해시는 카탈로그와 manifest로 남긴다. 우화의 최신 적용본과 우리 시안이 섞이면 사진별 출처를 구별한다. 이전 사진을 새 소스에서 촬영한 것처럼 표시하지 않는다.

## 3. 원본 예시와 재사용 도구

촬영 도구는 현재 게임 소스·손 외형 연결·URL 인자·Playwright 경로에 의존한다. 특히 날짜가 붙은 옛 둔황 촬영 도구는 간장 고정 당시 버전이다. **새 무기 배정/현재 UI와 맞춰 수정한 뒤 사용**한다. 형식을 보존하는 것과 옛 도구를 그대로 실행하는 것은 다르다.

도감 생성 순서는 현재 소스/카탈로그 확인 → 변경된 캐릭터만 촬영 → `node tools/content/build_character_roster.mjs` → 이미지/메타데이터 일치 확인이다. 촬영 도구의 `CAPTURE_IDS`로 변경 범위를 좁힐 수 있다. 포크에서 ID·외형 함수가 바뀌면 먼저 매핑을 갱신한다.

## 4. 전달 확인과 포크 이전 절차

- 실제 페이지 변경 시 휴대폰 세로·가로에서 사진 로딩, 스크롤/넘침, 대련 링크를 확인한다. 도감 배치 변경은320/390/844/1200px의 두 보기와 확대 이동/닫기/원본을 확인한다. 사진만 바뀌면 해당 사진/메타데이터 중심으로 검사한다.
- 게임 진입 동작이 바뀌면 실제 터치 공격·이동·일시정지/재개·재시작을 확인한다. 공개 배포 완료와 링크/새 자산 전달을 확인한 뒤 ‘볼 수 있다’고 보고한다. 문서만 저장할 때 게임 빌드·물리 회귀·촬영을 반복하지 않는다.
- 새 포크 시작 시 이 문서와 보존 묶음을 읽고 새 `AGENTS.md` 또는 시작 인계 문서에 이 지침을 연결한다. 일지 자동화 보존과 함께 이전 체크리스트에 넣는다.
- 원본 지침과 템플릿/사진 묶음은 저장소 밖 `/workspace/halfsword-handoff/presentation-format-20261014/`에도 보관한다. 이는 참고/이식 자료이며 독립 실행되는 게임 전체가 아니다. 새 작업공간으로 이전할 때 이 묶음을 함께 전달한다.

이번 요청은 승인된 **표현 방식의 보존**이다. 페이지 내용 갱신이나 모든 캐릭터 재촬영, 새 디자인 실험은 요구하지 않는다.
