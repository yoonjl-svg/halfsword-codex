# 자동 개발·개선 미션

2026-10-02 사용자 지시: “일 하고 있어? 자동 개발 및 개선을 너의 미션에 넣어”.

**미션은 중력·체중·관성·전신 협응이 실제 결투의 조작과 타격에 드러나도록, 승인된 개발을 스스로 선택하고 검증하면서 계속 개선하는 것이다.** 디렉터는 조율과 통합을 맡고 어려운 핵심 문제를 직접 푼다. 사용자의 추가 지시나 응답을 기다리는 것을 기본 상태로 삼지 않는다. [P-01~P-06](../strike/physical_realism_plan.md) 전체가 대상이며 하나의 비교판 완료로 미션을 닫지 않는다.

## 실행 순환

1. 실제 Git 상태·최근 실패·사용자 피드백을 읽고 가장 중요한 미해결 과제를 선택한다. 시작 전에 예상 시간을 알린다.
2. 원인 가설과 반증 조건을 정하고 작은 후보를 만든다. 독립적인 실험/검토는 PM에게 범위와 소유 파일을 지정한다.
3. 실제 게임 코드와 통제된 같은 상태/입력으로 측정한다. 계측이 동작을 바꾸지 않는지 확인한다. 수치와 인간 체감은 따로 판정한다.
4. 실패하면 원자료를 보존하고 다음 가설을 실행한다. 일부 수치 개선으로 기립·전신 물리가 해결됐다고 하지 않는다.
5. 통과한 수정/분리 후보·재현 명령·소스 SHA·한계를 독립 저장소에 보존한다. 필요하면 휴대폰 웹 비교판을 제공한다.
6. 결과를 보고한 뒤에도 **활성 실행과 기존 승인 범위 안에서** 다음 과제를 계속한다. 장시간 사용자 무응답 때문에 멈추지 않는다. 메이저 일반 반영의 확인이 필요하면 후보를 먼저 완성하고, 그동안 다른 독립 과제를 진행한다.

## 실제 자동 실행과 한계

- GitHub Actions의 [자동 검사](automatic_checks.md)는 성공한 소스 전송 뒤와 2시간 간격으로 검사 필요성을 확인한다. 관련 소스가 같으면 기존 결과를 재사용하고, 실패를 성공으로 바꾸지 않는다. 수동 force 실행도 제공한다. 실제 설정·실행 성공은 Actions run과 소스 SHA로 확인한다.
- 자동화는 실제 물리 회귀/빌드/결과 보존이다. 새 가설 작성, 코드 수정, 의미 감사, 모바일 체감 수락은 AI 활성 세션 또는 사람의 작업이 필요하다. **예약 검사와 자동 AI 개발을 동일하게 부르지 않는다.**
- 현재 연결 도구에는 대화 종료 뒤 이 디렉터를 다시 호출하는 예약 기능이 없다. 미션 파일을 작성했다고 상시 AI가 실행되는 것은 아니다. 종료 후 지속 여부는 실제 실행 프로세스/예약 근거로만 보고한다. GitHub 예약은 지연될 수 있고 정시 실행을 보장하지 않는다.
- 활성 세션은 검사 실패를 읽고 수정/새 실험을 우선한다. 통과한 동일 입력을 반복해 토큰·실행 비용을 소모하지 않는다. 검사 강도를 낮춰 실패를 숨기거나 문턱을 게임 제어에 넣지 않는다.

## 이어갈 과제

| 우선순위 | 과제 | 다음 판정 기준 |
|---|---|---|
| 1 | 실제 누움에서 upright 모터를 관절 삭제 없이 비활성화 | 같은 native 시작/요청에서 실제 enabled bit를 검증. 첫 스텝 에너지와 이후 지지·재넘어짐을 구분 |
| 2 | 손/무릎→발 하중 이전과 도달 가능한 발 배치 | 지면 접촉·마찰·관절 한도 아래 건강/부상 기립, 무접촉 받침·발사·옆 미끄럼 회귀 |
| 3 | 근력 한도 아래 몸통→팔→검의 가속·중력 이점·제동 | native 모터와 명시적 토크의 범위를 구분. 내려베기/올리기/횡베기·약화·충돌 대조 |
| 4 | 타격 반작용과 손상·신체 모델·휴대폰 체감 통합 | 실제 전달 충격·에너지·부상 결과, 한손/양손/둔기·메뉴/입력·사용자 평가 |

목록의 순서는 새 증거에 따라 조정한다. 현재 결과와 실행 명령은 팀 README 및 각 연구 보고를 따른다. 기존 원본 수정 금지, 시간 밖 상대 신규 자료 접촉 금지, 비공개 지시의 공개 금지, 메이저 일반 반영의 사용자 확인은 그대로 적용한다.
