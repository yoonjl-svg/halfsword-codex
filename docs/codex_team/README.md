# 혼합안 독립 개발 인계

이 문서는 이번 작업에서 새로 작성한 인계서다. 최초 첨부 패치와 원래 `AGENTS.md`/팀 README는 확보하지 못했다.

## 목표와 기준

- 총괄은 **조율자이자 에이스**: 효율적인 분업, 비용 관리, 결과 검증·통합, 어려운 핵심 문제의 직접 해결을 책임진다.
- 우화는 기본적으로 **경쟁자**다. 같은 디렉션에서도 독자적인 판단과 영리한 설계로 더 좋은 플레이 결과·개발 효율을 추구한다. 상대의 결론은 검토 자료이며 우리의 정답을 대신하지 않는다. 실제 사용자 체감·물리 일관성·회귀·시간과 비용으로 성과를 확인한다. 필요한 장점 교환은 유지하며 접촉은 정기 회차로 한정한다.
- 총괄 애칭은 **샛별**, 페이블 디렉터는 **우화**다. 사용자가 전달한 우화의 제안을 2026-10-01 받아들였다.
- 게임의 현재 목적은 손으로 검을 조작하며 거리·무게·힘·허점을 읽는 긴장된 결투다. 사용자 플레이가 자연스러움의 최종 판단이다.
- 독립 기준은 `14bcf1fe6bd205c775db91aa4ca36b9841b6d2bd`, 작업 가지는 `codex/hybrid-support`다.
- 원본 저장소는 수정하지 않는다. 원격은 `https://github.com/yoonjl-svg/halfsword-codex.git`다. 연결 앱의 생성 권한 부재(403)는 사용자가 빈 저장소를 생성하여 해결했다. 이 환경의 직접 Git 업로드는 별도 401이 있어, 정상 인증되는 GitHub API와 Actions로 커밋 이력을 보존해 전송했다. `main`/작업 브랜치의 트리 일치와 원격에서 다시 받기를 검증했다. [전송과 배포 절차](github_delivery.md)를 따른다.
- 최신 원본 `/support/`와 `/corr/`의 빌드 산출물은 조사했으나 해당 탐색 소스 커밋은 확보하지 못했다. 이번 소스 빌드는 본판 검술 보정 기준이며 corr v2 5차 통합판이 아니다.

## 현재 작업

2026-10-02 사용자는 그립 반작용 시험을 “괜찮았어. 엄청 크게 체감되는 차이는 아니었어”라고 평가하고 다음 작업을 지시했다. paired 그립을 기본값으로 승격하며 이전 legacy는 `physicsTrial=legacyGrip`으로 보존한다. [지지 반작용 2차](../strike/support_transfer_round2.md)는 실제 접촉 확인·골반↔발 내부 힘쌍·무접촉 보조 차단을 선택형 `physicsTrial=support`로 구현한다. 일반 지지 방식은 legacy다. 건강/편측 손상 기립은 마지막 자세를 회복하지만 더 느리고 전환 중 미끄럼 및 전진의 후퇴 신호가 있어 자연스러움 개선 완료가 아니다. [소스·배포 상태](../strike/support_transfer_release.md)를 확인한다. 다음은 남는 수평 추진/직립 보조와 기립 전환의 하중 이전을 분리하고 몸통→손 목표 간섭을 측정하는 것이다.

앞선 [힘 전달 1차](../strike/force_path_round1.md)는 실제 힘·일·운동량 장부, 네 상태의 바닥 제거 대조, 공통 작용점의 그립 반작용을 구현했다. 일반 그립 legacy라는 당시 문서는 역사적 상태이며 위 승격이 최신이다.

두 팀의 정기 교환은 [개발자 교환 규약](../dev_exchange/README.md)을 따른다. 운영 비교 기준은 2026-10-01 18:00 KST, 매일 23:30 발행·다음 날 00:00 상대 보고 수신이다. 기술 분기 SHA와 운영 시각을 구별한다. 기록 전용 `dev-exchange` 가지를 사용하며 자동 수신과 실제 의미 검토 상태를 분리한다.

최신 지시: 두 팀이 같은 문제를 다른 방법으로 연구할 수 있으며 분담·중복 회피를 강제하지 않는다. 상대 자료·남김말·게임과의 접촉은 자정 정기 회차(00:00–00:20 KST)로 한정한다. 그 밖에는 조회·플레이·수신본 열람·재시도하지 않는다. 질문과 답은 우리 초안에 모아 23:30 보고로 보내고, 세션 시작 시 미검토 상대 자료를 자동으로 읽던 지침은 폐기한다.

사용자 전달 회신: 우화는 우리 `dev-exchange:docs/devmeet/YYYY-MM-DD.md`의 자정 열람 설정, 자기 `main`의 같은 경로와 manifest 발행 계획, 공통 조상 `14bcf1f` 정정 수용을 알려 왔다. 실행·파일을 직접 확인한 것은 아니다. 전신 타격 연구는 각자 진행하고, 우화의 R2 실패 조건은 정기 회차에 확인할 대상으로 기록했다.

2026-10-02 자정 회차에서 [실제 첫 검토](../dev_exchange/reviews/2026-10-02.md)를 마쳤다. 일지/manifest·작성 노트 해시를 검증하고 남김말·R2 진단·S-003 patch를 읽었다. 상대 코드 채택은 없다. 상대 세션 예약 실행 자체는 미검증이며, 자동 수신과 디렉터 의미 검토는 별도 상태다. 이미 얻은 검토 결과는 이후 독립 개발에 사용할 수 있지만 시간 밖 미검토 상대 자료 조회는 계속 금지한다.

2026-10-01 추가 요청: [스포츠 생체역학 원문 5편](../strike/sports_biomechanics_research.md)으로 힘 생성·분절 전달·제동·접촉의 검증 항목을 정리했다. [모르겐슈테른](../strike/morgenstern_trial.md)은 고정 철구의 선택형 시험 무기이며 일반 카드 목록에는 아직 넣지 않았다. [사지 절단](../strike/limb_sever_trial.md)은 URL로 켜는 팔꿈치/무릎 시험과 별도 합성 상처 시연으로 준비했다. [저체력 숨소리](../strike/breath_volume_adjustment.md)는 이벤트 gain을 12.5% 낮췄다. 모바일 진입은 `/feature-lab.html`이며 메이저 변경의 일반 적용은 사용자 확인을 따른다.

신체 모델도 검증 대상이다. [모델·협응 조사](../strike/body_model_assessment.md)에 실제 몸 강체 14개/연결 관절 13개, 고정 어깨점·손/전완 단순화·자기 충돌 제외·발 추가 질량을 기록했다. 기립은 전신 물리와 같은 체중 지지 체계를 검증하는 필수 세부 과제로 유지한다. 관절을 일괄 추가하기보다 동작에 필요한 표현과 기존 제어의 간섭을 구분한다.

최신 방향: 사용자 체감에서 B(.1/on/1)가 A보다 약간 나았으므로 B를 비교 화면의 첫 플레이로 둔다. [2×2 결과](../strike/support_matrix_round2.md)를 완성했으며 일반 게임 기본값은 그대로다. **상위 목표는 중력·가속도·관성·체중이 전신 타격에 전달되는 물리**이며 다리 허우적거림은 이를 드러낸 증상이다. [전신 물리 개선 계획](../strike/physical_realism_plan.md)을 따른다. 첫 접촉 기반 기립 R0는 건강한 기립도 막아 기각했고 재현 패치로만 보존했다. 공개 게임에는 연결하지 않았다.

2026-10-01 사용자가 이전 사운드 PM의 `slash35_heavy` 적용을 승인했다. 기록의 35차 강베기(`slashHeavy`, 커밋 `7119944`)에 대응한다고 판단하여 `SOUND.fleshHit='samsho'`를 기본으로 활성화했다. 보통 베기·베고 지나감·찌르기도 원래 35차 세트의 변형을 쓴다. 정확한 후보명 매핑과 과거 기록은 `docs/handoff/sound_pm_state.md`를 참고한다.

사용자는 반사를 완전히 끄면 다리가 흐물거리고 **무릎을 꿇었다가 일어나기 어렵다**, 기본 받침도 0보다 조금 있는 편이 자연스럽다고 보고했다. 확인된 결함을 고친 뒤 동일 코드에서 지원 조합을 비교하는 혼합안을 승인했다.

- `7da5f3f`: 기울기 계산의 임시 벡터가 보행 전방 벡터를 덮던 결함 수정.
- `d36d66d`: 반사 방식·강도 조절, 선택적 실제 받침 힘 관찰, 비교 화면과 기립 검사.
- 후속 도구는 부상·동시 손 입력의 무릎 기립, 기립 보조 종료 뒤 관찰, 부상에 따른 의도된 자세 낮춤을 구분한다.
- 결과와 잠정 후보는 `docs/strike/hybrid_support_round1.md`를 본다. 세부 운영 기록·원문 연구 인계는 작업공간의 저장소 밖에 보관한다.
- 사용자가 추가로 지적한 것은 **기립 중 옆으로 흐느적거림과 검의 중력·관성 체감 부족**이다. `docs/strike/knee_gravity_diagnosis.md`에 별도 계측과 구조상 한계를 기록했다. 후보 A는 해결값으로 확정하지 않았다. 실제 사용자 최신 빌드의 같은 장면은 아직 재현하지 못했다.
- 사용자에게 당시 상황의 추가 특정을 요구하지 않고 전투 중 부상·옆 충격 자동 시험으로 넓힌다. 반복 검사는 [헤드리스 실행 원칙](headless_workflow.md)을 따른다. 작업 시작에 예상 시간을 알리며, 답변이 없어도 독립 가능한 개발을 계속하고 메이저 변경의 본판 반영은 사용자 컨펌을 받는다.

## 실행과 검증

```sh
npm ci
npm run dev
# /support-lab.html 에서 비교 후보를 연다.
node tools/sim/balance_axes.test.mjs
node tools/sim/catch_response.test.mjs
node tools/sim/support_options.test.mjs
node tools/sim/support_probe.mjs --assist=0.2 --catch=on --scale=0.5 --seeds=7 --out=/tmp/support-candidate.json
node tools/sim/gravity_probe.mjs /tmp/gravity.json
node tools/sim/knee_lateral_probe.mjs --candidates=baseline,mixed,off --conditions=healthy,hurt --seeds=7 --out=/tmp/lateral.json > /tmp/lateral.stdout.log
npm run build
```

- `?supportProbe=1&assist=0.2&catch=on&catchScale=0.5`는 이번 접속에서만 적용된다. 일반 접속의 비교 기준값은 받침 0.3·반사 on·강도 1이다.
- `catch=fall`은 균형 이탈만으로 반사를 요청한다는 뜻이다. 실제 쓰러짐 상태를 검사하는 옵션은 아니다.
- 반사 off에서도 기립 직후 넘겨받기 `levH`, 높이 스프링·감쇠와 균형 걸음은 남는다. 강도를 낮추거나 끄면 이전 `levC`가 새 설정보다 크게 남지 않게 한다.
- `balanceProbe`의 적용 힘과 적용 전 요구 성분을 구분한다. 이 계측은 전체 외력·관절 총토크 장부가 아니다.
- `ok`는 명시된 관찰 조건을 충족했다는 뜻이다. 인간 동작에 가장 가깝다거나 사용자 체감 문제를 해결했다는 뜻이 아니다.
- 동일 궤적의 중복 시드를 독립 표본으로 세지 않는다. 원문 연구 결과를 근거 없는 관절 한도·반사 이득으로 복사하지 않는다.
