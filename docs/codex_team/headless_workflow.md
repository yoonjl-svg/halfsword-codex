# 헤드리스 실행과 사람의 플레이를 연결하는 방식

물리 반복 계산은 Node.js에서 실제 Rapier/Fighter/Gait/AI/Combat 코드를 실행한다. 매 스텝마다 언어 모델을 호출하지 않는다. PM과 디렉터는 실험 코드·원인 분석·검토에 집중한다. 사용자는 나중에 비교 테스트판을 플레이해 체감 피드백을 준다. 사용자가 당시 설정을 특정하지 못해도 시험·연구를 계속한다.

## 현재 같은 것과 따로 맞춰야 하는 것

`tools/sim/harness_m.mjs`는 `src/main.js`의 핵심 순서인 시선 지정 → AI → player/enemy.step → cacheState → world.step → combat.afterStep를 따른다. 같은 물리 모듈·기본 중력·시간 간격·평면 마찰을 사용한다. 조건별 seed, 무기, 건강, 받침·반사, 입력과 변경 시각을 기록한다. 기본 플레이어는 수동 표적이므로 AI 대 AI에는 반드시 `AI2Class`도 지정한다.

다음 항목은 자동으로 같아지지 않는다.

- 브라우저의 터치/마우스 사건·프레임 누적·지연·hitstop 시간 배율.
- 캐릭터·방어구·부활·감정·자동 자세 보정·이동/밀치기 옵션과 저장된 선택.
- URL 옵션·화면·소리·부수 사건 처리와 난수 소비 순서.
- 벽을 끄거나 상대를 멀리 옮긴 실험의 전투 조건.

따라서 현재 도구를 같은 물리 코드의 자동 실행이라고 부르되, 모든 브라우저 상태와 스텝별 동일성을 증명한 쌍둥이라고 부르지 않는다. 기존 `fights12`/`live_battery`는 별도 `jelly_harness`를 쓰므로 더 좁은 구성 옵션도 확인한다.

## 검증 순서

1. 고정 seed·입력으로 결함을 재현하고 실패 시점의 상태·힘·기하를 보관한다.
2. 작은 변경은 같은 조건으로 전후 비교한다. 중복 궤적을 독립 표본으로 늘리지 않는다.
3. 실제 전투의 충돌 부상·기립을 수집하고 정적 시험과 대조한다. AI 승률만으로 인간 동작을 판정하지 않는다.
4. 브라우저에서는 실제 입력 사건과 옵션·화면을 확인한다. 초기값·난수·입력 시각이 같은 물리 스텝 상태 대조는 별도 관문이다.
5. 사용자가 테스트판을 플레이한다. 기립 제어/검 조작 같은 메이저 변경은 구현과 비교 결과를 준비한 뒤 본판 반영 전에 컨펌을 받는다.

작업 시작에는 예상 시간을 알리고 범위가 커지면 갱신한다. 응답이 없어도 독립 가능한 개발을 계속한다. 도구 실행 시간과 게임 안에서 진행된 시간을 함께 남기되, 그 비율을 전체 개발 속도나 토큰 비용 절감률로 바꾸어 말하지 않는다.
