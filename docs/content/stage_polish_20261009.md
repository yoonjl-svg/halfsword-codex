# 세 무대의 표면·공간·소리 보완 · 2026-10-09

## 목적과 승인

사용자는 기존 무대와 신규 무대의 비교 후 보완을 승인했다. 각 무대의 ‘킥’은 큰 장식을 하나 더 놓는 뜻이 아니라, 회랑의 바닥처럼 특정 부분의 만듦새에서 공을 들였음을 느끼게 하는 것이다. 이어 보이는 세부 움직임과 소리도 함께 설계하도록 요청했다. 기준은 `d5afa20`이며 이전 외형/비용 비교는 [기존 감사](stage_style_audit_20261009.md)에 보존한다.

## 구현

| 무대 | 집중한 시각 디테일 | 연결한 소리 |
|---|---|---|
| 붉은 회랑 | 1024² 석재 상감: 큰 로제트·맞물린 테두리·주변 메달리온·돌별 결/마모. 뒤가 막힌 아치를 실제 겹친 아치로 개방 | 기존 돌 발소리/짧은 잔향과 전용 낮은 바람. 붉은 천의 바람 절정에 천 마찰 |
| 산호 항구 | 삼각 돛의 재단/겹침/보강 모서리·수선, 선체 널판/코킹/닳은 뱃전, 실제 계선주에 닿는 굵은 로프 | 잔잔한 바다. 돛이 당겨지는 순간의 낮은 목재/밧줄 마찰과 부두 물결 |
| 신목의 숲 | 흙에 이어지는 판근·수피·이끼, 요철을 감싸는 꼬인 금줄과 접힌 종이, 입체 수관 | 낮은 숲 바람/먼 물소리. 수관과 종이의 움직임에 연결한 마찰 |

공통 전투/리볼버 음량과 물리·피해·캐릭터는 이번에 변경하지 않았다. 새 무대의 무기 카드 뒷면은 각각 상감/돛과 로프/신목 문양을 사용한다. 기존 카드 PNG는 재생성 후 바이트 변경이 없다. 공개 선택 페이지에 실제 배경 상세 화면을 추가했다.

소리는 외부 녹음/유료 생성 없이 기존 WebAudio 위에서 합성했다. `stage.onEvent('stageDetail', {kind, amp, pos, seed, time})`를 시각 움직임의 위상에서 발생시킨다. 별도 실제 시간 타이머를 만들지 않는다. 종류별 4–7초·전체 2초 제한, 최대 2음, 카메라 기준 거리/좌우, 파형 재사용이 적용된다. 무음·일시정지·무대 전환 시 재생 중인 세부음을 정리한다. 새 무대 환경음도 일시정지 중 줄고 복귀한다. 숲에서 화면에 없는 사찰 풍경종을 재사용하던 경로는 제거했다.

## 검증과 한계

근거는 저장소 밖 `/workspace/halfsword-handoff/stage-polish-20261009/`에 보존한다. 하위 `loggia/`, `corsair/`, `grove/`의 실제 stage-only WebGL 캡처/계측과 `audio/`의 원본 WAV·브라우저 오디오 검사를 사용한다. 새로 관측한 결함만 다시 검사하며 기존 9무대 감사를 반복하지 않는다.

- 초기 회랑 질감의 불필요한 선과 항구의 반복 질감 경계를 시각 검사 후 교정했다.
- 초기 숲 금줄의 몸통 파묻힘과 납작한 수관은 root 시각 검토 후 교정했다.
- 회랑 dev 게임 캡처가 동시 편집의 HMR 재탐색에서 시간 초과했다. 이 시도를 통과로 세지 않고 최종 고정 빌드의 실제 모바일 흐름으로 통합 검사를 한다.
- 음원 유한값·무음 여부·클리핑, 실제 클릭에 의한 AudioContext 시작, 겹침 제한, 무음/일시정지/전환/노드 정리를 검사한다. 파형 검사는 사람의 청취 품질 평가가 아니다. 실제 휴대폰 스피커에서의 가청성과 적절한 음색은 사용자 플레이로 판단한다.
- 배경 비용은 형상/인스턴스 및 RGBA8+mipmap 추정이다. 전체 GPU 메모리나 실제 휴대폰 FPS를 의미하지 않는다.

최종 빌드·모바일·공개 전달 결과는 [전달 기록](stage_polish_release.json)에 남긴다. `verified` 상태가 되기 전에는 배포 완료로 세지 않는다.
