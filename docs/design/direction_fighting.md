# 방향 3 — 대전 격투: 사람과 겨루는 결투

- 작성: 기획 PM, 2026-09-30. 근거: `docs/design/structure_map.md`(main `851d0af`), `docs/decisions.md`. 기준은 지금 본판이며 R2 뒤 한 절 덧붙인다(Q-S1).

## 요약 10줄
1. 대전 격투는 "같은 규칙으로 두 사람이 겨룬다"의 게임이다. 우리 결투는 이미 1대1이고, 플레이어와 AI가 같은 두 채널(손 목표·이동)로 싸운다 — 상대 자리에 사람을 앉히는 일이 구조상 가장 짧다.
2. 핵심이 그대로 주는 것: 1대1 판, 결정적 고정 스텝 물리(같은 입력 → 같은 결과), 검객 로스터 6·무기 15, 자세 이름 표시, 기술 12·속임수 4(AI용이지만 '기술표'의 씨앗), 승패·사인.
3. 새로 필요한 것: ① 둘째 플레이어 입력(한 기기 분할 또는 온라인), ② 대전 틀(캐릭터·무기 선택, 몇 판 승부, 결과·전적), ③ 사람이 고르는 동작 몇 개(밀치기·발차기·잡기 — 이미 설계 중), ④ 연습 모드·되감기.
4. 온라인은 결정적 시뮬 덕에 "입력만 주고받는" 방식(롤백)이 이론상 맞는다. 단, 기기마다 부동소수점이 같은지(WASM Rapier)는 검증이 먼저다. 네트워크 허용 자체가 사장님과 논의 중이다.
5. 한 기기 두 손가락(가로 화면 좌우 분할)은 조작 면적이 반이라 감기 궤적이 좁아진다. 태블릿에서만 될 수 있다.
6. 비용 어림: 로컬 대전(분할 화면·선택·3판 승부) 3~4주. 온라인 롤백 대전 10~14주(결정성 검증 2주 포함). 연습 모드 1주.
7. 핵심을 해치는 지점: 시간제한·체력 바·라운드 구조는 "한 수로 끝나는 적막"과 정반대다. 넣지 않는다. 대신 "먼저 베인 쪽이 진다, 3판"이면 된다.
8. 밸런스가 격투 방향의 본체가 된다: 무기 리그(91짝)·캐릭터 라운드로빈 도구가 이미 있어 AI 대 AI로는 잴 수 있지만, 사람 대 사람 밸런스는 시뮬로 못 잰다(사장님 규칙). 실제 대전 기록이 필요하다.
9. 참고: 부시도 블레이드(일격·체력 없음·자세), Hellish Quart(물리 검술 격투), Nidhogg(한 수·왕복), 사무라이 스피리츠(간격·한 방), For Honor(자세 3방향). 우리가 다른 점: 궤적을 손가락이 직접 긋는다, 재생 동작이 없다, 갑옷·상처가 물리.
10. 사장님이 정하실 것 7가지는 끝에.

## 1. 우리 핵심이 그대로 주는 것
- **같은 채널**: fighter의 `handOffset`·`move`·`skill.thrust()` 세 개가 플레이어·AI 공통 접점이다. 둘째 사람은 이 세 개에 입력을 넣는 새 `input` 하나로 들어온다.
- **결정성**: 1/120 s 고정 스텝, 시드 난수(fights12가 바이트 동일 관문). 입력 기록만 있으면 판을 그대로 재생할 수 있다 → 되감기·전적 재생·롤백 온라인의 바탕.
- **로스터**: 검객 6(외형·목소리·대사), 무기 15(카드·등급), 무대 6. 격투 게임의 "선택 화면" 재료가 다 있다.
- **읽을 수 있는 자세**: 화면에 자세 이름이 뜨고, AI가 읽는 "낌새"(칼을 드는 손, 간격 안 진입)가 사람 눈에도 같은 신호다.
- **밸런스 도구**: `weapon_league`(91짝), `characters_eval rr`, `ref_duel`이 있다.

## 2. 새로 필요한 것
### 시스템
| 항목 | 내용 | 이음새 | 비용(주) |
|---|---|---|---|
| 둘째 입력(로컬) | 가로 화면 좌우 분할, 각자 손가락 하나 + 이동(기울기는 못 쓴다 → 두 사람 다 조이스틱), 탭 찌르기 | input.js 둘째 인스턴스, main.js에 `player2`(AI 대신) | 1.5 |
| 대전 틀 | 캐릭터·무기 선택(카드 뽑기 대신 고르기 또는 둘 다 뽑기), N판 승부, 결과·전적, 재대결 | main.js 상태 기계에 `versus` 갈래 | 1 |
| 사람이 고르는 동작 | 밀치기·발차기(9/30 사장님 근접 동작 요청과 같은 것), 잡기는 뒤로 | shove()를 입력에 연결(동작 PM·디렉터 설계 중) | 이미 진행 |
| 연습 모드 | 가만히 선/느린 상대, 되감기(입력 재생) | 시뮬 더미 구성 재사용 + 입력 기록 | 1 |

| 카메라 | 두 사람 시점: 옆에서 보는 고정 카메라(분할 화면)로 바꿔야 한다. 지금은 어깨 너머 | main.updateCamera 갈래 | 0.5 |
### 콘텐츠
- 추가 콘텐츠는 거의 필요 없다. 로스터 6·무기 15로 시작. 격투 방향은 콘텐츠보다 밸런스와 동작(밀치기·발차기·잡기)이 본체.
### UI
- 선택 화면, 판 수 표시(체력 바 없음 — 점 세 개), 결과·전적, 연습 모드 메뉴. 화면 문법은 카드 v2.

## 3. 대략 비용
- **로컬 대전 수직 슬라이스**(분할 화면·같은 무기·1판): 2주 안. 태블릿 가로 기준.
- **로컬 대전 한 벌**(선택·3판·전적·연습): 3~4주.
- **온라인**: 결정성 검증 2주 + 롤백 8~12주. 네트워크 허용 결정 뒤.

## 4. 핵심을 해치는 지점
1. **격투 게임 문법**: 타이머·체력 바·라운드 카운트·콤보 표시는 적막과 일촉즉발의 반대다. 우리 식은 "먼저 베인 쪽이 진다, 3판, 판 사이 침묵".
2. **조작 면적**: 한 기기 분할이면 감기 궤적이 좁아진다(화면 높이 절반 = 손 1.3 m). 온몸 타격(감기 궤적 입력)과 부딪힌다. 폰에서는 온라인만 현실적이다.
3. **밸런스의 주인**: 사람 대 사람은 시뮬로 못 잰다. 사장님 플레이와 대전 기록으로만 본다 — "난이도 테스트 없음" 규칙과 같은 자리.
4. **연출**: 결정타 슬로모·멈칫이 두 사람에게 같은 시간을 준다. 온라인이면 연출이 판정과 분리돼야 한다(훅은 이미 분리돼 있다).
5. **온몸 타격 R2·R4 뒤**: 큰 감기 = 큰 위험(R2 시험판은 몸통만 클립을 따르고 닻 비틀기만 풀린다. 헛침의 쏠림은 R4 반동에서)이 사람끼리는 읽기 게임이 된다(가장 잘 맞는 방향). 다만 두 사람 다 큰 동작을 하면 판이 한 수에 끝나 짧아진다 — 3판이 아니라 5판이 맞을 수 있다(사장님).

## 5. 참고 게임과 우리가 다를 점
| 게임 | 가져올 것 | 우리가 다른 점 |
|---|---|---|
| 부시도 블레이드 | 일격 필살, 체력 없음, 자세, 명예 규칙, 침묵 | 우리는 물리 판정과 손가락 궤적, 갑옷 |
| Hellish Quart | 물리 검술 격투, 짧은 판, 사실 무기 | 우리는 재생 동작이 없고 조작이 궤적 |
| Nidhogg | 한 수 왕복, 간격 게임 | 우리는 3D 물리 몸 |
| 사무라이 스피리츠 | 한 방의 무게, 간격·기다림 | 우리는 체력 게이지 없음 |
| For Honor | 자세 3방향 읽기, 잡기·밀치기 | 우리는 자세 14, 궤적 자유, 판정 물리 |

## 6. 사장님이 정할 것
1. 먼저 할 것: 로컬 분할 화면(태블릿)인가, 온라인인가, 둘 다인가. 네트워크 허용 결정과 묶인다.
2. 판 수(3 또는 5)와 "먼저 베인 쪽이 진다"의 정의(치명만인가, 상처면 끝인가).
3. 캐릭터·무기 선택: 고르기인가, 뽑기(둘 다 무작위)인가.
4. 사람이 고르는 동작 범위: 밀치기·발차기(진행 중) + 잡기까지인가.
5. 분할 화면에서 이동 조작(둘 다 조이스틱)을 받아들일지.
6. 대전 기록(입력 재생)을 저장·공유할지.
7. 연습 모드에 "AI 검객과 같은 시트로 싸우는 사람 대리"를 둘지(사장님이 각 캐릭터로 직접 싸워 보는 용도).
