# 디자인 언어 점검 (카드 뒷면 v3 작업 중 정리)

> **게임 컨셉 (사장님, 2026-09-28)**: "이 게임의 컨셉은 **적막하고 고독한 대결**이야."
> 그림·소리·연출 모두 이 결을 따른다. 관중·함성·요란한 효과는 넣지 않고, 효과음은 아주 가볍고 간단하게 한다.

> **결정 (사장님 직접, 2026-09-28)**: 카드 뒷면은 **v3 픽셀 아트**를 쓴다. 디렉터가 main f24151e 에 반영했다.
> - 판마다 그 스테이지 테마의 뒷면이 나온다(main.js `setCardBack`). 어두운 홀은 옛 classic 뒷면이다.
> - `?back=<테마|classic>` 으로 고정해 볼 수 있다.
> - 한 칸 `--px`: 가로 폰 3px, 큰 화면은 4px까지, 카드 폭이 130px 미만이면 2px. 카드 크기는 두 칸의 배수다.
> - 상대 칸은 filter 대신 회색 조각 `px_<테마>_<조각>_foe.png` 를 쓴다(`tools/cardbacks/grey_foe.py` 가 만든다).
>   **조각을 다시 뽑으면 이 스크립트도 다시 돌린다.**
> - 스테이지 순서는 검객의 고향 순(사장님, 2026-09-28): 하인리히(포세이돈) → 브란(화전 터, 새로) → 랴오(산사) → 이졸데(성 안뜰; 한 번 쓰러져도 다시 일어나서 랴오 뒤) → 하인리히 흑화(밤의 포세이돈, 나중에) → 마르그레테(대성당). 무대마다 그곳 검객이 상대로 나온다(`STAGE_FOE`). `docs/stages.md`.
> - 화전 터는 봄비가 내린다(사장님 제안). 1안·2안 중 **사장님이 2안을 골랐다**(`clearing` = 2안, 1안은 `?stage=clearing_a`로 보관). 새벽임이 읽히게 동쪽 새벽 놀과 숲 가장자리 안개 띠를 넣었다.
> - 카드 앞면은 원래 앞면을 유지한다(사장님: 앞면은 자세한 정보 자리, 뒷면과의 대비가 오히려 흥미롭다 → §4). 픽셀 앞면 시안 v1 은 기록으로만 둔다. v2(`p_*.svg`)도 기록으로만 둔다.

실제 화면(844×390 가로 폰, 기본 모드와 픽셀 모드)을 찍어 보고 게임 전체에 공통된 '결'을 뽑았다.
찍은 화면은 `docs/handoff/design_language/`에 있고, 카드 뒷면 비교는 `docs/handoff/card_backs_v3.png`에 있다.

## 1. 지금 게임의 결

| 요소 | 결 |
|---|---|
| 3D 화면 (기본 모드) | 로우폴리에 평면 음영을 쓴다. 꼭짓점 색에 빛을 구워 넣어 면마다 색 덩어리가 크고, 외곽선은 없다. 질감은 캔버스로 그린 거친 무늬(돌·흙·기와) 정도다. |
| 3D 화면 (픽셀 모드) | 한 게임 픽셀을 CSS `max(3, round(화면높이/180))` px(가로 폰 844×390에서 3px, 세로로 130칸)로 그린 뒤 최근접으로 키운다. 계단 모서리가 그대로 보인다. |
| 캐릭터 | 기본 도형(상자·원기둥·공)을 이어 붙였고, 옷·갑옷도 큰 면 몇 개다. 한 캐릭터에 쓰는 색은 대략 4~6가지다. |
| UI (메뉴·HUD·뽑기) | 어두운 갈색 반투명 판(#30241a → #17110c), 금빛 강조(#d9a441, 글자 #e9c47a), 둥근 모서리 판·알약 단추, 시스템 산세리프 글꼴. 선은 1px 금테가 전부이고 그림자는 부드럽다. |
| 무기 썸네일 (카드 앞면) | 렌더를 캡처한 webp 그림이다. 부드러운 음영이 들어간 3D 그림이라 픽셀 모드에서는 조금 매끈하지만, 기본 모드와는 어울린다. |

**공통 규칙** (새로 만드는 그림은 이것을 따른다)
- **밀도**: 가장 작은 선이나 점은 한 게임 픽셀(가로 폰 3 CSS px) 이상이다. 머리카락 같은 가는 선(1 CSS px 이하)이나 촘촘한 벡터 무늬는 쓰지 않는다.
- **색**: 한 요소에 바탕 + 3~4색 + 공용 금(#d9a441)·외곽 짙은 갈색(#140d09)으로 끝낸다. 그러데이션은 크게 한 번만 쓰고, 잔 그러데이션은 쓰지 않는다.
- **음영**: 면 단위 평면 음영이다. 테두리 강조는 한 칸짜리 금선이나 짙은 선으로 한다.
- **모양**: 큰 덩어리 몇 개로 읽혀야 한다. 폰에서 카드 한 장이 130~200px이니, 문양 하나는 6~10칸(18~30px) 크기로 만든다.
- **글꼴**: 글자는 시스템 산세리프 그대로 둔다. 픽셀 글꼴은 한국어 가독성이 나빠 권하지 않는다.
- **스테이지마다 고유 카드 뒷면** (오너 결정, 2026-09-28): 무기 카드 뒷면은 그 판 스테이지의 문양이다. **새 스테이지를 만들면 그 스테이지의 카드 뒷면도 함께 만든다.**
  - 조각 네 개: `public/ui/cardbacks/px_<스테이지 id>_{tile,frame,center,plaque}.png` (`tools/cardbacks/gen_pixel_cardbacks.py`에 테마를 더해 뽑는다).
  - 상대 칸용 회색 조각: `python3 tools/cardbacks/grey_foe.py`를 다시 돌려 `_foe` 조각을 만든다.
  - 바탕색: main.js `PX_BACKS`에 `<스테이지 id>: '#rrggbb'` 한 줄을 더한다(디렉터에게 부탁하거나 스테이지 병합 때 함께).
  - 스테이지의 대표 오브제·문양을 추상 반복 패턴으로 풀고, 180° 대칭, 위·아래 가운데 원판(배지 자리)을 지킨다.
  - 확인: `?stage=<id>`로 뽑기 화면을 찍어 내 카드 두 장과 회색 상대 카드가 모두 읽히는지 본다.

## 2. 따로 노는 요소

1. **카드 뒷면**(지금 게임, 금빛 마름모 칼): 가는 사선 격자(머리카락 선)에 매끈한 벡터 칼이 있다. → v3 픽셀 아트로 교체한다(사장님 결정).
2. **카드 뒷면 v2**(1a53c9e, 채택 안 됨): 0.5~1px 선으로 된 촘촘한 벡터라 같은 문제가 있다. 파일은 보관만 한다.
3. **무기 썸네일**: 픽셀 모드일 때만 혼자 매끈하다. 기본 모드에서는 문제없다.
4. **그 밖**: 멈춤 단추·조이스틱·메뉴 알약 단추는 매끈한 원·둥근 모서리다. 게임 판(갈색·금)과 색은 맞고 선이 굵어 크게 튀지 않으므로 그대로 둔다.

## 3. 카드 뒷면 v3 (픽셀 아트) — 채택

**파일**: `public/ui/cardbacks/px_<테마>_{tile,frame,center,plaque}.png`
- 테마: `poseidon` · `poseidon_night` · `clearing` · `castle` · `temple` · `cathedral`. 조각 하나가 100~250바이트다.
- 생성기는 `tools/cardbacks/gen_pixel_cardbacks.py`다. 새 테마를 넣으면 `grey_foe.py` 도 다시 돌리고, main.js `PX_BACKS` 에 바탕색을 더한다.
- `poseidon_night`(밤의 포세이돈, 하인리히 흑화): 포세이돈 안의 밤 변주. 바탕 `#0c1220` + 어두운 물빛 `#2a4d58` · 달빛 `#dfe3d8` · 불꽃 `#e0782a`. 마름모 격자와 삼지창·뇌문 띠는 포세이돈과 같고, 물거품 자리에 이지러진 달과 별, 가운데는 초승달과 불꽃. `docs/handoff/card_back_poseidon_night.png`.
- `clearing`(화전 터, 브란 — 오너가 고른 2안): 바탕 `#1a1816`(탄 땅) + 잿빛 `#5e5c55` · 새싹 연두 `#8fae3e` · 양골담초 노랑 `#c9a83a` · 바랜 나무 `#6e665a`. 문양은 비스듬한 빗줄기와 새싹, 띠는 둥글게 이어 놓은 탄 통나무의 마구리(나이테), 가운데는 위에서 본 날개 편 까마귀(잿빛 — 옆모습은 180° 돌려 붙이면 덩어리로 보여 위에서 본 모습으로). `docs/handoff/card_back_clearing.png`. 1안 뒷면(새싹·밭돌·울타리·회초리)은 `px_clearing_a_*`로 보관한다(main.js 는 안 쓴다).

**조각으로 나눈 까닭**: 카드 비율이 화면마다 다르다(가로 폰 약 1:1.16, PC 1:1.5, 세로 폰 1:2.1). 그림 한 장을 늘리면 칸이 찌그러진다. 그래서 CSS가 조각을 정수 배로 붙인다.

| 조각 | 크기(칸) | 하는 일 |
|---|---|---|
| tile | 16×32 | 이음새 없이 반복되는 바탕 문양이다. 가운데 기준으로 깔면 카드 전체가 180° 대칭이 된다(위 절반의 삼지창·종·장미가 아래 절반에서는 거꾸로). |
| frame | 20×20 | 9조각 테두리다. 폭 7칸이고 가운데 6칸이 띠 한 마디로 반복된다. 위·아래와 왼·오른 띠가 서로 180° 짝이다. |
| center | 14×14 | 가운데 작은 장식으로, 스스로 180° 대칭이다. |
| plaque | 10×10 | 번호 배지 자리(아래 가운데)와 그 대칭(위 가운데)에 까는 원판이다. |

**어느 안을 쓰나 (제안)**: 그 판의 스테이지에 맞춘다. 포세이돈 신전 판에는 `poseidon`, 성 안뜰에는 `castle`, 산사에는 `temple`, 대성당에는 `cathedral`을 쓴다.
`#draw`에 `data-back="<스테이지 id>"`를 달고 아래 CSS의 네 경로·바탕색만 바꾸면 된다. 어두운 홀(`?stage=darkhall`, 점검용)은 `castle`을 쓴다.
하나로 고정하길 원하면 사장님이 번호로 고르면 된다.

**제안 CSS** (디렉터가 index.html에 옮길 때 참고):

```css
.wback { --px: 3px;                         /* 한 칸 = 게임 픽셀 (아래 JS 로 정한다) */
  border: 0 solid transparent;              /* 배지(.wkey) 자리가 밀리지 않게 폭 0, 그림만 border-image 로 */
  border-image: url(ui/cardbacks/px_castle_frame.png) 7 / calc(7*var(--px)) / 0 repeat;
  background:
    url(ui/cardbacks/px_castle_center.png) center / calc(14*var(--px)) no-repeat,
    url(ui/cardbacks/px_castle_plaque.png) center bottom calc(3*var(--px)) / calc(10*var(--px)) no-repeat,
    url(ui/cardbacks/px_castle_plaque.png) center top calc(3*var(--px)) / calc(10*var(--px)) no-repeat,
    url(ui/cardbacks/px_castle_tile.png) center / calc(16*var(--px)) calc(32*var(--px)) repeat,
    #1e2433;                                 /* 테마 바탕색: poseidon #1d3037 · castle #1e2433 · temple #1a352b · cathedral #2b171a */
  image-rendering: pixelated; image-rendering: crisp-edges; }
```

- **--px**: 게임 픽셀과 같게 `Math.max(3, Math.round(innerHeight / 180))`로 정하기를 권한다. 아주 작은 카드(폭 130px 미만)에서는 2도 괜찮다.
- **카드 크기**: `--cw`·`--ch`를 `2*--px`의 배수로 반올림하면 가운데 정렬 때 반 칸 어긋남이 없다.
- **border-image**: `border-radius`로 잘리지 않아 테두리 모서리가 네모로 남는다. 픽셀 결에는 오히려 맞는다.
- **상대 카드**: `grayscale(1) brightness(.55)`로 확인했고, 네 안 모두 문양이 읽힌다(비교 이미지 아랫줄).

## 4. 카드 앞면 — 원래 앞면 유지 (사장님 결정)

> 사장님: "카드 앞면은 원래가 낫다. 여긴 자세한 정보가 필요한 곳이라. 뒷면과의 대비가 오히려 흥미로워 보이기도 해."
> 그래서 앞면은 픽셀 결로 맞추지 않는다. 뒷면(픽셀, 스테이지 테마)과 앞면(매끈한 그림, 등급색, 자세한 글)의 대비를 의도로 둔다.
> 아래 v1 시안은 되돌렸고(`index.html`·`main.js` 원래대로), 기록과 도구만 보관한다: `public/ui/weapons_px/`, `tools/cardface/`, `docs/handoff/card_face_v1.png`.
> 다만 `tools/cardface/face_check.mjs`(무기 14종 × 6개 화면 넘침 점검)는 원래 앞면에도 그대로 쓸 수 있다.

### (보관) 카드 앞면 픽셀 시안 v1 — 채택 안 됨

비교 이미지: `docs/handoff/card_face_v1.png`. 844×390과 568×320에서 기본·픽셀 모드로, 고르기 전과 뒤집힌 뒤의 전·후를 찍었다.

- **테두리**: CSS 네모 선으로 그린다(그림 파일 없음). `box-shadow` 안쪽으로 짙은 선 한 칸 · 등급색 한 칸 · 짙은 선 한 칸을 넣는다(`.wface` 의 `--fr`). 네 귀퉁이에는 금빛 네모 징(두 칸)을 둔다. 모두 `--px`의 정수 배라 뒷면과 칸 크기가 같다.
- **테두리 색 = 등급색** (스테이지 테마가 아님). 까닭은 셋이다.
  1. 뒷면이 이미 스테이지를 말한다.
  2. 앞면에서 가장 먼저 읽혀야 하는 것이 등급이다.
  3. 스테이지×등급을 섞으면 색이 너무 많아진다(규칙 1장: 바탕 + 3~4색).
- **바탕**: 평면 단색 `#1d140d`. 부드러운 그러데이션과 무기 뒤의 빛 번짐(`--tg` 원)은 뺐다.
- **딱지**:
  - 등급(`.wtier`)은 등급색으로 채운 네모에 짙은 글자다.
  - '내 무기'는 금빛 네모에 짙은 글자다.
  - '상대 무기'는 짙은 네모에 흰 글자와 옅은 회색 테두리이고, 붉은색은 쓰지 않는다.
  - 둥근 알약은 쓰지 않는다. '누구' 딱지는 글 흐름에서 빼 테두리 안쪽 위 가운데에 얹었다. 그래서 568×320에서도 설명 두 줄이 들어간다.
- **고른·상대 카드 강조**: 바깥 한 칸짜리 선을 두른다. 고른 카드는 금빛, 뒤집힌 상대 카드는 옅은 회색이다.
- **이름 글자**: 번지는 빛 대신 1px 딱딱한 그림자를 쓴다. 글꼴은 시스템 산세리프 그대로다.
- **무기 그림**:
  - `public/ui/weapons_px/<id>_{32,24,16}.png`로 굽는다(`tools/cardface/bake_px_thumbs.mjs`: 줄이기 → 알파 문턱 → 채널 8단 → 한 칸 외곽선).
  - 한 칸 = `--px`로 정수 배 확대한다. 그림 칸 높이가 카드·설명 길이마다 달라서(41~242px) 컨테이너 질의로 들어가는 가장 큰 그림을 고른다. `--px`가 4인 큰 화면은 `@media (min-height: 630px)`로 문턱을 올린다.
  - **전·후 판단**: 기본 모드에서도 칸이 보이는 픽셀 그림 쪽이 뒷면·테두리와 한 벌로 읽혀 이쪽을 택했다. 원래 매끈한 그림(`ui/weapons/*.webp`)은 그대로 두었다.
- **filter**: 카드에는 쓰지 않는다. 그림의 `drop-shadow`와 못 고른 카드 그림의 `grayscale`을 뺐고, 못 고른 카드는 어두운 덮개만 약간 짙게(.42) 했다.
- **점검**: `tools/cardface/face_check.mjs`로 무기 14종 × 6개 화면(568×320 · 667×375 · 844×390 · 932×430 · 1280×720 · 1920×1080)을 확인했다. 기본 모드 90장과 568·844의 픽셀 모드 30장에서 테두리 넘침·가로 잘림이 0이고, 콘솔 에러도 0이다.
