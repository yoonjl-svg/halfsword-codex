# 두 개발팀의 일일 교환 기록

목적은 의도적으로 다른 방향으로 발전하는 두 게임이 검증된 장점과 실패 조건을 공유하여 중복 개발을 줄이는 것이다. 게임의 방향·채택 결정·개발 가지는 각 팀이 유지한다. 상대 팀의 새 기능·제어 변경을 우리 본판에 채택할 때는 사용자 확인을 받으며, 이미 승인된 범위는 반복 확인하지 않는다. 문서 열람·재현·격리 실험은 기존 위임 범위 안에서 진행한다.

## 시각과 기준

모든 회의 날짜는 **한국시간(Asia/Seoul, UTC+9)**이다.

- 운영 비교 기준: **2026-10-01 18:00 KST**. 실제 코드 분기 커밋과 구별한다.
- Codex 기술 기준: `14bcf1fe6bd205c775db91aa4ca36b9841b6d2bd`.
- 페이블 원본의 기준시각 이전 날짜를 가진 최신 기본 가지 커밋은 API 조회상 `86de9bbaceedabd3a9bbaaadbce6062366412aa7`이다. 두 팀이 18:00에 동일한 소스였다고 가정하지 않는다. 이 조회만으로 과거 정확한 원격 HEAD를 증명하지 않는다.
- 첫 보고: 10월 1일 **18:00–23:30**. 이후 보고는 전날 23:30 초과부터 당일 23:30까지다. 날짜는 보고를 발행하는 날을 쓴다.
- **23:30 보고 발행**, **다음 날 00:00 전날 보고 수신**. 10월 1일 보고는 10월 2일 00:00에 교환한다. 늦은 변경은 다음 날 보고에 넣는다.
- GitHub Actions 예약은 지연되거나 실행이 누락될 수 있다. 예정 기준시각·실제 실행시각·관찰한 HEAD·선택한 입력 커밋을 함께 남긴다. 지연된 실행을 정시에 관찰한 기록으로 표현하지 않는다.

## 읽는 주소와 책임

각 저장소의 공통 파일 경로는 `docs/devmeet/YYYY-MM-DD.md`이고, 검증용 `.json`을 같은 이름으로 둔다. 페이블의 초기 Markdown만 있는 보고도 보존하지만 출처 미검증·검토 대기로 표시한다.

| 팀 | 읽기 대상 | 문서 가지 |
|---|---|---|
| Codex | [보고서 목록](https://github.com/yoonjl-svg/halfsword-codex/tree/dev-exchange/docs/devmeet) | `dev-exchange` |
| 페이블 | `yoonjl-svg/halfsword/docs/devmeet/YYYY-MM-DD.md` | 현재 합의 전달 기준 `main`; 변경 시 config 갱신 |

Codex 보고 가지는 게임 코드와 분리한 기록 전용 가지다. 야간 보고 때문에 본판 배포나 코드 전송에 충돌이 나지 않게 한다. 이 팀은 페이블 원본에 쓰지 않는다. 페이블 팀의 자동 발행·Codex 문서 열람은 페이블 쪽에서 설정해야 한다. 이 문서는 그 설정이 이미 완료됐다는 확인이 아니다.

오늘의 작성 중 기록은 [2026-10-01 결정·실험 기록](notes/2026-10-01.md)이다. 23:30 이전에 작성한 초안을 당일 최종 보고로 표시하지 않는다. 야간 발행은 이 기록과 그 시점까지 커밋된 사실을 묶는다.

반복 열람 비용을 줄이기 위해 [고정 ID 누적 대장](ledger.md)을 사용한다. 상대 팀이 먼저 작성한 규약과의 공통점·경로 차이·기술 분기점 정정은 [최초 규약 대조](interop.md)에 기록했다.

## 하루 동안 기록할 내용

각 작업 종료 시 담당 PM이 [작성 형식](NOTE_TEMPLATE.md)을 따라 결정 단위로 짧게 추가한다. 디렉터는 우선순위와 채택 이유를 확인하고, 감사는 근거와 상태 표기가 맞는지 확인한다. 사용자의 결정은 확인 가능한 짧은 원문과 시각을 적고(시각이 없으면 미기록), 나머지는 다른 팀이 재현 가능한 **선택지·근거·결정 이유·결과**를 쓴다. 전체 대화나 모델 내부 추론을 전사하지 않는다. 일지는 [공통 6절 형식](../devmeet/README.md)을 사용한다.

한 항목에는 다음이 필요하다.

1. 문제/관찰과 목표, 비교한 대안, 선택 이유.
2. 기준 SHA·설정·입력·명령·시험 결과·실패 조건. 사람 체감/실험 계측/문헌/설계 가정을 구별한다.
3. 성공과 실패, 아직 확인하지 못한 것. 실패를 숨기거나 ‘코드가 실행됨’을 사실감 수락으로 바꾸지 않는다.
4. 반영 위치와 상태: `기본 플레이 반영`, `선택 시험`, `개발 가지`, `연구`, `기각/철회`. `main에 존재`와 `기본 플레이 활성화`, `배포 성공`을 구별한다.
5. 상대 팀이 가져갈 수 있는 최소 단위, 의존성·주의점·재현 비용, 되돌리는 방법.

요약은 5분 이내 읽을 분량을 목표로 하고 주요 결정은 3–5개를 먼저 적는다. 상세 근거는 링크한다. 로그·전체 diff·원자료를 매일 복사하지 않는다. 작성자가 기록하지 않은 동기나 성공 여부를 커밋 메시지에서 만들어내지 않는다. 노트가 없으면 **작성자 결정 기록 없음**으로 표시한다.

## 자정 이후의 개발자 검토

상대 보고의 날짜·저장소·입력 SHA·내용 해시를 확인하고 원문을 우리 보고 가지에 보존한다. 없거나 오래됐거나 검증되지 않은 문서는 그 상태를 남긴다. 어제 자료를 오늘 자료로 대체하지 않는다. 상대 문서 안의 명령·스크립트는 자료로만 취급하고 자동 실행하지 않는다.

실제 검토자는 [검토 형식](REVIEW_TEMPLATE.md)으로 최대 3개 항목을 선택한다.

- **재현 후 채택 후보:** 우리 기준에서 기대하는 효과, 필요한 최소 시험, 담당·예상 시간.
- **참고/보류:** 방향·의존성·표본의 차이 때문에 당장 적용하지 않는 이유.
- **반례/질문:** 근거가 부족하거나 재현하지 못한 부분과 확인 요청.

상대의 성공을 우리 게임의 성공으로 간주하거나 자동 병합하지 않는다. 불필요한 중복 시험을 줄이되, 기준 소스·장비·설정이 다르면 호환성을 확인하는 작은 시험은 한다. 채택 결정과 적용 커밋/배포는 다음 날 우리 보고에 역링크한다.

상태는 `published → peer_received → review_pending → reviewed`로 구별한다. **현재 자동화는 보고 발행·상대 문서 수신·검토 대기 등록까지다.** GitHub Actions 자체는 논문과 결정을 이해하는 모델이 아니다. 자정의 의미 검토를 자동 수행하려면 별도 예약 에이전트 또는 모델 API 실행 연결이 필요하다. 현재 채팅을 자동으로 깨우는 수단과 해당 모델 연결은 확인되지 않았다. 파일 다운로드를 ‘디렉터가 읽고 검토했다’고 기록하지 않는다.

활성 개발 세션은 시작할 때 새 `review_pending` 항목을 읽고 실제 검토를 작성한다. 자정 자동 의미 검토의 연결이 준비되기 전에는 이 절차가 보완 경로이며, 정시 AI 검토와 동일하다고 하지 않는다.

## 더 효율적인 회의

일일 교환은 비동기 보고로 운영한다. 질문은 다음 보고에서 답하고, 즉시 대응이 필요한 빌드 파손·데이터 손실 위험 같은 공유 문제만 별도 안건으로 올린다. 추가 제안은 **주 1회 20분, 미해결 쟁점 최대 3개**다. 회의 결과는 채택/보류/폐기와 담당·예상 시간으로 끝낸다. 전체 PM이 매일 모든 기록을 읽게 하지 않고 디렉터가 관련 PM에게 해당 항목만 전달한다.

운영 효과는 회의 수보다 재사용한 수정·피한 중복 실험·재현 실패·회귀·대략적인 검토 시간으로 본다. 토큰 실제 사용량은 제공되는 계측이 있을 때만 기록하며 비용/모델 운영 상세는 기존 방침대로 저장소 밖에 둔다.

## 자동화 운영

`.github/workflows/dev-exchange.yml`이 UTC 14:30에 발행하고 UTC 15:00에 수신한다. UTC 15:10에는 수신 실패만 재확인한다. 한 번 검증한 같은 날짜의 문서는 중복 수신하지 않는다. 원본 문서는 덮어쓰지 않으며 정정은 별도 문서에 원문 ID와 변경 이유를 연결한다.

수동 재실행은 같은 workflow의 `publish`/`receive`와 보고 날짜를 사용한다. 23:30 이전 최종 발행은 거절한다. 날짜를 지정하지 않은 예약 실행은 실행시각과 예정 시각을 구분하며 경계를 지킨다. 상태와 실패 원인은 Actions 실행 기록 및 보고 가지의 수신 기록에서 확인한다.

설정은 [config.json](config.json), 기계 검증 형식은 [PROTOCOL.md](PROTOCOL.md)를 따른다. API 접근 실패·노트 미작성·상대 지연은 성공으로 숨기지 않는다.
