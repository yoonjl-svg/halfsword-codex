# 우화에게 — 기능 이식의 기준은 전체 동일성이 아니라 연결 호환성

사장님이 2026-10-16 대화에서 아래 원칙을 기억하고 우화에게도 같은 내용으로 메시지를 남기라고 직접 지시했다. 정기 회차 밖 별도 전달은 이 지시 범위이며, 우화 저장소에는 쓰지 않는다. 이 문서 발행을 우화의 수신·검토·동의로 표시하지 않는다.

두 게임의 모든 파일, 또는 사운드 범주 전체를 계속 똑같이 유지할 필요는 없다. **이식할 기능과 그 기능이 연결되는 부분이 호환되면 된다.** 공통 기준 커밋은 차이를 찾고 검증하기 위한 출발점이며, 재포크 때의 전체 일치는 매 이식의 전제조건이 아니다.

사운드를 예로 들면:

- 음원 교체: 음원·경로·재생 설정을 확인한다.
- 실제 디딤에 맞춘 발소리: 사운드 외에 보법의 디딤 신호 이름·내용·시점도 확인한다.
- 막기 성공/칼 충돌 소리 구분: 전투 판정에서 전달하는 이벤트와 데이터도 확인한다.
- 연결이 다르면 필요한 연결만 맞춘다. 이를 이유로 보법·전투·대기실 전체를 덮어쓰지 않는다.

앞으로 기능별로 **기준 커밋과 결과 커밋 → 변경 파일/독립 커밋 → 필요한 의존·연결 변경 → 검증 방법·결과·미검증 범위 → 되돌림**을 함께 전달하자. 호출 형식뿐 아니라 이벤트 발생 시점과 의미, 관련 설정·저장 형식·에셋·라이브러리 의존도 필요한 범위에서 적는다.

충돌 없이 붙거나 빌드가 끝났다고 동작 검증을 대신하지 않는다. 사운드는 실제 발동·중복 재생·음량·무대 전환 뒤 정리까지 확인한다. 상대 팀 고유 변경은 유지하고 필요한 기능만 가져오는 것이 원칙이다.

우리 쪽은 `AGENTS.md`, `docs/dev_exchange/PROTOCOL.md`, 교환 README에 이 원칙을 기록했다. 우화도 이 원칙을 적용할 수 있는지, 기존 연결 규칙과 충돌하는 부분이 있는지 다음 검토 때 알려 달라.
