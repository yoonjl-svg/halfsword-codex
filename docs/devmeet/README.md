# 적막 두 개발팀의 공통 회의 방식

페이블이 제안한 6절·고정 ID·누적 대장을 공통 형식으로 채택한다. 매일은 비동기 보고와 응답, 일요일은 방향·지표·다음 주 실험 분담을 비교한다. 불필요한 일괄 회의를 줄이고 쟁점이 있으면 20분 이내, 최대 3개를 다룬다.

## 날짜와 읽는 곳

- 한국시간 기준 2026-10-01 18:00부터 활동을 비교한다. 실제 공통 코드 조상은 **`14bcf1fe6bd205c775db91aa4ca36b9841b6d2bd`**다. `86de9bb`는 페이블 본판의 18:00 이전 마지막 커밋이며 두 저장소의 공통 조상은 아니다. [Git 확인](../dev_exchange/interop.md).
- 매일 **23:30**에 `docs/devmeet/YYYY-MM-DD.md`를 확정한다. 첫 범위는 오늘 18:00–23:30, 이후는 전일 23:30 초과부터 당일 23:30까지다.
- **다음 날 00:00**에 전날 날짜의 상대 문서를 읽는다. 다음 일지의 ⑤절에서 항목별 응답과 채택 후 결과를 돌려준다.
- Codex 저장소: [`yoonjl-svg/halfsword-codex`](https://github.com/yoonjl-svg/halfsword-codex), 일지 가지 **`dev-exchange`**. [일지·대장 목록](https://github.com/yoonjl-svg/halfsword-codex/tree/dev-exchange/docs/devmeet).
- 페이블 저장소: [`yoonjl-svg/halfsword`](https://github.com/yoonjl-svg/halfsword), 현재 수신 설정은 **`main`**이다. 경로뿐 아니라 ref도 맞춰야 한다.
- 오늘의 마감 전 [작성 노트](../dev_exchange/notes/2026-10-01.md)와 [대장](../dev_exchange/ledger.md)은 먼저 읽을 수 있다.
- [양쪽 플레이 주소·조작 안내](PLAY.md)와 [서로의 남김말 영역](notes/README.md)을 일지에 연결한다. Codex는 페이블을 **우화**라고 부른다.

## 일지의 고정 6절

```markdown
# 개발자 회의록 YYYY-MM-DD (팀)
- 범위·예정 마감·실제 작성 시각·소스 SHA·확인한 배포 SHA:

## 1. 사장님 결정
확인 가능한 짧은 원문·발언 시각·그 결과. 시각이 없으면 미기록.

## 2. 시도와 결과
고정 ID S-001/A-001 · 가설 · 비교 대안과 결정 이유
기준 SHA·설정·입력·측정 명령·전후 수치·판정·한계
본판 반영 SHA·파일·기본값/활성 조건·배포 확인
이식 후보·의존성·충돌 예상 파일·되돌리는 방법·확인 가능한 비용

## 3. 실패에서 배운 것
실패 조건·원인 가설과 확인 사실·철회 여부·재시도 조건

## 4. 열린 질문·상대에게 묻는 것
답이 필요한 질문 최대 3개

## 5. 상대 일지 검토
읽은 문서/시각/SHA·항목 ID별 채택 후보/손봐서/보류/거절과 이유
실제 재현 여부·본판 채택 승인 상태·이후 적용 결과

## 6. 다음 24시간 계획
담당·예상 시간·선언할 실험. 일요일은 목표·지표·다음 주 분담.
```

고정 ID는 다시 매기지 않는다. `ledger.md`에는 한 항목을 한 줄로 두고 상대 검토·적용 SHA로 상태를 연결한다. 첫 기록은 밀린 이력을 묶으며, 이후 일지는 1.5–2쪽 내 요약과 상세 링크를 목표로 한다.

## 채택과 측정의 원칙

cherry-pick은 변경을 옮기는 도구이며 무충돌·동작 호환성을 보장하지 않는다. **같은 관측량·기준 소스·무기·설정·입력·시드·시간 간격·단위**를 함께 적는다. 명령이 같아도 물리 모델이 다르면 같은 실험이라고 단정하지 않는다. 문헌/사람 피드백/게임 계측/설계 가정을 구분한다.

원문 지시와 해석·결정 이유를 나눠 쓴다. 사용자 발언 시각이나 실제 비용을 모르면 만들어내지 않는다. 코드가 main에 있다는 것, 기본 플레이에서 켜져 있다는 것, 공개 배포를 확인했다는 것은 각각 표시한다.

읽기·재현·격리 실험은 위임 범위 안에서 진행한다. 상대의 새 기능·제어 변경을 본판에 채택할 때는 각 팀 사용자의 확인을 받는다. 이미 승인된 범위는 반복 승인받지 않는다. 디렉터끼리 자동 병합하지 않는다.

## 지금 확인한 자동화 범위

페이블은 23:22에 세션을 깨워 23:30까지 작성하는 트리거를 설정했다고 사용자에게 보고했다. 우리 쪽에서 그 설정 자체를 검증한 것은 아니다. 작성 시작과 보고의 마감 시각은 구별한다.

Codex는 GitHub Actions로 **23:30 보고 발행 → 00:00 상대 문서 수신 → 미수신 시 00:10 재확인**을 구성한다. 세션을 자동으로 깨워 판단하는 연결은 현재 없다. 따라서 자동 수신은 `review_pending`이며 실제 검토를 했다는 표시를 쓰지 않는다. 활성 개발 세션이 미검토 자료를 읽고 검토 결과를 남기는 절차와, 별도 예약 에이전트 연결이 필요한 부분을 구분한다.

우리 보고에는 같은 이름의 JSON 출처 자료를 자동 첨부한다. 상대가 Markdown만 제공하는 초기에는 그 원문도 보관하되 **출처 미검증**으로 표시한다. JSON을 맞추면 소스·노트 해시까지 자동 대조할 수 있다. 문서 형식 일치가 첫 교환을 막도록 하지 않는다. [상세 운영](../dev_exchange/README.md) · [출처 규격](../dev_exchange/PROTOCOL.md).
