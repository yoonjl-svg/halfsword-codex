# 우화에게 — 오른쪽 색 경계 수정 확인 및 새 기력 지시

사용자가 직접 “어떤 것을 어떻게 고쳤는지를 포함하여, 그 내용을 인지하고 있는지 우화에게 메시지 남겨”라고 요청하여 발행하는 메시지다. 다음 일지에서 아래 수정의 원인 가설·적용 내용·검증 한계를 인지하고 있는지 확인 부탁한다.

## 오른쪽 일부만 색이 갱신되지 않던 현상

- 사용자 제보: iPhone Safari 가로 화면에서 오른쪽 세로 영역에 출혈·감정 색이 다르게 남았다.
- 우리 수정: `2f593ba6`, `src/screen_tint.js` 추가와 `src/main.js`, `index.html` 연결 변경. 별도 전체 화면 CSS 색막 `#vignette`·`#emotion`을 제거하고, 게임 장면과 **같은 WebGL 캔버스/drawing buffer**에 전체 화면 사각형으로 합성한다. 장면을 그린 뒤 색을 덧그린다.
- 없앤 경로: 별도 CSS 합성 층/타일 일부만 이전 크기나 색을 유지하는 경로. 출혈·공포·분노·집착의 색, 세기, 그라디언트 범위와 세기 보간은 보존했다. 효과가 없으면 추가 그리기를 생략한다. 단순한 오른쪽 가리개를 붙인 수정이 아니다.
- 검증: 로컬 Chromium에서 출혈+감정3종×화면4크기12조합, 좌우 끝 픽셀 동일·오른쪽 인접 픽셀 차 1/255 이하. 실제 게임 화면 크기/가로세로 전환도 확인했다. **원래 Safari 고장을 Chromium에서 재현하지 못했으므로, Safari 원인 확정·실기기 재발 없음·실기기 성능 검증을 주장하지 않는다.**
- 기록·실제 화면: https://github.com/yoonjl-svg/halfsword-codex/blob/72ac73b75ee252f762e1444ee4764017b7b29004/docs/codex_team/STAMINA_FIX_20261015.md
- 확인한 우화 본판 `adc87f41`에도 `createScreenTint` 연결이 있고, `screen_tint.js` 내용이 우리 수정본과 같다. 재이식 요청이 아니라 **수정 취지와 한계의 인지 확인**이다. 이후 CSS 색막을 다시 병행하지 않도록 이 경위를 남긴다.

## 사용자 새 기력 지시 — 연구 중, 완료 아님

- 단계 문턱은 유지: 0 미만 지침, −40 미만 심한 지침, −80 도달 탈진(기존 2.5초). 회복 시 단계 되돌림 조건도 유지한다.
- 이동: 지침 ×0.7, 심한 지침 **×0.4**(−30%/−60%).
- 공격: **×0.8/×0.6 목표**(−20%/−40%). 기준은 준비·회수를 제외한 실제 타격 접촉 시각, 시간비 목표 **1.25/1.6667**. 최고 칼끝 속도 시각으로 대신하지 않는다.
- 사용자가 이번에 “딱 맞진 않더라도 지금보단 훨씬 근사치”, 유파·무게·길이별 범주화도 허용했다. 이전 전 무기 ±7% 일치 요구를 새 승인 기준으로 고집하지 않고, 같은 기준 공격에 대해 오차·빗나감·접촉 부위·에너지·예외를 비교해 보고한다.
- 입력 시간·물리 추종 시간·중력 지지를 분리하는 실험 중이다. 유파 동작/보법의 내용, 기력 비용/회복은 재설계하지 않는다. 선정 계수·재현 도구·전후 표는 연구 결과를 확정한 뒤 별도 메시지와 개발 일지로 전달하겠다.

공격의 운동 에너지는 같은 질량에서 속도의 제곱에 비례하지만, 실제 상처에는 접촉 위치·각도·방어구·기존 비기 판정도 관여한다. 새 목표 0.8/0.6을 맞혔다고 피해를 일괄 64%/36%로 설정하지 않는다.
