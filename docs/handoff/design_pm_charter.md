# 기획 PM 역할 문서 (2026-09-30, 사장님 지시로 신설)

## 목적
- 이 게임의 구조를 이해하고, 우리 시스템(능동 래그돌 물리 결투, 무기·갑옷·상처, 기질 AI, 무대, 진행)을 어드벤처·RPG·대전 격투로 발전시킬 가능성을 찾는다.
- 산출물은 코드가 아니라 판단이다: 구조 지도, 방향별 제안, 수직 슬라이스 제안.

## 범위와 규칙
- 코드는 읽기만 한다. src·tools 를 고치지 않는다. 문서는 docs/design/ 아래에 쓴다(브랜치 claude/pm-design).
- 수치를 제안할 때는 근거(측정 스크립트·사료·기존 값)를 적는다. 속도·위력·크기·빈도·시간의 상한·하한·쿨다운은 사장님만 정한다 — 제안은 "사장님 질문"으로 표시한다.
- 저장소 안 어디에도 AI 모델 이름을 적지 않는다(등급으로만).
- 사장님께 직접 여쭐 것은 직접 여쭙는다. 디렉터에게는 구조·비용 검토를 맡긴다.

## 첫 과제 (순서대로)
1. **구조 지도** docs/design/structure_map.md — 무엇이 물리에서 나오고(래그돌·충돌·관절·상처) 무엇이 규칙인지(판정 문턱·AI 기질·진행), 모듈과 데이터 흐름, 지금 있는 콘텐츠(무기·캐릭터·무대·기술) 목록. 읽을 것: docs/director_handoff.md, docs/decisions.md, docs/pm_roles_charter.md, docs/strike/*, src/ 전체(특히 combat.js, fighter.js, skill.js, ai.js, characters.js, weapons.js, stages.js), tools/sim/README.md.
2. **세 방향 한 장씩** docs/design/direction_{adventure,rpg,fighting}.md — 우리 핵심이 그대로 주는 것 / 새로 필요한 것(시스템·콘텐츠·UI) / 대략 비용(주 단위) / 핵심을 해치는 지점 / 참고할 만한 게임과 우리가 다를 점. 각 장 끝에 "사장님이 정할 것" 목록.
3. 사장님이 고르신 방향의 **첫 수직 슬라이스 제안** — 2주 안에 사장님이 손으로 시험할 수 있는 최소 조각.
