## 1. 물건 — 자리 · 가짐 · 장착 · 싸움으로

- **정의**: `src/lobby_equipment.js` `HERO_TEAR` — id `hero_tear` · 이름 '용사의 눈물' · 등급 `legend` · 설명 '물방울 모양의 작은 다이아 목걸이. 옷 안에 걸어 겉으로는 보이지 않는다.' · 능력 '(불굴: 기력 무한)' · `infiniteStamina: true` · 그림 `ui/armor/hero_tear.webp`. 방어구 칸 차례는 `LOBBY_ARMORS = [케틀 햇, 용사의 눈물]`.
- **가짐**: 방어구 칸에 늘 있다. 케틀 햇처럼 시작부터 가진 물건 꼴이다 — 산 것 · 얻은 것(`acquisitions`)이 아니라서 레벨은 그대로(Lv.1 은 Lv.1).
- **자리**: `armorSlot(id)` — 케틀 햇 `head` · 용사의 눈물 `neck`. 자리마다 하나씩이고 서로 벗기지 않는다.
  - 까닭: 방어구 칸이 '한 번에 하나'였다면 목걸이를 걸 때 케틀 햇이 벗겨져 투구가 사라진다 — '외형 변화는 없음'에 어긋난다.
- **저장**: 목 자리는 새 열쇠 `stillness.lobby.neck.v1` = `{"version":1,"neck":"hero_tear"|null}`. 머리 자리 `stillness.lobby.armor.v1` 은 전 꼴 그대로라 옛 저장도 그대로 읽힌다. 저장이 막히면 이번 실행 동안 유지된다(케틀 햇과 같은 규칙). 처음 값은 `null`(안 걸침).
- **대기실** (`src/lobby.js`):
  - 방어구 칸이 `LOBBY_ARMORS` 를 읽어 두 칸을 그린다(그림 · 레전드 빛 · 설명 카드 · 장착 / 해제).
  - 장착 상태는 자리별(`equipped.head` · `equipped.neck`)이다. 그래서 '장착 중' 알약 둘이 같이 뜰 수 있다.
  - 알림 글: '용사의 눈물 장착' · '용사의 눈물 장착 해제'(무기 · 케틀 햇도 '… 장착 해제' 꼴로 이름이 붙음).
  - 목 자리는 미리보기(`lobby_character.js`)를 부르지 않는다. 걸기 전 · 뒤 미리보기 화소가 한 점도 안 바뀌고 다시 그리지도 않는다(§6 브라우저 2).
- **싸움으로** (`src/main.js`):
  - `journeyLoadout()` 에 `neck: readLobbyNeck()` 를 더했다. 첫 화면·대기실에서 연 여정만 읽는다 — 케틀 햇 · 무기와 같은 규칙이라 주소 고정 판 · 테스트 경로 · 옛 메뉴 판은 읽지 않는다.
  - `newRound` 에서 플레이어를 세운 직후, 케틀 햇 `setMaxBonus` 바로 뒤에 `if (loadout?.neck === HERO_TEAR.id) player.stamina.setInfinite(true)` (602 줄). 상대 Fighter 에는 부르는 곳이 없다.
  - 둘 다 걸면 최대 130 · 늘 130. 판 시작 장착으로 정한다(케틀 햇과 같음 — 사장님 결정 10/16 08:1x '아이템은 사라져도 효과는 그대로 둬.' 와 같은 꼴).

## 2. 기력 무한 — 어떻게 (`src/stamina.js`)

- 몸마다 `infinite`(기본 `false`, 13 줄).
- `setInfinite(true)`(53 줄) → `refill()`(58 줄): 값 = 최대(케틀 햇 덧 포함) · 단계 0 · 탈진 시간 0 · 숨 고르기 자세 0.
- **청구 거절** — `spend()` 맨 앞(150 줄) `this.infinite` 이면 `false`. 모든 청구가 이 한 곳을 지난다:
  - 걷기 `move` · 베기 / 찌르기 / 권총 `attack` · 막아 받기 `block` · 비기 `secret` · 박차기 `push` · 클린치 `clinch`.
  - 그래서 값 · 회복 쉼 시계(`rest`) · 단계가 안 바뀐다.
- **스텝마다 가득** — `step()` 의 기력 끔 분기 바로 뒤(275 줄) `if (this.infinite) this.refill()`. 시험 도구나 콘솔이 값을 바꿔 놓아도 다음 스텝에 가득으로 돌아온다. 그 뒤 길(클린치 짝 셈 · 긋기 확정 · 걸음 셈)은 그대로 돌고, 청구만 `spend` 가 받지 않는다.
- 그래서 기력을 읽는 곳은 모두 '생생' 값을 본다:

  | 읽는 곳 | 기력 무한일 때 |
  |---|---|
  | `stamina.speed` — 이동(`fighter.js` 2175) · 팔꿈치 · 어깨 · 손목 빠르기(2596 · 2820 · 3191) · 기술 걸음(`skill.js`) · 비기 시계(`secret_instant.js`) | 늘 1 |
  | `stamina.power` — 팔 · 손목 힘(`fighter.js` 2568 · 2975) | 늘 1 |
  | `stamina.exhausted` — 발 묶음(`feetHeld`) · 입력 막기(`main.js`) · 막기 단추(`parry_button.js`) · 기술 시작(`skill.js`) · 자세 칸 '탈진' | 늘 거짓 |
  | `stamina.level` — 지친 칼끝 처짐(`fighter.js` 3036) · 숨소리(`sound.js`) | 늘 0 |
  | `stamina.pose` — 숨 고르기 자세(`fighter.js` 2539 · 2958 · 3035) | 늘 0 |
  | 상대 AI 가 읽는 내 기력(`ai.js` 669 — 지친 상대 노림) | 늘 생생 → 지친 틈 노림을 안 받는다 |
  | 클린치(`canClinch` · `stepClinch`) | 무한 쪽은 0 · 상대는 전처럼 초당 10 · 상대가 탈진하면 밀기 끝(전 규칙) |

- **남는 것**: 공격 번호(`attackId` · `attackUntil`)는 전처럼 오른다. 상대의 막아 받기 청구가 이 번호를 읽으므로 **상대 장부는 전과 같다**. 공격 횟수 셈(`counts.cut` · `counts.thrust`)도 남는다(깎인 양 `spent` 은 0).
- 기력 끔(`?stamina=0`)이면 원래대로 100 · 막대 없음 — 아무 일 없다.
- **'+1000' 대안을 안 쓴 까닭**: 청구가 모두 `spend` 한 곳을 지나서 표시 하나로 끝난다. +1000 이면 막대(1100 의 몫) · 회복 · 문턱의 비율이 다 달라지고, 오래 싸우면 결국 바닥난다.

## 3. 기력 막대 (`src/stamina_hud.js` 28 줄)

- 기력 무한인 몸은 막대를 그리지 않는다(`f.stamina.infinite` 이면 숨긴 채로 넘어감). 이 표시는 플레이어만 받으므로 곧 **내 막대가 없다**. 상대 막대는 그대로 보인다.
- 사장님 말 '어차피 기력 무한이기 때문에'를 따라 무한인 내 막대만 뺐다. 상대 막대까지 숨길지는 §8 질문 1.
- 판을 세울 때(첫 그리기 전) 표시가 붙으므로 한 번도 깜빡이지 않는다(§6 브라우저 3: 49 번 읽어 0 번 보임).

## 5. AI · 시뮬이 그대로인 까닭

- 표시 `infinite` 의 기본값은 `false` 다. 켜는 곳은 `main.js` `newRound` 의 플레이어 한 줄뿐이다(여정에서 대기실 목 자리가 용사의 눈물일 때). AI(`ai.js`) · 상대 Fighter · 시뮬 하네스(`tools/sim/harness_m.mjs`)는 `setInfinite` 를 부르지 않는다.
- `false` 일 때 바뀐 길은 셋뿐이고 모두 결과가 같다:
  - `spend` 조건의 `|| this.infinite` — 거짓이라 같은 결과.
  - `step` 의 `if (this.infinite) this.refill()` — 들어가지 않음.
  - 막대의 `if (f.stamina.infinite) return` — 들어가지 않음.
- 난수(`Math.random`)를 부르지 않고 계산 차례도 그대로라 같은 입력 → 같은 출력이다. 설정값(`src/config.js`)은 하나도 안 바꿨다.
- 기존 `tools/sim` 파일은 한 글자도 안 바꿨다. 새 시험 파일 하나(`tools/sim/hero_tear.test.mjs` — `node --test` 시험, 시뮬 출력 아님)만 더했다.
