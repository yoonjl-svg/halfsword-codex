# PM 역할 분담안 (협력·보완·견제)

> 상태: 시행 중 (2026-09-29). 새 디렉터가 검토해 고친 형태로 시행하며, 고친 내용은 `docs/decisions.md` "디렉터가 기본값으로 시행 중"이 우선한다(사장님이 바꾸시면 되돌림). 근거: 각 PM 브랜치·문서·세션 기록을 읽고 두 관점(협력·처리량 / 견제·붉은 팀)으로 따로 설계한 뒤 반박 검토로 합쳤다.

인체 동작 연구 PM 역할 정리 (최종안)

원칙
- 만드는 사람과 판정하는 사람을 나눕니다. 디렉터가 만들고, 동작 PM·무기 PM·캐릭터 PM이 각자 따로 판정합니다.
- 재는 방법은 하나를 같이 쓰고, 판정만 따로 합니다. 같은 숫자를 두 벌로 만들지 않습니다.
- 판정은 거부권이 아니라 의견입니다. 최종 판정은 사장님 플레이입니다.
- 한도와 제약은 사장님만 넣습니다. 사람 자료는 참고일 뿐, 천장이 아닙니다.

1. 동작 연구 PM의 역할
한 줄: 사람 참고 동작을 혼자 만들고, 게임 동작이 사람다운지 판정합니다. 게임 코드(src/)는 쓰지 않습니다. 그래야 제3자로 판정할 수 있습니다.

맡는 것 (이 사람만 씁니다)
- 참고 클립(docs/motion/clips/)
  - 게임이 이 파일을 그대로 읽습니다. 복사본은 두지 않습니다.
  - '디렉터가 v0 클립을 직접 만든다'는 조항은 지웁니다. 늦어지면 동작 PM이 거친 v0부터 냅니다.
- 클립 형식 문서. 버전 번호를 붙입니다.
- 동작 모양 목표
  - 재설계 §2-6 가운데 모양 줄을 맡습니다: 감기 때 손 높이·앞뒤, 어깨 들림, 지나가기, 가슴·골반 회전, 손 이동 길이, 사슬 순서.
  - 이 줄들을 사람 자료로 다시 세웁니다.
  - 빠르기·세기·몸통 몫·지연은 디렉터 몫으로 둡니다.
- 사람 동작 사양표: 평균±편차로 적고, [문헌]/[실측]/[추정]을 표시하고, '참고, 한도 아님'을 붙입니다.
- 출처·사용권 대장 하나
  - 연구 ASS와 무기 PM의 문서는 링크만 겁니다.
  - 막힌 사이트 목록도 여기에 둡니다.
- 동작 이름 목록: 베기·기술 이름과 클립 번호. 무기 PM의 새 기술과 유파 기술도 이 이름에 연결합니다.
- 오프라인 도구(tools/motion/)
  - 키프레임 저작. 재설계의 author.html을 여기로 흡수합니다.
  - 클립 검사기, 채점기, 비교 화면.
- 참고 대비 채점의 정의 하나
  - 손 오차, 위상 오차, 최고점 순서, 칼 방향, 동작 범위.
  - 라운드 중에는 고정합니다.
- 라운드 소견서(사람다움)와 한도 점검(새로 생긴 제한만).
- 몸 신호 사양: 감기·지나가기·반동이 몸에 어떻게 보이는지 적습니다. AI와 플레이어가 읽을 신호입니다.

돕는 것 (사람 쪽 사양만 내고, 적용은 주인이 합니다)
- 런지와 지나는 걸음, 흐름·이어 베기(최소 간격은 넣지 않음), 손목 늦게 풀기: 코드는 디렉터, 무기별 값은 무기 PM.
- 한손 무기와 츠바이핸더의 몸통 몫: 무기 PM의 값에 근거를 댑니다.
- 캐릭터별 감기 모습의 범위: 캐릭터 PM에게 줍니다.
- 큰 벌 극단 자세: 외형 PM의 갑옷 뚫림 점검에 씁니다.
- 딛는 시각: 사운드 PM의 디딤 소리에 씁니다.

받아 쓰는 것 (읽기만 합니다)
- 뼈대 치수(config.js).
- 게임 안의 보간·IK. 디렉터가 src/strike에 만들고, origin에 올라오는 대로 씁니다.
- 무기 분류 틀과, 실제로 켜진 S=0 자세표(무기 PM).
- 디렉터의 게임 기록. 형식은 동작 PM이 정합니다.
- 연구 ASS의 조사, 재설계 문서.

하지 않는 것
- src/를 편집하지 않습니다. 게임 손잡이 값도 정하지 않습니다. 고칠 방향은 제안해도 되지만, config 숫자를 처방하지는 않습니다.
- 사람 값을 한도·최소 간격·상한으로 제안하지 않습니다. 게임이 사람 범위를 넘으면 '관찰'로만 적고, 줄일지는 사장님이 정하십니다.
- 무기 밸런스와 캐릭터 성격 수치는 다루지 않습니다.
- 다른 세션의 문서를 고치지 않습니다. 이미 된 출처 조사나 사용권 확인을 다시 하지 않습니다.
- 연구 ASS에게 새 조사를 시키지 않습니다. 짧은 질문은 직접 해도 됩니다.
- 사장님 대신 합격을 선언하거나 사장님 질문에 답하지 않습니다.

2. 일부러 겹치게 할 일
① 같은 기록을 두 사람이 판정 (디렉터 ↔ 동작 PM)
- 이유: 만든 사람이 자기 채점으로 '됐다'고 하지 않게 하려는 것입니다.
- 방식
  - 같은 게임 기록을 디렉터는 기술 관문(지연·CPU·튐·판정·S=0·빠르기·세기)으로 보고, 동작 PM은 사람다움으로 봅니다.
  - 채점 코드는 하나입니다.
  - 숫자가 어긋나면 평균 내지 않고 원인을 찾습니다. 그래도 사장님 시험판은 막지 않습니다.

② 거꾸로 점검 (디렉터 → 동작 PM의 클립)
- 이유: 게임 몸으로 불가능한 참고를 내면 구현이 영원히 불합격이 됩니다.
- 방식
  - 디렉터가 클립을 게임 뼈대로 따라갈 수 있는지 봅니다.
  - 못 따라가면 몰래 줄이거나 늦추지 않고, '이 클립은 이 이유로 못 따라감'이라고 적어 올립니다.

③ 붉은 팀 (무기 PM ↔ 동작 PM)
- 이유: 사람다운 자세가 무기 승률을 깰 수 있습니다(세이버 35 → 10% 사례). 반대로 무기 자세표가 몸을 어색하게 만들 수도 있습니다.
- 방식: 라운드마다 무기 PM은 motion_league로, 동작 PM은 비교 화면으로 봅니다. 서로 부딪히면 두 의견을 한 장에 나란히 사장님께 올립니다.

④ 성격 유지 (캐릭터 PM ↔ 동작 PM ↔ 디렉터)
- 동작 PM이 감기 모습의 범위를 냅니다.
- 캐릭터 PM이 기질을 그 범위 안의 값으로 옮기고, 라운드마다 pair_sweep로 다섯 캐릭터가 자기답게 싸우는지 잽니다.
- 디렉터가 AI 장치를 만듭니다.

⑤ 출처 두 번째 독자 (연구 ASS → 동작 PM)
- 원문 사이트가 막혀 있어 지금 근거가 모두 [2차]입니다.
- 묶음마다 인용 몇 개만 표본으로 점검합니다. 다시 조사하는 것은 아닙니다.

⑥ 자세 이음새 (무기 PM ↔ 동작 PM)
- 클립 작은 벌의 시작 자세는 실제로 켜진 S=0 자세표와 ±2 cm 안이어야 합니다.
- 이 한 점만 두 사람이 같이 확인합니다.

⑦ 갑옷과 소리
- 큰 동작이 갑옷을 뚫는지는 외형 PM이 봅니다.
- 센 타격과 딛기가 소리에 맞는지는 사운드 PM이 봅니다.

⑧ 클립 형식 계약 (동작 PM이 쓰고, 디렉터가 읽음)
- 버전을 올릴 때만 두 사람이 확인합니다.
- 버전이 맞지 않으면 게임이 조용히 넘기지 않고 크게 실패합니다.

3. 겹치면 안 되는 일 (주인은 한 명)
- 참고 클립 만들기 → 동작 PM
- 저작·클립 검사·채점기·비교 화면 → 동작 PM
- 게임 안에서 도는 보간·IK·꼭두각시 모드 → 디렉터. 한 벌만 두고 동작 PM 도구가 가져다 씁니다.
- 참고 대비 점수 정의 → 동작 PM
- 빠르기·세기·몸통 몫·지연·CPU 숫자 → 디렉터. 동작 PM은 인용만 합니다.
- 동작 모양 목표 → 동작 PM
- 빠르기·세기 목표와 기술 관문 → 디렉터
- 출처·사용권 대장 → 동작 PM
- 기술 이름·클립 번호 → 동작 PM
  - 어느 무기가 어느 기술을 쓰나 → 무기 PM
  - 어느 유파·캐릭터가 즐겨 쓰나 → 캐릭터 PM
- 무기 분류 → 무기 PM의 틀(A~E × ①~⑤). 재설계의 자체 분류는 이것으로 바꿉니다.
- 정지 자세(S=0) → 무기 PM / 움직이는 감기·베기 길(S>0) → 동작 PM / guards.js 코드 → 디렉터
- 런지·흐름·손목 코드 → 디렉터
  - 무기 PM의 흐름·런지·새 기술은 동작을 살린 채 온몸 타격 쪽으로 옮깁니다. 코드 길은 하나로 합칩니다.
- 판정 코드(combat.js, applyWound) → 디렉터. 둔기·파손 값은 무기 PM이 R0 뒤에 다시 재어 값으로 냅니다.
- ai.js의 온몸 부분 → 디렉터 / 성격 값과 ai.js의 감정·부활 부분 → 캐릭터 PM
- sound.js → 사운드 PM
- 화면 신호의 모양·색 → 외형 PM. 신호의 뜻은 디렉터가 정합니다.
- 연구 ASS 작업 목록 → 무기 PM 하나
- '동작 라이브러리'라는 이름 → 온몸 타격 atlas만 씁니다. 무기 PM 쪽은 '무기 층'이라고 부릅니다.
- 각 PM의 상태 파일 → 그 PM. 디렉터는 병합할 때 고치지 않습니다.
- 사장님 질문의 답(Q13·Q14·Q26 포함) → 사장님. 디렉터는 대신 답하지 않습니다.
- 한도·제약 추가 → 사장님
- 같은 코드 파일을 둘이 고쳐야 할 때: 파일을 통째로 묶어 두지 않습니다. 요청으로 넣고 디렉터가 병합합니다.

4. 견제
누가 누구를 보나
- 디렉터의 구현
  - 동작 PM: 사람다움, 한도 점검.
  - 무기 PM: 무기 밸런스.
  - 캐릭터 PM: 성격.
  - 외형 PM: 갑옷 뚫림.
  - 사운드 PM: 소리.
  - 디렉터 자신은 기술 관문만 판정합니다.
- 동작 PM의 클립
  - 디렉터: 따라갈 수 있는지.
  - 무기 PM: 패드 자리가 곧 베기 길의 경유점이라는 규칙.
  - 연구 ASS: 인용 표본.
  - 사장님: 비교 화면.
- 무기 PM의 값
  - 디렉터: 게임 동작이 몰래 바뀌지 않았는지.
  - 동작 PM: 자세가 사람다운지.

두 사람의 서명이 꼭 필요한 것 (셋뿐)
- 클립 형식 버전 변경: 동작 PM + 디렉터.
- 작은 벌 시작 자세나 S=0 자세 변경: 무기 PM + 동작 PM.
- 새 한도·제약: 제안자 + 사장님. PM끼리 합의해도 넣을 수 없습니다.
- 그 밖의 판정은 모두 의견입니다.
- 온몸 타격을 main 기본값으로 켜는 일은 사장님이 정하십니다. 소견서를 붙여서 드립니다.

규칙
- 한도 신고
  - 디렉터는 병합 메모에 새로 넣은 제한(빠르기·세기·크기·빈도·시간)을 적습니다.
  - 동작 PM은 라운드마다 바뀐 코드에서 새로 생긴 제한만 대조합니다.
  - 사장님 승인이 없는 제한은 병합하지 않습니다.
  - 범위로 적은 목표의 끝값도 한도로 쓰지 않습니다(사슬 간격 30~60 ms, X-factor 40~55°).
- 관문 옮기기 금지
  - 목표와 채점 정의는 구현 커밋과 따로 바꿉니다.
  - 라운드 중에는 바꾸지 않습니다.
  - 바뀌면 사장님 보고에 한 줄로 적습니다.
- 재현되는 증거만 받습니다
  - 커밋·시드·명령을 적습니다.
  - origin에 있는 도구로 잰 숫자만 증거로 씁니다. scratchpad에만 있는 도구로 잰 숫자는 증거가 아닙니다.
- 측정마다 빌드 커밋을 적고, R0·R3 뒤에는 다시 잽니다.
- 디렉터가 급히 PM 영역을 만들었다면: 같은 날 그 PM에게 알리고 소유권을 돌려줍니다. '손대지 마라'는 없습니다. PM은 뒤에 검토합니다.
- 붉은 깃발 직통
  - 동작·무기·캐릭터 PM이 씁니다.
  - 세 경우에만 씁니다: 신고되지 않은 제한, 지운 원칙이 되살아남, 재현되지 않는 증거.
  - 한국어 3줄로 사장님께 바로 드리고, 디렉터에게도 같은 글을 보냅니다.

사장님께 올릴 것
- 새 한도나 제약. 제안만 해도 올립니다.
- 판정자 둘이 한 번 주고받고도 합의하지 못할 때. 두 의견 원문을 한 장에 올립니다.
- 비용이나 사용권이 걸릴 때(Q20).
- 연구 ASS 우선순위가 부딪힐 때.
- 핵심 기능의 기본값(Q 목록).
- 한 질문에는 한 장만 드립니다. 여러 PM의 의견은 그 한 장에 나란히 붙입니다.

사장님을 늦추지 않기
- 시험판은 소견서를 기다리지 않고 바로 드립니다. 소견서는 같은 날 뒤따라 붙입니다.
- 사장님 답은 '사람 같다/아니다 + 어느 클립' 한 줄이면 됩니다. 디렉터가 해당 PM에게 그대로 전합니다.

5. 넘겨주는 것
형식
- 클립: docs/motion/clips/<무리>_<좌우>.json
  - 한 파일에 작게·보통·크게 세 벌을 담습니다. 벌마다 자기 크기와 시간을 가집니다.
  - 위상 φ0~φg, 120 Hz 채널, 출처·사용권, 판본(v0 교본 / v1 모캡 / v2 촬영), 뼈대 지문, 시작 자세 참조.
  - 검사기를 통과해야 합니다.
- 게임 기록
  - 형식은 동작 PM이 정하고, 디렉터 도구가 그 형식으로 냅니다.
  - 머리 칸에 커밋·시드·Hz·무기·장면을 적습니다.
- 사양표와 모양 목표: docs/motion/ 아래에 둡니다. 모든 수치에 '참고, 한도 아님'을 붙입니다.
- 라운드 판정: docs/reviews/R<n>_<역할>.md
  - 통과/우려, 근거 숫자, 빌드 커밋을 적습니다.
  - 디렉터는 고치거나 요약하지 않고 링크를 그대로 붙입니다.
- 디렉터 병합 메모: 기술 관문 결과, 재현 명령, 제한 신고란, 못 따라간 클립.
