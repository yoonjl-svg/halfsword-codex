## 설치 방법

- **아이폰 (Safari)**: 주소를 Safari 로 연다 → 공유 버튼 → '홈 화면에 추가' → 이름 'Stillness' 확인 → 추가. 홈 화면 아이콘으로 열면 주소창 없는 전체 화면(standalone)이다. (iOS 16.4 이상은 다른 브라우저에서도 홈 화면 추가가 되지만 Safari 를 권한다)
- **안드로이드 (Chrome)**: 주소를 열면 '앱 설치' 안내가 뜨거나, 메뉴(⋮) → '앱 설치' / '홈 화면에 추가'. 설치한 앱은 가로로 잠긴다(`orientation: landscape`).
- 처음 한 번은 인터넷이 연결된 채로 열어 둔다(약 5.6 MB 를 뒤에서 받는다). 그 뒤로는 오프라인에서도 마지막으로 받은 판이 열린다.

## 갱신 방식 (새 판이 곧바로 닿게)

1. **화면(HTML)은 언제나 네트워크 먼저.** 서비스 워커가 HTML 요청을 받으면 HTTP 캐시(GitHub Pages 의 10 분)까지 건너뛰고 서버에 다시 묻는다. 그래서 새 판을 올리면 **다음에 여는 순간** 새 HTML 과 새 묶음 파일(이름에 해시)이 온다 — 워커가 아직 옛 판이어도 마찬가지다. 서버 대답이 10 초 넘게 없거나 오프라인이면 기기에 깔린 판의 HTML 로 연다.
2. **나머지 파일(묶음 JS·소리·그림)은 깔린 판 캐시 먼저.** 목록에 없는 주소(새 판의 새 파일, 옛 실험판, 바깥 주소)는 캐시를 건드리지 않고 그냥 네트워크.
3. **캐시 이름이 판마다 바뀐다**: `stillness-pwa:<scope>:<판 번호>` — 판 번호는 dist 파일 목록·내용의 해시(내용이 바뀐 빌드마다 바뀐다). 브라우저가 열 때마다 `sw.js` 를 HTTP 캐시 없이 다시 묻고(`updateViaCache: 'none'`), 바뀌었으면 새 워커가 뒤에서 새 판을 받는다(바뀐 파일만 내려받고 나머지는 옛 캐시에서 옮겨 담음). 파일 하나라도 크기·해시가 어긋나면 그 판 설치를 통째로 버리고 옛 판을 지킨다.
4. **다 깔리면 곧바로 넘어간다**(skipWaiting · clients.claim). 열린 화면을 강제로 새로 고치지 않는다 — 이미 읽은 게임은 그대로 돈다. 옛 판 캐시는 그때 지운다(같은 출처의 다른 앱·게임 캐시는 건드리지 않음).
5. **안전한 순간 새로 고침**: 아이폰 홈 화면 앱은 껐다 켜도 메모리에서 되살아나기만 할 때가 많다. 그래서 앱(또는 탭)으로 **돌아올 때**마다(30 초에 한 번까지) 서버의 `index.html` 이 지금 판과 다른지 보고, **첫 화면(아직 '싸움 시작'을 누르지 않은 상태)** 이면 그 자리에서 새로 고쳐 새 판으로 연다. 싸움 · 무기 뽑기 · 결과 화면(여정 도중)에서는 새로 고치지 않는다 → 다음에 열 때 새 판.

정리: 새 판을 올린 뒤 사장님은 **앱을 새로 열거나, 첫 화면에서 다른 앱에 갔다 돌아오면** 새 판을 본다. 싸우던 도중이었으면 그 판은 끝까지 옛 판, 다음 열 때 새 판.

## 비상 스위치

- 웹 주소 끝에 **`?nosw=1`** (예: `https://yoonjl-svg.github.io/halfsword/?nosw=1`): 이 주소의 서비스 워커를 내리고 그 캐시를 지운다. 화면 위에 '서비스 워커를 내렸습니다 …' 한 줄이 5 초 뜬다. 그 화면에서는 다시 등록하지 않는다. 다음에 `?nosw=1` 없이 열면 새로 설치된다.
- **홈 화면 앱에는 주소창이 없다.** 아이폰에서는 앱과 Safari 의 저장 공간이 따로라서 Safari 에서 `?nosw=1` 을 열어도 앱의 워커는 그대로다. 앱에서 문제가 생기면: (1) 앱 아이콘을 길게 눌러 지우고 다시 '홈 화면에 추가', 또는 (2) `src/pwa.js` 의 `PWA_ENABLED` 를 `false` 로 바꿔 배포 — HTML 이 늘 네트워크 먼저라서 다음에 온라인으로 열 때 모든 기기(앱·웹)에서 워커가 내려가고 캐시가 지워진다.
- 개발 서버(`npm run dev`)에서는 등록하지 않는다.

## 앱 · 웹 저장 공간은 따로 (중요)

**아이폰에서 홈 화면 앱과 Safari 는 저장 공간(localStorage · 캐시 · 서비스 워커)이 따로다.** 그래서 **'여정 깬 수 · 인장'(unique_assist.js 의 깬 수), 설정(`gladiator-settings`), 테스트 고르기 기억은 앱과 웹 사이에 이어지지 않는다.** 앱에서 깬 무대는 앱에만, Safari 에서 깬 무대는 Safari 에만 쌓인다. 안드로이드 Chrome 은 설치한 앱과 Chrome 탭이 같은 저장 공간을 쓰는 것이 보통이지만 기기·브라우저마다 다를 수 있다. 옮기는 기능은 아직 없다(계정·서버 저장이 필요 — 이번 범위 밖).

## 확인 (10/13, 크로미움 · `tools/pwa/lifecycle.mjs`)

`npm run build` 뒤 `node tools/pwa/lifecycle.mjs dist <빈 작업 폴더>` — dist 를 판 A·B(진입 묶음 이름·HTML 표시가 바뀐 새 판)·C(바뀐 파일 하나가 깨진 판)로 복사해 하위 경로 `/halfsword/` 에 GitHub Pages 처럼 `Cache-Control: max-age=600` 을 붙여 띄우고, 폰 가로(844×390, 터치) 크로미움으로 본다. 11 항목 모두 통과:

1. 매니페스트 읽힘(이름 'Stillness' · start_url·scope·id = `/halfsword/` · 아이콘 크기 = 파일 크기 · maskable 따로 · apple-touch-icon 192) · 크로미움 설치 가능 조건 오류 없음 · 워커 등록 · 판 A 통째로 담음
2. 다시 열면 워커가 화면을 맡음
3. 오프라인으로 새로 열기 → 판 A · 소리 파일 · 첫 터치('싸움 시작')로 소리 켜짐(자동 재생 막힘 설정)
4. 판 B 를 올리면 다음 여는 화면이 **곧바로 판 B** (워커는 아직 판 A, HTTP 캐시 10 분이어도)
5. 새 워커가 판 B 를 담고 곧바로 넘어감 · 판 A 캐시만 지움 · 남의 캐시 그대로 · **바뀐 파일만 내려받음**
6. 첫 화면에 있던 판 A 창은 돌아오면 판 B 로 새로 고침 · 싸우던 창은 그대로
7. 판 B 로 넘어간 뒤 오프라인 새로 열기 → 판 B
8. 깨진 판 C → 설치 통째로 버림 · 판 B 캐시 유지
9. `?nosw=1` → 워커 내림 · 이 scope 캐시 지움 · 남의 캐시 그대로
10. 그 뒤 그냥 열면 다시 설치
11. `test.html` · `voices.html` · `sounds.html` 그대로 열림

## 알려진 한계

- **실기기 확인 남음**: 아이폰 '홈 화면에 추가' · 안드로이드 설치 · 노치 안전 영역 · 소리는 크로미움 흉내로만 봤다(안전 영역은 index.html 의 `env(safe-area-inset-*)` 가 이미 HUD·조이스틱·막기 버튼·일시정지 줄에 걸려 있음 — `viewport-fit=cover` · 상태 막대 `black-translucent`). 첫 터치로 소리가 켜지는 흐름(sound.unlock)은 앱에서도 같은 코드다.
- 아이폰은 오래 안 쓴 웹 앱의 저장 공간을 지울 수 있다 → 그러면 다음 온라인 실행 때 다시 받는다(오프라인이면 안 열릴 수 있음).
- 크로미움에서 새 워커가 skipWaiting 을 불러도 가끔 '설치됨'에 머무는 것을 재어 봤다(옛 판 창이 열려 있을 때) → 화면이 등록·설치 끝·돌아올 때 `pwa:skip` 을 한 번 더 보내 넘어가게 했다. 넘어가지 않더라도 HTML 은 네트워크 먼저라 새 판은 열린다(오프라인 캐시만 늦게 바뀜).
- 판 C 처럼 서버가 잠깐 어긋난 파일을 주면(배포 도중) 그 판은 깔리지 않고 다음 확인 때 다시 받는다.
- 오프라인 목록에 옛 실험판(`corr/ r2p/ support/ wb/`)은 없다 — 주소로는 그대로 열리지만 오프라인에선 안 열린다.
- 앱스토어 배포 · 푸시 알림 · 앱·웹 저장 공간 잇기는 없다.
