# 이탈리아 I7·I2·I9 시험 방법

기준 본판은 `88a96061e8dd93e8f107b7b0df647a341e73fa5d`입니다. 리솔루토는 별도 담당이며 이 자료에는 포함하지 않았습니다. 실행 환경 확인에 `cloud-environment:cloud-environment-runtime` 지침을 적용했습니다. 게임의 `src/`와 공통 시뮬레이터는 이 담당자가 변경하지 않았습니다.

## 실행 조건과 대조군

- 매 시행마다 Rapier world와 두 Fighter를 새로 만듭니다. 롱소드 상대·레이피어 플레이어, 기본 주인공/상대 외형을 사용했습니다. 주인공은 케틀햇, 상대는 투구 없는 기본 복장입니다. 피해·상처·사망·넘어짐·칼 놓침을 정상 적용합니다.
- 정상 해금의 이탈리아 스킬 키트를 사용하고 켬/끔 쌍에서 대상 기술만 `kit.unique`에서 뺍니다. 보조 칸·보법·막기·패시브·기력은 유지합니다. 끔은 효과 분해 대조군이며 정상 육성 키트라는 뜻이 아닙니다. `perks` 보강에서만 I8 헛누름을 별도로 제거합니다.
- `humanInput=true`, 최대 기력 100, 무한 기력 꺼짐, 사람 회복 기준 초당 25입니다. 레이피어 무게에 따른 실제 공격 비용도 원래 계산을 따릅니다. 특수 공격 식힘, 카바치오네 기본 속도 및 1.2 보정, 인콰르타타의 0.3 속도 몫, 공격 시간 상한 0을 유지했습니다.
- 비기 감시기/실행 경로는 이 세 공격의 효과 분해에서 제외했습니다. 판당 비기 횟수나 특수 식힘 상수를 변경한 것은 아닙니다. 따라서 완성형 키트의 자연 선택 빈도나 비기와의 우선순위 시험은 아닙니다.

## 실제 조건과 입력 경로

칼 쪽 입력은 원본 `Input.onDown/onMove/onUp → consumeHandDelta/consumeTaps → PlayerUniqueAssist.feed / Skill.thrust`를 통과합니다. 터치 감도·세로 배율·탭 시간·탭 이동 문턱은 원본 Input의 계산입니다. 옆 이동은 `Input.stickMove → Input.move`의 명시적 노드 프록시입니다. 브라우저 DOM 스틱의 원형 배치와 trusted 이벤트는 이 시험에 포함하지 않았습니다.

Node용 `window` 표면은 Input 생성/입력 함수 호출 동안만 설정하고 즉시 복구합니다. 매 world step 전에 `window`가 남아 있으면 오류로 중단합니다. Rapier가 실행되는 동안 브라우저 부분 shim을 상시 두지 않았습니다.

입력 프록시는 두 물리 스텝마다 한 번(`FRAME=2/120`게임초, 기본 템포의 기준 시간으로 약66Hz) 전달합니다. 실제 브라우저의 화면 갱신 묶음이나 사용자 기기의 입력 빈도를 재현한 주장이 아닙니다.

| 기술 | 준비 정책 | 발동 입력 | 조건의 관측 |
|---|---|---|---|
| I7 임브로카타 | 상대는 칼을 낮게 둔 수동 몸, 플레이어는 정상 회복 속도로 시작 자세에 손을 옮깁니다. | 수직 `oberhau` 내려긋기. 추가 `paths`에서 원래 `stichOchs` 및 사선 `zornhau`도 시험합니다. | 원본 감지기가 읽은 강화동작 요청과 실제 강화/탭 실행을 구분합니다. |
| I2 카바치오네 | 상대는 긴 자세, 플레이어는 막기 버튼 경로로 접촉을 준비합니다. I6 막아찌르기의 실제 효과와 준비 피해도 남깁니다. | 실제 칼 접촉 덩이를 처음 본 뒤 정한 박자에 탭합니다. 탭을 떼기까지의 시간도 실제 Input을 통과합니다. | `feel.touching → touchTick`으로 생긴 원본 접촉만 사용합니다. 새 접촉으로 바뀜, 내 베기의 접촉 제외, 이른 탭 소진을 기록합니다. |
| I9 인콰르타타 | 상대의 발 이동 명령은 0, 롱소드 `zornhau` 손목표 입력을 한 번 실행합니다. 실제 팔·칼의 물리는 정상입니다. | 원본 막기 감시기가 실제 위협을 읽으면 정한 반응 뒤 옆 스틱과 탭을 넣습니다. | `PlayerParryGuard`의 원본 `threatNow`, `noThreat`, `threatId`를 읽습니다. 위협 값을 쓰거나 접촉을 주입하지 않습니다. |

인콰르타타의 처음 `pilot`만 자유 AI 상대입니다. 거리 조건이 접근 이동 때문에 섞여, `pilot_validated`와 본 시험은 위 표의 상대 단발 입력으로 통제했습니다. 그 상대는 사람 입력 기록이나 자연 AI 선택의 표본이 아닙니다. 실제 위협 판정은 준비 자세로 칼을 옮기는 동안에도 열릴 수 있습니다.

초기 간격(m)은 임브로카타/인콰르타타 1.15·1.55·1.95, 카바치오네 1.10·1.45·1.80입니다. 몸이 안착하고 준비/동작을 수행하면 거리가 달라집니다. 실제 입력 시점·실행 시점의 거리를 snapshot에 함께 보존했습니다. 가까움·보통·끝은 이 시험의 세 조건 이름이며 모든 공격의 절대 사거리 분류는 아닙니다.

## 입력 변동과 독립성

첫 `matrix`는 3기술×3거리×6시드×켬/끔=108개입니다. 수동 상대와 정확히 같은 명령에서 시드만 달라지면 물리 결과가 같은 시행들이 있습니다. 이 반복을 독립 표본 6개나 정밀한 확률 추정으로 해석하지 않습니다.

`seeded`는 같은 108개 설계를 여섯 개의 서로 다른 정상 입력 명령으로 보강합니다. `inputs`는 정확/작은/큰 흔들림×8개 입력 시드×3기술=72개입니다. 이들은 여덟 개의 명시적 정상 입력을 공유하며, 그 위에 흔들림을 더합니다. 시드별 실제 궤적과 샘플 값은 원본 JSONL에 있습니다.

| 정상 입력 은행 | 여덟 값(각 켬/끔 쌍은 같은 값을 사용) |
|---|---|
| 내려긋기 속도(패드 m/게임초) | 3.0, 3.4, 3.8, 4.2, 4.6, 5.0, 5.4, 5.8 |
| 접촉을 본 뒤 탭을 누를 때까지(기준초) | 0.25, 0.35, 0.45, 0.55, 0.65, 0.80, 0.95, 1.05 |
| 위협을 본 뒤 탭을 누를 때까지(기준초) | 0.04, 0.06, 0.08, 0.10, 0.12, 0.14, 0.17, 0.20 |
| 탭을 누르고 있는 시간(기준초) | 0.04, 0.05, 0.06, 0.07, 0.04, 0.05, 0.06, 0.07 |

작은 흔들림: 시작 위치 가우스 σ0.06 패드 m, 방향 σ0.10 rad, 경로 끝 σ0.035 m, 속도 σ0.35, 시점 σ0.09초, 옆 스틱 σ0.13, 스틱 선행 σ0.025초, 탭 유지 σ0.018초, 탭 이동 각 축 σ3px입니다. 큰 흔들림은 각각 0.20m·0.45rad·0.16m·1.8·0.45초·0.55·0.12초·0.15초·14px입니다. 실제 샘플은 기록한 범위로만 절단합니다. 분포는 사용자 손 입력에서 추정한 것이 아닙니다.

‘정확’은 정한 명령에 흔들림을 추가하지 않았다는 뜻입니다. 접촉이 새로 바뀌거나 상대 칼의 위협이 사라지면 정확 묶음도 실패할 수 있습니다. 이 운전기는 화면 영상의 단서 대신 내부의 실제 접촉/위협 관측을 사용합니다. 결과 명칭은 **노드 자동 입력의 발동 내성**이며 실제 인간 성공률이 아닙니다. 직접 `requestArtThrust`를 호출하거나 창/위협/접촉을 강제한 시행은 없습니다.

## 분모와 피해의 의미

`denominators`는 새 몸 시행, 조건 덩이, 의도된 입력 시도, 대상 기술 요청 수락, 실제 동작 실행, 대상 기술 몸 접촉, 실제 새 상처를 별도로 셉니다. `Skill.thrust()`가 보통 탭을 수락한 것과 카바치오네/인콰르타타 요청 수락은 다릅니다. 요청이 수락됐다는 이유만으로 실제 실행을 세지 않습니다. 여러 프레임 이어진 같은 동작은 한 번으로 셉니다.

`physiology`는 원래 `applyWound`를 실행한 전후를 읽습니다. `actualWounds > 0`인 실제 베기/찌르기 상처의 심각도만 실상처 합에 넣습니다. 분석 단계의 접촉 심각도, 방어구/옷에 막힌 둔타, 몸에 적용된 실상처를 혼합하지 않습니다. 둔타의 의식 손실은 별도 생리 결과입니다. 준비 전에 생긴 상처, 대상 기술의 상처, 회수/다른 공격의 상처를 구분합니다. 받은 피해는 준비·실행 시간대·회수 시간대로도 구분합니다.

대상 기술 귀속은 사건 시점의 원본 `strokeTechOf`/IAI 기술 이름과 입력 시각을 함께 사용합니다. 동작이 끝난 뒤 잔여 칼 운동과 물리적인 연쇄 효과의 원인을 완전히 분해하는 방법은 아니므로, 같은 입력의 켬/끔 총 결과도 나란히 제공합니다. `cause='기절'`을 KO로 분리하고 `state=dead`만으로 생물학적 사망이라고 부르지 않습니다.

동작 시작 뒤 1초·5초 snapshot과 공통 입력 시점 뒤 1초·5초 snapshot을 남깁니다. 종료 상한 때문에 관측하지 못한 시점은 null입니다. 첫 목표 입력 시점 뒤 보통 6기준초까지 관측하며 전체 관측 상한은 15기준초입니다. 이 상한은 관측 종료이며 공격 동작을 강제로 끝내는 제한이 아닙니다. 초기 2게임초의 판 시작 안착도 원래대로 유지했습니다. 물리 시간·`TIME.k=1.1`을 나눈 기준 시간·실측 벽시간을 모두 기록합니다. 브라우저의 피격 정지/렌더링 벽시간을 그대로 재현한 수치로 부르지 않습니다.

`controlRecovery`는 동작의 손 제어 잠금이 해제된 시점의 관측입니다. 새 손/발 입력을 넣어 반응을 재확인하는 시험은 하지 않았으므로 완전한 손맛/조작 복구 시간으로 해석하지 않습니다. 넘어짐·기절·사망·무장 상실은 각각의 사건과 실제 상태를 함께 보셔야 합니다.

## 재현과 파일

루트에서 다음 명령을 한 프로세스씩 실행합니다. CLI가 run별 manifest, 코드/core snapshot, 원본 JSONL, 요약, 실측 timing을 저장합니다. 코드 snapshot은 증거 보존용이며 재현하려면 원래 `tools/sim/balance_italian_20261101.mjs` 위치에서 상대 import를 유지해 실행하십시오.

```sh
node tools/sim/balance_italian_20261101.mjs pilot
node tools/sim/balance_italian_20261101.mjs seeded
node tools/sim/balance_italian_20261101.mjs inputs
node tools/sim/balance_italian_20261101.mjs paths
node tools/sim/balance_italian_20261101.mjs perks
```

`pilot`은 초기 운전기, `pilot_validated`는 실제 조건/기록 검증, `matrix`는 단일 정상 입력 반복 탐색, `seeded`가 서로 다른 정상 명령을 사용한 주 단발 비교입니다. `paths`는 I7의 두 추가 경로, `perks`는 I2에서 I8을 제거한 추가 짝시험입니다. 주 본판 코드는 원본 SHA로, 공통 관측부는 run별 snapshot과 해시로 고정합니다. 입력 UI의 실제 DOM 및 trusted touch 확인, 30초 자연 선택 판은 다른 담당 자료와 분리합니다.
