# 독일 외 비기 계측

고정 본판은 `88a96061e8dd93e8f107b7b0df647a341e73fa5d`이며 실행기는 `tools/sim/balance_secrets_20261101.mjs`입니다. `src/`와 기존 하니스는 수정하지 않습니다. 표와 원본의 시간은 별도 표시가 없으면 **물리 시간 ÷ TIME.k(1.1)**인 기준 초입니다. 실제 실행 벽시계는 각 행 `timeline.wallSeconds`, 배치 전체는 요약 `measuredWallSeconds`에 있습니다.

## 시험의 뜻

| 모드 | 입력과 상대 | 해석 |
|---|---|---|
| `direct_potential` | 기본 시작 정지·서기·자세 회수를 그대로 3기준 초 관측한 뒤 비기 직접 요청, 무기를 든 정지 상대 | 조건을 건너뛴 잠재 위력. 격살 4자세는 요청 문맥에서 선택합니다. 조작성·기회·자연 빈도 자료가 아닙니다. |
| `conditional_upper` | 실제 `PlayerSecretWatch`, 막기 버튼, 정상 탭/긋기/공격 원/스틱 입력을 통한 첫 사용, 기본 롱소드 AI 상대 | 엔진의 실제 창과 기하를 읽는 조건부 자동 입력입니다. 저장 이름의 `upper`는 참값 관측을 뜻하며, 이 대본이 최적 입력이라는 수학적 상한 보장은 없습니다. 실제 DOM 입력/렌더링을 거친 사람 성공률은 아닙니다. 기회를 못 만들거나 실행이 거절된 판도 남깁니다. |
| `scripted_30s` | 위 자동 정책을 30기준 초 유지하는 선택 실행 모드 | 특정 대본의 사용 횟수입니다. 사람의 자연 빈도로 바꾸지 않습니다. 정책에 엔진 참값 관측이 있으므로 일반 사람 플레이의 대리 표본이 아닙니다. |

켬/끔의 `off`는 비기 연결만 끈 실험 대조군입니다. 조건 모드는 같은 입력 정책이 일반 공격/막기/전진으로 계속됩니다. 직접 요청의 대조는 보통 탭 또는 하나의 왼쪽 아래 긋기입니다. 후자는 동작 자체가 다르므로 순수 피해 배율 비교가 아닙니다. 어느 대조군도 정상 육성 상태라고 부르지 않습니다.

사람 몸은 `humanInput=true`, 최대 기력100, 장비 덧0, 무한 기력false입니다. 기본 회복25/기준 초, 비기 제한1회(동방3회), 기력>0 조건, 실제 상처·출혈·의식·사지·죽음·넘어짐·무기 놓침을 유지합니다. 제한과 설정 해시는 각 행에서 검증합니다. 양측 기본 외형은 기존 하니스 그대로이며 플레이어는 케틀햇, 상대는 투구 없는 기본 외형입니다. 모든 유파의 공격·패시브·막기·심화 칸은 시뮬 기본 해금 상태와 정상 고유 공격 보조기를 사용합니다. 손 보조 숙련 몫 `skill.level`은 하니스 기본0.7입니다.

물리는120 Hz, 입력은60 Hz이고 누락된 프레임을 버리지 않습니다. 카메라, 렌더링, 타격 멈칫, 비기 연출 늦춤은 없습니다. 기존 `ARENA.startHold=2.0`물리 초와 실제 몸의 발 묶임을 유지합니다. 관측기는 공격을 취소하거나 새로운 공격 시간 제한을 넣지 않습니다. 관측 예산이 끝났는데 동작이 살아 있으면 `observationComplete=false`로 따로 표시합니다. 정상 단발은 첫 요청 뒤5기준 초 이상, 실행이 끝날 때까지 관측합니다. 기회가 없으면30기준 초 또는 사망까지 관측합니다.

## 입력 정책

- 리솔루토: 기존 도구처럼 내 칼 손 쪽 절반을 상대 칼끝 쪽 절반 위로 느리게 옮깁니다(손 목표0.6m/물리 초). 앞/뒤 스틱은0.2기준 초 늦게 본 상대 걸음에 맞춥니다. 창 뒤0.25기준 초에 탭을 시도합니다. 덮음 거리·간격·걸음 조건과 취소 이유는 실제 `RisolutoWatch`에서 기록합니다.
- 싱지르: 칼끝 거리 밖에서 기본 무장을 기다리고 목표 거리에 접근합니다. 실제 무장 창 안에서 반지름0.15손m, 0.8기준 초, 1.35바퀴 원 궤적을 입력합니다. `spinCircle`가 읽고 `fire→Skill.secret`로 연결합니다. 기존 최소 크기·각도·시간 조건을 바꾸지 않습니다.
- 고노센: 실제2초 무행동 준비를 기다리고, 준비 뒤에만 목표 거리까지 걷습니다. 상대의 실제 사건 창 뒤0.25기준 초 탭을 시도합니다. 현재 기본 허리 대기, 준비/이동/상대 사건 규칙을 유지합니다.
- 격살: 상대 AI의 공격 시작을0.25기준 초 뒤에 보고 막기 버튼을 누르며 앞으로 걷습니다. 실제 새 맞댐→상처 없이 떨어짐→자동 대기열→실행을 따릅니다. 정상 조건에서는 받은 자세를 강제하지 않습니다. `diagnostic.gk`에 맞댐·누름 없음·늦음·전진 아님·느린 칼·다침·공격 중·자세 없음·대기·부상 취소·열린 창·실제 자세 분포를 보존합니다. 한 프레임을 한 번의 기회로 세지 않습니다.

## 거리와 피해 기록

가까움/보통/끝은 직접 요청에서는 시작 가슴 간격입니다. 조건 입력 v3는 아래 기준 간격에 접근 공간0.9m를 더해 서로 다른 초기 가슴 간격을 만듭니다(고노센은 아래 간격 그대로). 싱지르·고노센은 아래 기준을 접근 목표로도 씁니다. 리솔루토·격살은 실제 조건을 만드는 스틱 정책을 따르므로 아래 기준에서 멈추지 않습니다. 실제 요청 시점 간격은 `events`의 `accepted`/`attempt`에 따로 있습니다. 초기 거리 조건과 발동 거리가 같다고 가정하지 않습니다.

| 기술 | 가까움 / 보통 / 끝 |
|---|---|
| 리솔루토·격살 | `measure.contact + [-0.15, 0.05, 0.25] m` |
| 싱지르 | `measure.reach + [-0.15, 0.1, 0.3] m` |
| 고노센 | `measure.reach + japaneseReach + [-0.3, 0, japaneseFar] m` |

조건 v3의 `attempted`는 의도된 탭·원 시작·새 막기/전진 누름의 횟수이며, `requestAttempted`는 실제 비기 실행 요청 횟수입니다. 원을 시작해도 인식/조건 실패로 요청까지 못 갈 수 있고, 여러 번 막기를 누른 뒤 한 번 자동 격살이 나갈 수 있습니다. `accepted`는 `Skill.secret` 수락, `started`는 수락된 실행에서 **실제 `Skill.updateSecret` 최초 콜백**입니다. 같은 실행은 한 번만 셉니다. 비기 소모는 실제 `PlayerSecretWatch`가 기록하며 매 행 제한 내인지 검증합니다. 직접 요청 v2의 `attempted`는 직접 요청 수로서 입력/요청 단계가 하나입니다.

`severity`는 `onWound`가 보고한 접촉의 심각도 합입니다. `lacerationSeverity`는 실제 새 상처 목록의 합이며 절단 단면 상처가 추가되면 두 합이 다를 수 있습니다. 실제 출혈·의식·사지 기능·사망은 전후 몸 상태에서 별도로 계산합니다. 끝 시점 의식 회복이 손실을 가릴 수 있어 최저 의식에서 계산한 `peakConsciousnessLost`도 남깁니다. `limbsLost`는 사지 기능 손실 합이며 실제 절단 부위는 `detachedParts`입니다. 에너지를 치명률로 환산하지 않습니다.

피해 합은 준비 시작부터 관측 끝까지입니다. 시작 뒤1초·5초 몸 상태와 각 상처의 부위·시각·비기 단계, 종료·굳음·상태 변화·무기 놓침을 원본에 남겨 공격 전후 교환을 분리할 수 있습니다. 위력 결과를 판 승률로 부르지 않으며, 자기 피해가 있어도 더 큰 상대 손실과 함께 봅니다.

현재 정본은 `potential_v2.jsonl`/`.summary.json`과 `conditional_v3.jsonl`/`.summary.json`입니다. 재실행은 위처럼 사용하지 않은 `--out` 경로를 주십시오. 실행기는 기존 원본을 덮어쓰지 않습니다. 직접 요청 v2 이후 입력 의도/요청 구분 필드가 추가됐으며 직접 요청의 몸 상태·위력 경로는 같습니다. 조건 v2와 v3는 초기 간격 설계도 다르므로 서로 다른 설계 확인본입니다.

`pilot.jsonl`은 최초 기록부 확인본입니다. 최초 버전은 요청 수락 때 `started`도 함께 세었으므로 실행 정의를 검증한 파일럿은 **`pilot_v2.jsonl`**입니다. v2의11행은 최초본과 양측 최종 몸 상태가 모두 동일하고, 모든 실제 실행 콜백/설정 해시/소모 제한 검증을 통과했습니다. 파일럿11행 시험 루프의 실측 소요는11.43초(모듈 초기 로드 별도)였습니다. 파일럿은 확대 배치와 같은 시드·조건의 재실행이어서 독립 표본에 합산하지 않습니다.

조건 `conditional_v2.jsonl`은 중단한 설계 확인본입니다. 의도된 원/막기 입력보다 실행 요청을 `attempted`로 세었고, 리솔루토 가까움/보통 초기 간격이 같은 값으로 묶이는 문제가 있어 정본 결과에 합산하지 않습니다. 조건 v3는 의도/요청을 분리하고 초기 간격을 묶지 않습니다. `pilot_conditional_v3.jsonl`은 중간 확인본이며 싱지르 끔 대조에서 같은 원을 여러 프레임 요청으로 세는 문제를 확인했습니다. 정본은 첫 요청 때 창을 실제 `fire()`로 소비하고 요청을 한 번만 기록합니다. 수정 뒤 `circle_off_check_v3.jsonl`에서 원 의도1·요청1·비기 수락0·실행0을 확인했습니다. 이 확인본들도 독립 표본에 합산하지 않습니다.

확대 배치252+144=396행을 완료했습니다. [결과와 실패 사유](RESULTS.md), [검증](validation.json), [정본 원본 목록](artifacts.json)을 확인하십시오. 중간 확인본과 파일럿은396행에 합산하지 않습니다.
