# 비기 입력 변주96케이스

정상 게임 조건을 유지한 **4비기 × 정확/소폭/큰 흔들림3수준 × 실제 다른 입력 계획8개**입니다. 무기는 레이피어·츠바이핸더·우치가타나·환도, 상대는 기본 롱소드 AI입니다. 모든 케이스의 상대 난수 시드는2로 고정합니다. 같은 궤적을 시드만 바꾼 반복이 아니라 실제 시간·궤적·속도를 바꿉니다. 여덟 기본 계획은 세 흔들림 수준에서 짝을 이룹니다.

사람 회복25/기준 초, 기력최대100/장비 덧0/무한false, 비기1회(동방3회), 기력>0, 상처·출혈·의식·사지·종결·넘어짐·무기 놓침을 유지합니다. `CONFIG` 상수를 바꾸지 않으며 직접 비기 요청·강제 명중·기회 조건 완화도 없습니다. 실제 `PlayerSecretWatch→fire→Skill.secret→updateSecret`를 통과합니다. 준비 실패나 요청 전 종결도 그대로 남깁니다.

## 입력 범위

입력 경계는 **60Hz의 main 프레임 소비 입력**(손 변화량·탭·스틱·막기 버튼)입니다.120Hz 물리와 실제 창/자세/기력 조건을 사용합니다. DOM의 터치/마우스 이벤트 분류, 픽셀 이동·데드존·실제 화면 단서 반응은 이 파일의 측정 범위가 아닙니다. 엔진의 창과 기하를 읽는 조건부 대본이므로 사람 성공률·자연 빈도로 해석하지 않습니다. 카메라·타격 멈칫·연출 늦춤은 없습니다. `TIME.k=1.1`로 물리 시간을 기준 초로 바꾸며 원시 물리 시각도 남깁니다.

`exact`는 추가 흔들림이 없는 계획입니다. 여덟 계획의 기본 반응 시간 자체는0.16,0.18,…,0.30초로 다릅니다. 조작 시작 시점도0~0.117초로 다릅니다. 손 추적 속도0.565~0.670m/물리 초, 수직 덮음 목표0.0265~0.037m, 상대 걸음 반응0.17~0.24초, 스틱 크기0.91~0.98도 실제로 바뀝니다. 고노센은 준비를 지킨 뒤 서로 다른 시점의 탭을 실제로 입력합니다.

| 손잡이 | 정확 | 소폭 | 큰 흔들림 |
|---|---|---|---|
| 반응 추가 오차 | 0 | 계획별 부호를 가진0.021~0.042초 | 같은 오차의5배 |
| 리솔루토 추적/고노센 탭 접근 중 손 흔들림 반경 | 0 | 0.006손m | 0.045손m |
| 손 흔들림 주파수 | 계획마다4.7~6.1Hz | 같은 기본 주파수 | 같은 기본 주파수 |
| 스틱 추가 각도 진폭 | 0° | 10° | 65° |
| 막기 반응 추가 오차 | 0 | ±0.045초 | ±0.225초 |
| 막기/전진 동시성 오차 | 0 | 계획별 ±0.015~0.036초 | 같은 오차의5배 |
| 공격 원 반지름 추가 변동 | 0 | 반지름의8% | 반지름의45% |
| 원의 진행 속도 변동 | 0 | 3.5% | 26% |

공격 원의 기본 계획도 실제로 다릅니다. 반지름0.140~0.168손m, 소요0.700~0.875초,1.220~1.395바퀴이며 시작 방향·타원 축·시작 지연도 계획별로 바꿉니다. 원과 계획된 탭은 게임이 실행 중 입력을 버리더라도 제시간에 진행·종료합니다. 끝난 몸짓을 실행 뒤에 다시 이어 그리지 않습니다.

위 크기는 이 연구의 실험 설정이며 사람에게서 측정한 오차 분포가 아닙니다. 큰 흔들림이 무조건 더 나쁜 결과를 내도록 정렬하거나 성공할 때까지 시도/시드를 교체하지 않습니다. 원시 `inputPlan`에 모든 수식 결과와 단위가 있습니다.

## 기록과 검증

- `attempted`: 의도된 탭 접근/원 시작/새 막기와 전진 누름. 격살은 한 실행을 만들기 위해 여러 막기 시도를 할 수 있습니다.
- `requestAttempted`: 실제 비기 실행 요청. 큰 흔들림이 의도된 공격 전에 창에서 긋기로 읽혀 나가면 별도 `request_without_intended_attack` 이벤트가 있습니다.
- `accepted`: 실제 요청 수락. `started`: 그 실행에서 최초 실제 `Skill.updateSecret` 콜백. `ended`와 결과가 동작 종료·접촉/막힘/헛침을 보여 줍니다.
- `intendedInputTrace`: 게임의 실행 잠금으로 버리기 전의 계획된 매 프레임 입력입니다. `inputTrace`: main 입력 프레임의 분기 뒤 기록이며 손 변화량이 실제 손 목표에 반영되는지는 비기/막기/기력 잠금에 따릅니다. 원시 시각·손 변화량·탭·스틱·누름을 보존하고 실제 실행은 별도 콜백으로 셉니다.
- `inputActionDigest`: 유휴 프레임을 제외한 실제 의도 입력 궤적의 해시입니다. 같은 비기·같은 흔들림 묶음 안에서8개의 서로 다른 입력인지 확인합니다. 단순 관측 종료 시각만 달라져 해시가 달라지는 것을 이 검증으로 피합니다.
- 양측 피해는 준비부터 관측 끝까지 기록합니다. 실행 전·실행/굳음 중·후속 관측의 접촉 심각도를 추가 요약에서 분리합니다. 공격 자체를 새 시간 상한으로 취소하지 않습니다.
- `dead`는 기존 공통 스키마의 엔진 종결 플래그입니다. `engineEnded`·`knockedOut`·`engineEndCauseClass`도 기록하고 KO/출혈/머리/목을 따로 셉니다. 생리적 비가역성을 별도로 확정하는 검사는 아닙니다.

정지 상대에서의 단발 잠재 위력252행이나 기존 조건144행은 이96케이스와 합쳐 입력 표본 수를 부풀리지 않습니다. 입력 계획8개는 작은 설계 탐색이며 사람의 성공 확률을 추정하는 독립 무작위 표본8개가 아닙니다.

## 재현

```sh
node tools/sim/balance_secrets_20261101.mjs --suite=input --out=docs/research/attack_balance_20261101/secrets/input/matrix_replay
```

`--input-levels=exact,small,large`, `--input-plans=1,2,3,4,5,6,7,8`, `--opponent-seed=2`가 기본입니다. 기존 원본을 덮어쓰지 않으므로 재실행은 새 `--out` 경로를 사용합니다. 현재 정본은 `matrix_v2.jsonl`과 `matrix_v2.summary.json`입니다. 96행을 완료했습니다. 실제 입력 궤적·설정/한도·실행 콜백·종결 원인 검증은 [validation.json](validation.json), 정본 해시와 제외 파일은 [artifacts.json](artifacts.json), 결과는 [RESULTS.md](RESULTS.md)에 고정했습니다.

`pilot_v1.jsonl`은 계획1의12케이스 확인본이며 정본에 합산하지 않습니다. `matrix_v1.jsonl`은 계획된 원/탭이 실행 중에도 제시간에 끝나도록 운전기를 점검하면서 중단한 확인본입니다. `circle_progress_check_v2.jsonl`은 원 진행 확인3케이스, `non_input_regression_v1.jsonl`은 기존 입력 없는 계획의 계측 회귀 확인1케이스입니다. 모두 정본96행에서 제외합니다. 기존 고노센 조건 정본과 회귀 확인본의 양측 최종 몸 상태가 동일했습니다.
