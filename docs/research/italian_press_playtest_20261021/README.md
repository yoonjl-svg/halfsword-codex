# 입력형 막아찌르기 — 누르는 순간 약하게 찌르기

사용자 2026-10-21: 접촉 뒤 자동 반격 대신 **막기 버튼을 누르면 기본적으로 공격이 나오고, 방어선과 비슷한 길로 약하게 찌르며 피해를 교환한다. 동작 중 피해 감소로 교환을 유리하게 만든다.** 이 요청에 따른 별도 비교판이다. 정식 밸런스 확정이나 우화 main 반영이 아니다.

## 시험판 동작

`encounters/italian-press-20261021/`의 기본은 **입력형 · 피해 감소45%**. 30%, 감소 없음, 이전 접촉형+전진 스텝도 선택할 수 있다.

- 레이피어·이탈리아 막기 책을 사용 중일 때, 버튼/F를 새로 누른 다음 물리 틱에 시작한다. 상대 공격 번호, 칼 접촉, 정밀 입력 창을 기다리지 않는다. 실제 근접 터치 검사에서 검증 입력4.0667초→시작4.0750초, 다음1틱이었다.
- 누른 순간 읽은 막기 줄에 따라 칼자루를 위/아래·좌/우 방어선에 둔다. 칼끝은 가슴을 겨누되 칼 든 아래팔이12cm 이상 가까우면 그 팔을 우선한다. 첫0.18초 동안 목표 이동을 최대10cm만 따라가며 이후 고정한다. 손 목표는42cm 뻗는다(실제 손/몸 이동량을 보장하는 값은 아니다). 어깨·몸통은 기존 보통 찌르기의−20°/−20°·숙임8°·낮춤7cm로 부드럽게 이어진다.
- 정상 기력 기준 뻗기0.28초+끝 유지0.12초+회수0.24초=0.64초. **한 입력 한 동작**이다. 누르고 있어도 재발동하지 않는다. 동작이 끝난 뒤 놓았다가 다시 눌러야 한다. 동작 중 다시 눌러도 타이머가 갱신되지 않는다.
- 짧게 눌렀다 놓아도 시작한 공격과 받는 구간은 한 번 마친다. 쓰러짐·탈진·무장 해제·사망·다른 수동 공격/비기 등에서는 취소한다. 자동 스텝은 새 안에 붙이지 않았다. 이동 스틱으로 걸을 수 있다.
- 동작 중 주는 칼날 상처는60%, 둔타의 피해 에너지도60%. **가짜 명중이나 고정 피해는 없으며 실제 칼과 몸의 충돌로만 피해가 생긴다.** 사거리 밖/빗겨감/물리 막힘은 그대로다. 실제 전투에서 성공할 확률이60%라는 뜻이 아니다.
- 받는 피해 감소45%(비교30%/0%)는 뻗기+끝 유지0.40초에만 있다. 회수/중단/완료 시0. 기력 감속으로 동작이 느려져도 실제 시간0.70초를 넘겨 유지되지 않는다. 계속 누른다고 보호가 연장되지 않는다.
- 피해 계산은 기존 흘림 보호와 같은 단계: 칼날 상처 심각도, 둔타 피해 에너지에 곱한다. 칼날의 원래 충격 에너지, 관통 판단, 강체 충돌, 무기끼리 튕김 힘은 직접 증폭/감소시키지 않는다. 따라서 칼날 충격의 휘청임·통증·옷/갑옷 마모까지45% 줄어드는 것은 아니다.
- 기력은 일반 찌르기 한 번(이번 레이피어5.8041). 동작 중 받는 칼 접촉은 그 비용에 포함한다. 기존 걷기·클린치 비용은 그대로다. 기력 비용으로 탈진하면 시작하지 않는다.
- 시작 즉시 HUD의 막아찌르기 표시/동작/짧은 바람 소리·지원 기기의 진동으로 알린다. **실제 칼 접촉이 있을 때만** 이전에 가져온 우화 흘림의 마찰음·불꽃·멈칫을 한 번 사용한다. 버튼만 눌렀는데 칼을 막았다고 가짜 불꽃을 만들지는 않는다.

## 작은 비교

손길 선별은 예비12회+5변형 각4회(20회). 최초 느린 짧은안, 가슴 우선, 추적20cm, 더 빠른 뻗기, 더 긴 뻗기도 보존했다. 아래팔 우선·42cm/0.28초·기존 찌르기 몸통안(path2)을 선택했다. 실제 상처를 더 만들 수 있었지만 첫4조건만으로 범용 우위를 주장하지 않는다.

그 뒤 새4시드×접근 후 입력/일정 간격 입력2대본×4안=32회. 인간 입력을 모사한 대본과 브론 AI의 물리 전투이며 인간 플레이 자체는 아니다. 고유 후보 실행64회에 계측 위치를 고친32회 재생을 추가했다(총96회 실행, 재생을 독립 표본으로 세지 않음). 모든 원자료를 `raw.tar.gz`에 보존했다. 처음 입력 직전 상태 해시8조건이 네 안에서 모두 같았다(`analysis.json`).

| 각8조건 | 발동 | 동작 중 실제 피해를 준 동작 | 최대30초 패배 |
|---|---:|---:|---:|
| 이전 접촉형+스텝 |28|5|7|
| 입력형·감소 없음 |60|21|7|
| 입력형·30% |48|18|8|
| 입력형·45% |55|20|7|

45%는 발동55회 중20회(36.4%)에서 동작 중 실제 상처/사지 기능/의식 피해가 있었다. **사용자 목표인 높은 명중 확률과 유리한 피해 교환을 완성했다고 볼 수 없다.** 미세한 상처도 포함하고, 한 번에 여러 접촉이 있어도 동작은 한 번만 센다. 상대에게 주는 추가 수동 반격은 대본에 없었다.

발동당 첫1초의 사지 피해 평균: 이전은 받은.1020/준.0119,45%는 받은.0397/준.0364. 첫5초는 이전 받은.3789/준.0119,45% 받은.4159/준.1064. 즉, **5초에는 피격 증가도 있지만 주는 피해가 더 증가하여 같은 항목의 맞교환은 개선되는 방향**이다. 의식·출혈 평균도 함께 `analysis.json`에 적었다. 발동 시각/횟수가 다르고 창이 겹치므로 이 평균을 순수한 인과 효과나 독립55표본의 통계적 확신으로 읽지 않는다.

같은 첫 버튼 입력을 기준으로 한8조건5초는, 이전 사지 받은.2772/준.0417,45% 받은.3449/준.1213이다. 사지 순손해는 약.0139 줄었지만 아주 작은 차이다.30%는 받은.2987/준.0801로 사지 쪽만 보면 더 낫고,45%는 상처 심각도/출혈 쪽이 낫다. 항목별 최적값이 하나로 일치하지 않는다.45% 기본 선택은 **첫1초 체감용 후보**, 확정 최적값이 아니다.30초 승패는 참고만이며 승리는 모두0이다.

검사 당시 버튼은 매번0.8/0.85초 유지하여 모든 피해 감소 창(실제 상한0.70초)을 덮었다. 이후 짧은 탭에서도 시작한0.40초 보호를 끝까지 유지하도록 정리했지만, 이 대본에서 활성 보호 상태는 동일하다. 별도 합성/실제 터치로 짧게 놓은 뒤 보호 유지와 정상 종료를 확인했다.

## 화면과 기능 검사

- 입력 상태 해시를 guard.step 뒤에 기록했던 초기 계측 오류를 발견해 입력 직전으로 옮겼다.32회 재생에서 전체 물리/피해/사건/시계열은 정확히 같았다. 초기 원자료도 confirm-oldhash로 보존했다.
- 24개 상태/비용/피해 적용/취소 검사 통과. 실제 접촉 없이 발동, 한 번만 실행, 중복 타이머 갱신 없음, 탭 후 완료, 비기/쓰러짐/탈진/무기·책 부적합, 칼날과 둔타 감소의 적용 단계 등.
- 브라우저4모드·양역할·터치 누르기/놓기·재시작·일시정지·저장 격리·모바일 넘침 검사 통과. Chromium 터치 에뮬레이션이며 실제 휴대폰 성능·사람의 손맛 확정이 아니다.
- [30% 실제 근접 입력 화면](touch-30/side-thrust.png): 실제 입력과 강체 전투로 상대에게 상처가 난 장면. [45% 실제 입력 화면](touch-45/side-thrust.png): 다음 물리 틱 시작과 탭 해제 후 정해진 동작/보호 완료를 확인한 장면. 이45% 촬영의 초기 onWound 관찰기를 시작 화면의 이전 라운드에 붙여 빈 배열이 나온 오류가 있었다. 이 빈 배열은 무피해의 증거가 아니다. 새 라운드 뒤에 관찰기를 붙인 [검증 촬영](touch-verified/side-thrust.png)에서4.075초 시작,4.200/4.208초 실제 찌르기 상처(0.23571→0.14143,0.13861→0.08317),4.275초 받은 둔타의 피해 에너지25.373→13.955(55% 유지)를 기록했다. 두 찌름 접촉은 한 번의 공격이다. 성공 사진만으로 명중을 보장하지 않는다.
- 촬영은 관찰 시점에서 물리/입자 시간을 정지했고 측면은 카메라만 옮겼다. 몸/손/칼 자세나 충돌을 주입하지 않았다. 일반 플레이는 정지하지 않는다. 최초 멀리서 누른 사진도initial-touch/에 보존했다.
