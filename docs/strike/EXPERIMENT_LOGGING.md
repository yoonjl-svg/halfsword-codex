# 짧고 재사용 가능한 실험일지 계약

실험은 채팅이 없어도 소스·입력·결과·판정을 찾을 수 있어야 한다. 기존에 적절한 기록이 있으면 링크하고 재실행/중복 작성하지 않는다.

한 회차는 **Markdown 요약1개 + JSON 수치/해시 + 원자료**다. 요약은 보통500–900자, 비교가 복잡할 때 표/한계만 추가한다. 원자료는 새 이름으로 저장소 밖에 보존하며 작은 재현 도구는 Git에 둔다. 고정자수 때문에 필요한 실패/출처를 삭제하지 않는다.

1. **게임 목적/질문:** 플레이에서 무엇이 달라져야 하는가, 사용자 승인 범위.
2. **소스/환경:** 완전commit SHA, dirty 여부 또는 변경 파일SHA, 엔진·lockfile·도구SHA. 배치 중 소스 고정. 연구 엔진과 게임 npm 엔진 구분.
3. **설정/실행:** 무기·seed·보정·후보·입력/시간/분기 경계, 복사 가능한CLI·worktree SHA·필수 reference. 당시 argv와 protocol에서 재구성한 명령 구분.
4. **원자료:** 실제 현재 상대경로/보존root 매핑, bytes·SHA-256, source/입력/관찰 trace, 필요한 외부 자료의 존재/접근 범위. 경로 이름만으로 수령/검증 선언하지 않음.
5. **결과:** 기준→후보의 핵심2–4지표, 실행/고유조건/반복·관찰off의 분모, 실제개입과 목적 효과. 새 계산 정정은 원자료를 보존하고 파생본으로 기록.
6. **실패/한계:** 실패한 실행·첫 반례·측정범위. 실측/해석/사용자체감/문헌을 구분. 동등성이 깨지는 입력·접촉/상처 뒤 인과 주장 제한.
7. **판정/적용:** 기각·연구보존·선택형·일반 적용을 구분. 공개commit/웹/남은검증·승인, 이식할 최소단위·의존성·충돌파일·되돌리는방법.
8. **다음:** 작은 다음 행동1개와 시간한도. 실행 wall time와 전체 설계/감사 시간을 구분. 같은 실패 가설을 무조건 재실행하지 않음.

[색인](EXPERIMENT_INDEX.md)에 회차 링크·판정·소스만 추가한다. ACTIVE_PLAN에는 현재 다음 행동과 완료만, 일일 교환에는3–5개 주요 결정과 원보고 링크만 쓴다. 모든 단계에 raw/table를 다시 복사하지 않는다. 공용6회귀/모바일/Actions는 배포 영수증을 참조한다.

닫기 전에 보고서에서 소스·CLI·원자료SHA·판정으로 이동할 수 있는지 점검한다. 외부 raw/엔진이 필요한 경우 확인된 위치·해시와 접근 제한을 명시하고 누구나 현재checkout만으로 완전 재현 가능하다고 주장하지 않는다. 예전 실패자료는 재적용 권고가 아니다.
