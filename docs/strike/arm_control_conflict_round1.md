# 팔꿈치·양손 제어 경로 분리 1차

2026-10-03 KST. 기준 `7fba1c2e838ce1d92ac3ec12f8105c73ecc16da1`. 사용자의 “2번 계속 이어가” 지시에 따라 [연속 목표 2차](elbow_continuity_round2.md)의 첫 실패를 조사했다. **실제 폼멜 추종 후보를 구현했으나 기각했다. 일반 게임 변경·배포·사용자 수락은 없다.** 수치와 소스 해시는 [실행 자료](arm_control_conflict_round1.json)가 기준이다.

## 범위와 재현

실제 Fighter/Rapier를 기존 headless harness에서 실행했다. zweihander, 보정0, paired 그립, legacy 팔/절삭, seed7, 준비3초, 사선 입력 `[-.42,.25]→[.42,-.30]` .55초, 끝점 유지1.2초. 120Hz 기록이다. **17회 실행이지만 외부 베기 입력은 한 가지**이며 무기/방향을 넓힌 회귀나 플레이 검증이 아니다. 실행 wall time 합계12.252초는 설계·구현·감사 시간과 다르다.

```sh
node tools/sim/experiments/arm_control_conflict_probe.mjs --level=0 --out=/tmp/arm-conflict-early-new.json
node tools/sim/experiments/elbow_offhand_follow_probe.mjs --level=0 --weapons=zweihander --directions=cross --endings=target_hold --out=/tmp/offhand-follow-new.json
node tools/sim/experiments/arm_control_conflict_probe.mjs --level=0 --base=coupled --start=1 --modes=intact,noWrist,noGrip,noPrimary --out=/tmp/arm-conflict-late-new.json
```

준비 native/controller·외부 입력 일치, 설치 시 native 불변, 각 실행 중 소스 동결을 확인했다. early/follow의 original-forwarding observer는 원래 trace와 일치했다. early baseline/observe/intact는 앞 coherent 자료의 baseline/observe/coherent와도 trace가 같다. 후기 분기에는 별도 observer 쌍이 없으며 앞 관찰 검증을 재사용한다.

## 1. 처음 나빠지는 구간

기존 원자료 재분석에서 coherent의 검 방향 오차가 기준보다 .01rad 이상 큰 상태로 세 프레임 지속되는 첫 시각은 .091667초였다. 이때 실제 목표 검 축의 차이는 약6.9e-6rad였지만 보조 손 목표 변경은 .03724m였다. 두 팔 도달 범위 투영이 처음 개입하는 .375초보다 앞선다.

새 계측은 명시적 토크/점 힘을 실제 주손 축으로 옮긴다.

`τgrip = τCOM + (COM − grip) × F`

힘·토크 impulse를 DT로 나누며 주손은 실제 native anchor `(.13,0,0)`를 쓴다. ledger의 torqueCOMImpulse에는 점 힘의 COM 모멘트가 이미 들어 있으므로 COM→grip 이동만 한 번 더 한다. .075–.15초의 두 모멘트 cosine은 기준 **+.7046~+.9975**, coherent **−.99997~−.89794**였다. **반대 방향 모멘트는 제동에서도 생기므로 그 자체가 결함·낭비·실패 원인이라는 뜻은 아니다.**

.075초 이후 손목·그립·주어깨 경로의 명시적 작용/반작용을 각각 통째로 제거했다. .075초까지 native snapshot과 선택된 관절 목표/이력/입력의 prefix가 일치하고 첫 제거는 step9, 첫 다른 결과는 .083333초다. 모든 숨은 JS 필드까지 동일하다는 검사는 아니다. noPrimary에서도 native 팔꿈치가 남고, noGrip에서도 보조 손 IK/그립 판정이 남는다.

| coherent 기반 | 입력 뒤 축 이동 rad | 끝 방향 오차 rad | 끝 검 운동에너지 J |
|---|---:|---:|---:|
| 그대로 | 1.261209 | .016397 | .051292 |
| 손목 토크쌍 제거 | 1.747712 | .440588 | .986491 |
| 그립 힘쌍 제거 | .888175 | .021042 | .463062 |
| 주어깨 토크쌍 제거 | 2.945088 | .360413 | 4.895494 |

그립 제거는 일부 이동만 줄이고 손잡이가 벌어진다(.7초 gap .062→.226m). 힘 제거는 해결 후보로 연결하지 않는다.

## 2. 실제 칼자루를 따라가는 후보

`offhand_follow_candidate.mjs`는 보조 손 IK 목표만 `sword.translation + sword.rotation·(0,gripAlong,0)`으로 바꾼다. 기존의 ‘현재 검자루 원점(sword.translation)+희망 검 방향’이 아닌 실제 폼멜이다. 주팔/손목 목표 계산식, 물리 그립 힘쌍의 식·작용점 규칙·계수, 근력·감쇠·native 관절을 직접 바꾸지 않는다. 몸의 반응이 달라진 이후의 실제 목표·힘·일 수치는 달라진다. 원래 팔/연속 팔/양손 도달 팔 각각과 비교했다.

| 팔 목표 / 보조 손 | 베기 최대 방향 오차 rad | 입력 뒤 축 이동 rad | 끝 검 K J |
|---|---:|---:|---:|
| 원래 / 원래 | .204560 | .620039 | .000379 |
| 원래 / 실제 폼멜 | .253378 | .661364 | .000296 |
| 연속 / 원래 | .206584 | .769079 | .000580 |
| 연속 / 실제 폼멜 | .273707 | .813326 | .000594 |
| 양손 도달 / 원래 | .206584 | 1.022241 | .824882 |
| 양손 도달 / 실제 폼멜 | .273707 | 1.120702 | .591231 |

세 쌍 모두 베기 추종과 입력 뒤 축 이동이 나빠졌다. 마지막 한 점의 에너지/손 오차 개선만으로 채택하지 않는다. **작은 반례에서 기각하여 넓은 무기·입력 행렬과 모바일 검증은 실행하지 않았다.** 다음 단계에서 같은 목표 위치 가설의 gain/반경 스윕을 반복하지 않는다.

## 3. 멈춘 뒤의 양손 도달 후보

1초까지 같은 prefix에서 경로를 각각 제거했다. intact의1–1.75초 명시적 signed midpoint work는 주어깨 **+11.513J**, 손목 **−5.752J**, 그립 **+3.378J**, 팔꿈치 중력 보상 **−2.052J**다. native 모터·접촉·감쇠 work는 포함하지 않는다. 이 구간을 순수한 관성 잔류라고 부를 수는 없지만, 양의 일 자체가 불필요하다는 뜻도 아니다.

| 1초 이후 | 입력 뒤 축 이동 rad | 끝 방향 오차 rad | 끝 검 K J |
|---|---:|---:|---:|
| 그대로 | 1.022241 | .038087 | .824882 |
| 손목 토크쌍 제거 | 1.436957 | .418423 | .135250 |
| 그립 힘쌍 제거 | 1.043500 | .055989 | .861250 |
| 주어깨 토크쌍 제거 | 1.790747 | .611763 | 4.313887 |

세 제거 모두 종료 이동/방향이 나빠졌다. 특히 어깨가 양의 일을 한다는 이유로 그 출력을 끄면 .825→4.314J로 커진다. 명시적 signed work만으로 한 관절을 원인이라고 단정해서는 안 된다.

## 판정과 다음 실행

정적인 목표 정렬과 한 힘 경로 제거는 이번 실패를 해결하지 못했다. 기존 근력·목표를 약하게 만들거나 반대 방향 힘을 일괄 지우는 일반 변경은 하지 않는다. 앞서 준비한 `targetCorrection=none|weak` 비교와 팔꿈치 실패 후보도 결합하지 않는다.

다음은 **.075–.15초 실제 결합 상태에서 관절 목표→native 반응**을 분리한다. 어깨/팔꿈치의 목표 자세 항과 목표 각속도 항을 별도로 관측하고, 같은 prefix 뒤 한 항만 바꾸어 검 축·양손 gap·기계적 일/반작용을 함께 잰다. 이는 아직 수행하지 않은 다음 연구이며 새 해법의 성공을 전제하지 않는다. 측정 예산을 통과한 제어 분담 후보만 하강/상승/사선·한손/양손·놓기/재입력으로 확장한다.

독립 읽기 감사에서 모멘트 기준점, impulse 변환, 기존 trace 재현, prefix 범위와 제거 가설의 한계를 확인했다. raw 세 파일은 `/workspace/halfsword-hybrid-evidence/`에 보존했다. Git 복구 bundle은 도구·요약·기록을 보존하며 외부 raw 전체나 환경 소실 보호를 뜻하지 않는다. GitHub 인증은 지원 답변 대기 상태를 유지했고 이번 회차에 반복 재인증/상대 자료 조회는 하지 않았다.
