# 실제 팔 피격 후 중단·재입력과 다시 서기 — 1차

2026-10-03. **상처 API 대조에서 실제 칼 접촉 대조로 진행했다.** 두 세이버 피격을 같은 물리·제어 상태에서 재생해 기존/연속 날 토크/팔 최종 한도/결합을 비교하고, 회복 후 서기까지 이어 검사했다. 결합은 한 장면의 순간 회전을 줄였지만 추종 오차가 후퇴했고, 발 마찰 기록 수정도 실제 피격 회복에서는 혼합 결과였다. 새 일반판 승격·공개 배포는 없다. 중장기2단계 제어 검증과1단계 부상 기립을 연결한 결과이며 전신 힘 전달 완료가 아니다.

## 실제 접촉과 비교 경계

도구 `arm_hit_reinput_probe.mjs`는 기존 newRound/Fighter/Combat/Rapier를 실행한다. 보정0·autoGuard false, paired grip, 기존 팔/절삭/legacy 지지·받침 .3·반사1, 세이버 또는 양손검 대 보통 AI 롱소드, 시작1.85m·벽 없음이다. 신체 위치/속도·상처·건강을 주입하지 않는다. 적 AI는 계속 반응한다. 종전 절대 패드 경로 대신 손 변화량을 현재 handOffset에 누적한다. 기존 탭 요청2.2초 등도 유지한다.

첫 실제 Combat 상처 콜백에서 플레이어 주팔 farmS/uarmS 기능이 감소하면 사건을 기록한다. onWound는 applyWound 뒤지만 전체 충돌 처리가 끝나기 전이다. 따라서 **같은 tick의 가슴 등 다른 상처와 절삭/반발 처리가 모두 끝난 다음 물리 경계**에서 분기한다. 전체 native snapshot, 선택 controller/event trace, 입력 prefix의 동일성을 검사한다. 그 뒤 놓기 .75초 → 사선 변화량(+.35,+.35)m을 .45초 동안 입력 → 손을 댄 채 정지 .8초를 진행한다. 이동 스틱0·새 탭 없음이며 기존 찌르기 상태는 인위적으로 취소하지 않는다.

세이버 두 장면의4방식 모두 첫 피격/분기까지 동일하며, 이후2초 외부 요청과 관찰 길이도 같다. seed7은2초 동안 새 strike/clash 콜백이 없었다. 기존 접촉의 지속·저항까지 없다는 뜻은 아니다. seed19는 분기 .05초 뒤 새 칼 경합이 생겨, 그 뒤는 **반응하는 상대와 다른 접촉 결과를 포함한 회귀 비교**다. 재접촉 전 공통 창은6step뿐이며 이를 긴 인과 검증으로 부풀리지 않는다.

## 팔 제어 2×2: 한 지표의 개선으로 승격하지 않음

아래는 피격 직후2초, 살아서 무기를 든240step이다. 기존 finalCap(`armTorqueModel=sharedCap`)은 어깨/손목의 덧붙은 비틀림도 같은 최종 벡터 한도 안에 넣는다. native 팔꿈치·빈팔·척추·접촉까지 하나의 인체 근력 예산으로 묶는 것은 아니다. 연속 날 토크는 기존 planePotential이다. 옵션 전환은 인과 분리 연구이며 부상 순간 옵션을 바꾸는 제품 설계가 아니다.

|---|---:|---:|---:|---:|
| seed7 기존 | 30.117 | 7.085 | .1535 | .6645 |
| seed7 연속 날 | 31.660 | 7.217 | .1342 | .6481 |
| seed7 최종 한도 | 30.053 | 7.012 | .1552 | .6852 |

| seed19 기존 | 40.394 | 8.406 | .3839 | .3913 |

seed7 결합은 peak 약42% 감소지만 방향 오차와 손 추종이 후퇴한다. 연속 날 단독도 기존보다 놓기 peak30.117→31.660rad/s가 커졌다. seed19의 비교창 뒤 새 상처는 기존의 정강이 상처 등 서로 달라, 적게 다친 결과를 동일 피격 대응의 우수성으로 해석하지 않는다. **결합을 새 모바일 권장값으로 올리지 않는다.** 기존 선택형 후보의 한계 자료를 추가한 것이다.

기존 최종 토크/선행 cap 비율은 seed7 손목1.00379·어깨1.05505, seed19 손목1.00271·어깨1.04179까지였다. finalCap은 부동소수 오차 범위에서1 이하였다. 한도 충족 자체는 제어 품질의 충분조건이 아니다. 명시적 어깨·손목 토크와 실제 반작용 수신체의 순간 power/합을 기록했으나 native 관절·접촉·발 지지의 전체 일은 측정하지 않았다.

모든2초 비교는 비유한 값/사망/낙검 없고, valid native 관절·그립 최대 틈2.503mm 이하였다. 그런데 몸은 피격 다음 step에 getup으로 넘어가고, 실제 손은 목표에서 최대 .66m 이상 벗어난다. **작은 관절 틈은 입력 목표 추종이나 자연스러운 몸 동작의 증거가 아니다.** 코드의 balance 감소→knockDown(false)→getup은 낮은 근육 목표와 무릎 자세를 함께 시작한다. 이를 실제로 다리가 버티지 못한 결과나 잘못된 동작으로 단정하기 전에 목표·부상 용량·접촉을 분리해야 한다.

## 실제 재기립: 마찰 기록 수정은 혼합 결과

같은 두 사건의 관찰을6초로 늘리고, 플레이어가 처음 다시 서는 `Gait.enter`에서만 기존 runtime helper로 Nf를 비우는 후보를 대조했다. 적의 옵션은 유지한다. 첫 실제 entry 직전 native/controller/input/time은 모두 일치하며, reset 자체는 Nf 외 필드·native 상태를 바꾸지 않았다. 후속 entry는 이미 달라진 전투 결과이므로 동일 준비라고 부르지 않는다.

첫 entry는 seed7 5.225초, seed19 6.258333초다. 이전 서기의 뒤/앞발 Nf는 각각522.104/582.619N이었다. 후보는0으로 비우고 현재 접촉 읽기/마찰 식은 그대로 사용한다. 다음 새 strike/clash까지 공통 창은 각각 .533333/.975초다.

| 같은 첫 entry 뒤 새 접촉 전 | 최대 접점 수평속도 기존→수정 m/s | 최대 valid gap mm | 플레이어 몸+검 K 최대 J |
|---|---:|---:|---:|
| seed7,64step | .86693→.86801 | .28234→.26024 | 3.59172→3.54982 |
| seed19,117step | 1.14600→1.29675 | 1.83407→2.37147 | 18.63016→14.20299 |

seed19는 K가 줄어도 미끄럼과 gap이 증가했다. 과거 같은 누움의 개선을 모든 실제 부상 회복에 일반화할 수 없다. 기존 선택형 마찰 기록 수정은 유지하되 기립 해결/일반 승격의 근거로 확대하지 않는다.6초 전체에서는 seed7 기존이 추가 팔 피격 뒤5.783333초에 검을 놓쳤고 후보는 보유했지만, 서로 다른 후속 상처/전투라 낙검 방지 성공으로 세지 않는다. 무기 방향·손 추종 지표는 낙검 뒤 제외하며, 발 지지/실제 몸·검 K의 관찰 범위를 별도로 둔다.

접점 속도는 native foot–fixed-body manifold의 solver 점에서 읽었다. 거리≤.01m이고 manifold raw normal impulse 합>1e-6Ns인 점을 선별한다. 각 점의 양의 지지 하중·전체 step 힘·COP를 증명하지 않는다. 엔진 마지막 substep의 접촉 충격량이고 지면 고정체와의 상대 수평속도다.

## 다음 수정 구간

실제 팔 IK 도달 한도는 `.3+.27−.005=.565m`다. 같은 피격 뒤 첫2초 동안 요청 도달거리는 seed7 최대 .62225m(240step 중146초과), seed19 .57559m(10초과)였다. 초과 약5.7cm만으로 실제 손 오차66cm 전체를 설명할 수 없다. 앞선 도달 범위 투영 실패를 반복하거나 목표 오차 표시만 줄이지 않는다.

다음60–90분은 **seed7의 추가 접촉 없는 피격2.725→4.725초**에서 실제 상완/전완 자세·팔꿈치 native 반응, getup의 근육 감소, 입력 목표/목표속도 전환을 시간순으로 분리한다. 현재 관절 수를 늘리거나 gain을 올리기 전에, 손을 놓고 다시 움직일 때 두 분절이 왜 목표에서 뒤처지는지 특정한다. 후보는 최대1개를 격리해 같은 건강/부상·중단/재입력 대조로 검증한다. 발 마찰 기록의 혼합 결과와 몸통→팔→검 전달·지면 반력/제동의 전체 목표는 계속 미완료다.

## 실행·소스·검증 범위

[기계 판독 결과](arm_hit_reinput_round1.json)에5개 원자료의 SHA256·소스 archive·명령·옵션·모든 비교를 보존했다. 선별4 + 팔8조건/관찰4 + 회복4조건/관찰2 + 도달거리 metadata 정정 재실행3 = **25회**. 실제 실행 벽시계 합59.279초이며 개발시간/토큰비용/독립 표본 수가 아니다.

- 도구 `3e93fc8` → 회복 계측 `cd4b1fe` → 실제 ARM geometry 참조 `ee39290`. 게임 src/일반 기본값/메뉴/공개 build의 새 반영 SHA는 없다.
- 최초 Node의 자식 git 호출은 EPERM으로 **물리 실행 전** 중단되어 파일 읽기 방식으로 바꿨다. 이 실패는25회 물리 실행에 포함하지 않는다.
- 회복 초기 계측의 IK 한도 표시 .595m는 잘못된 상수였다. 실제 config .565m로 정정해 기존 회복을 재실행했고 native/controller/input 전체 hash가 이전과 동일했다. 초기3회는 검증용 반복이며 올바른 한도 기준 최종 집계를 사용한다.
- Source/engine hash 안정성과 각 archive 내용 일치를 확인했다. 네 제어법 clone↔원래 runtime 전체 hash 비교는 **seed7의4회**다. 회복 각 dataset의 observer1회도 seed7이다. seed19는 실제 계측 실행이며 별도 observer exact 검증 범위를 주장하지 않는다.
- 독립 검토는 원본 callback1회·완전한 afterStep 이후 분기·입력90/54/96tick 계약을 확인했고, observer의 seed 범위와 전체 입력/길이 별도 판정 필요를 지적했다. 최종 요약기는 입력/길이 필드도 실제 확인한다.
- 사망 즉시 중단하고 최대18초 동안 주팔 사건을 찾는다.120Hz 물리시계이며 브라우저 hit-stop/느린 시간/가변 렌더링·사람의 자연스러움 평가는 미포함이다.

