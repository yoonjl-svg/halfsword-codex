# 실제 피격 후 팔 활성 분리 · 한손 선택형 1차

2026-10-03. **중장기 2단계의 상체 제어 안정화 중 작은 후보 하나를 구현했다. 전신 전달·부상 기립 전체의 완료가 아니다.** 게임 소스 `912e0f6`, 연구 소스 `eae180a` → `1c2c6c9` → `f7053b8` → `f673e16`. 일반 기본값은 유지한다. 새 비교판은 로컬 완성 빌드만 검증했으며 GitHub 전송·공개 반영은 없다.

## 결론과 변경

[직전 실제 피격](arm_hit_reinput_round1.md)의 66cm 손 오차를 분리했다. seed7에서 팔꿈치의 목표 대비 평균 각오차는 .019rad였지만 어깨는 .667rad였다. 팔꿈치가 목표 자체를 따라가지 못하는 문제보다 **회복 자세의 근육 상승 곡선이 주팔까지 제한하면서 생기는 상완 추종 지연**이 이 장면의 유효한 개입 지점이었다. 목표 기하·회전면의 모든 문제가 해결됐다는 결론은 아니다.

기존 회복 목표는 `min(1, .35 + stateTime/kneelTime) × vigor`다. 선택형 후보는 **주팔만 별도 필터**로 나누어 `getup` 동안 목표를 `vigor`로 둔다. 상승4/감소12의 기존 필터와 `dt`, 팔 상처·strength·Hill·기존 gain/반작용을 유지한다. 다른 상태는 기존 목표로 돌아가며 다리·몸통·빈팔은 기존 muscle을 계속 쓴다. 위치/속도를 직접 고치거나 팔 건강을 회복시키지 않는다.

주팔의 허용 활성을 높이는 변경이므로 **같은 근육 일·같은 토크 예산에서 전달 효율이 개선됐다고 말하지 않는다.** 세이버로 검사한 한손 후보만 `?armRecoveryTrial=independent`에 연결했다. 양손무기는 아래 정지 비틀림 반례 때문에 항상 기존 방식이다. `legacy`, 잘못된 값, 쿼리 없는 일반판의 처리와 저장 설정 복귀도 검증했다.

## 실제 피격과 측정 결과

실제 일반 AI의 Combat 충돌을 그대로 사용한다. seed7은 2.716667초 같은 tick에 가슴/주상완을 베이고, 주팔 건강1→.299184·pain2가 된 다음 전체 step 완료 경계2.725초에 분기한다. seed19는 3.141667초 전완 피격, 분기3.15초이며 앞선 머리 충격과 의식 저하도 보존한다. 분기까지 native 전체 snapshot·제어/사건·입력 prefix가 같다.

분기 뒤 손 떼기 .75초 → 실제 누적 입력 +(.35,.35)m/.45초 → 잡고 멈춤 .8초. 검술 보정0, 이동0, 새 찌르기 없음, 상대 AI는 계속 반응한다. 손 오차는 실제 손과 현재 목표의 거리이며 관절이 그 거리만큼 벌어졌다는 뜻이 아니다.

| 실제 장면 / 2초 관찰 | 기존 | 주팔 활성 분리 |
|---|---:|---:|
| seed7 평균 / 최대 손 오차 | .353 / .664m | .157 / .273m |
| seed7 평균 검 방향 오차 | .1535rad | .0603rad |
| seed7 최대 검 각속도 | 30.117rad/s | 29.974rad/s |
| seed19 평균 / 최대 손 오차 | .138 / .391m | .049 / .112m |
| seed19 평균 검 방향 오차 | .3839rad | .2895rad |

**후속 접촉은 같은 사건이 아니다.** seed7 후보가3.566667초 적 허벅지에 새 접촉(손상0)을 만든다. 그 전 공통101step/.841667초의 평균 손 오차도 .226→.156m, 최대 .434→.272m로 줄지만, 같은 창의 검 축 회전 적분은3.949→4.456rad로 증가한다. 추종 개선을 회전량 전부 개선으로 바꾸지 않는다. seed19는 새 접촉까지 .05초뿐이므로 이후2초 수치를 동일 피격의 순수 인과효과로 해석하지 않는다.

몸/발 회귀도 보존한다. seed7의 최대 관절 틈은2.502858→2.502904mm로 거의 같지만, seed19의 접촉점 최대 수평속도는 .319→.701m/s, 골반 최대 상승속도 .368→.682m/s로 늘었다. 후속 접촉이 달라진 조건의 반례이며, 따라서 전체 기립이나 플레이 자연스러움 수락은 아직이다. 지지 수치는 마지막 solver substep의 접촉점 관찰이며 모든 점의 하중·COP를 측정한 것이 아니다.

6초 연장은 상태 전환/낙검 뒤 수치 유한성 검증이다. 기존은5.783333초 낙검하고 후보는 무기를 유지했지만 이후 상처/접촉과 무기를 든 시간 자체가 달라진다. 전체 창 평균이나 낙검 차이를 승률·낙검 방지 효과로 판정하지 않는다.

## 양손 반례와 범위 축소

건강하게 서 있는 대조에서는 연구 후보와 기존의 두 무기 native/controller/input 전체 궤적이 일치했다. 추가 기립 대조는 gap6m, AI update만 끄고 native 몸은 유지한 채3초에 `knockDown(false)`를 호출했다. 상처 대조는 여기에 실제 `applyWound(farmS, severity=.6, energy=76)` 경로를 사용한다. **이는 합성 회복/상처 개입이며 실제 충돌 피격 표본이 아니다.**

| 합성 상처+기립 | 기존 | 주팔만 분리 | 양팔 활성까지 일치 |
|---|---:|---:|---:|
| 세이버 최대 손 오차 | .414m | .121m | 미실행 |
| 양손검 최대 손 오차 | .746m | .584m | .549m |
| 양손검 정지 .8초 검 축 회전 적분 | .488rad | 1.412rad | 1.428rad |

양손 모두240/240frame에서 gripping이었다. 그러므로 빈손이 놓였다거나 양팔 활성 차이만이 원인이라고 단정할 수 없다. 빈팔 native 근육과 grip까지 활성 값을 맞춘 두 번째 구조 검사도 정지 비틀림을 해결하지 못했다. gain 전수 탐색을 중단하고 **양손 적용을 제외**했다. 실제 양손 피격 탐색seed3/11은 주팔 손상을 확보하지 못했다. 이 두 회차를 성공한 부상 회귀로 세지 않는다.

세이버 합성 회복도 최대 gap1.484→1.816mm·최대 상승속도 .742→.755m/s의 작은 후퇴가 있다. 손 추종 하나로 일반 적용하지 않는다.

## 구현과 검증

- `src/arm_recovery_activation.js`: 한손·명시적 independent에만 동작하는 WeakMap 필터. 기존 몸 muscle 갱신 **직전** 호출하여 현재 값에서 시작한다. 모드 해제/양손 전환은 기록 삭제, 재활성화는 현재 muscle에서 시작한다.
- `src/fighter.js`: 주팔 어깨/팔꿈치 근육·손목·팔꿈치 중력 보상만 새 값을 사용한다. 기존 상처/strength 곱셈의 순서까지 보존한다.
- `src/arm_recovery_trial.js`, `src/main.js`, `public/feature-lab.html#arm-recovery-comparison`: 이번 접속의 player만 설정. A/B 모두 세이버·보정0·기존 팔/날/절삭·보통 상대·받침.3/반사1. B만 필터를 켠다. 새 라운드 첫 물리 step 전에 적용하며 저장 선호는 바꾸지 않는다.
- 헬퍼 의미 검사 **7/7**, 독립 읽기 감사 통과. 물리 실행 **58회 = 연구36 + 실제 코드22**. 같은 피격prefix·관찰 on/off·소스 동결 관문 통과. 런타임↔연구/기존 **14행**의 native/input/사건/물리 frame exact를 확인했다. 양손 런타임 B는 기존과 exact다. 후보에는 새 own flag가 있으므로 연구와 전체 controller digest까지 같다고 하지 않는다. 기존 A는 controller도 exact다.
- 완성 빌드 **77모듈** 통과. 모바일 브라우저 **4조건**: A/B 실제 링크·가로/세로 넘침·실제 터치·중단/재입력·첫 step·pause/재시작·새로고침, 잘못된 쿼리/일반 접속의 저장 .7/hard 복귀 확인. 캐릭터 위치·건강·AI를 주입하지 않았다. 이것은 실제 휴대폰의 사용자 체감 평가가 아니다.

연구의 기계적 분기는 피격 이후이고 메뉴 후보는 라운드 생성부터 적용한다. 앞선 getup이 있는 전투에서는 첫 피격 전 궤적도 달라질 수 있다. 처음부터 선택한 후보의 더 넓은 실제 전투·다른 한손무기 수락은 다음 관문이다. 이 한계를 숨겨 공개 플레이를 요청하지 않는다.
