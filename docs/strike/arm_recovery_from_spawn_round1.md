# 한손 회복 활성 · 생성부터 켠 실제 전투 1차

2026-10-03. **10회 실행의 측정 관문은 통과했지만, 한손 회복 후보의 공개 보류를 유지한다.** 생성부터 선택한 후보의 손 추종 개선과 함께 방향 추종·운동 에너지·발 접점 속도의 후퇴를 확인했다. 같은 상태에서 시작한 인과 창에는 다친 주팔의 회복 노출이 없었고, 이후 실제 상처와 접촉도 달라져 부상 회복 효능을 확정할 수 없다. 일반 기본값·공개 CTA·직접 URL은 변경하지 않았다. 실패한 지지·절삭 후보도 재적용하거나 재시험하지 않았다.

기준 소스는 `d351c5384a3514c701d395ce6c625ec261a6df53`다. [앞선 피격 후 활성 분리](arm_recovery_activation_round1.md)의 추가 관문을 검사했으며, 물리 변경을 새로 구현한 회차가 아니다. [재현 집계·소스 해시](arm_recovery_from_spawn_round1.json)에 원자료·창 정의·관찰 불변성·모든 비교 지표를 보존했다.

## 생성부터 선택한 실제 게임 경로

`arm_recovery_from_spawn_probe.mjs`는 원래 `harness_m.newRound`·Fighter·AI·Combat·Rapier를 실행한다. `newRound`의 `onFighter`에서 **플레이어 생성 직후·첫 `G.step` 전에** `armRecoveryModel='independent'`를 설정했다. 상대는 기존 방식이며, 공개 URL 파서는 사용하지 않았다. 연구용 Fighter 변환·controller clone·AI 정지·상처/건강 주입·몸 위치/속도 변경은 없다.

세이버/팔쉬온 × seed7/19 × 기존/후보의 **8행**, 팔쉬온 seed7 두 방식의 선택적 관찰 끔 반복 **2행**이다. 짝과 반복을 독립 성공 표본10개로 세지 않는다. 모두18물리초·2160step 동안 살아서 무기를 유지했으며, 사망·낙검은 없었다. 도구의 종료·공유 창 기능이 실제 사망/낙검 장면까지 검사된 것은 아니다.

설정은 플레이어 보정0·autoGuard false, paired 그립, 기존 팔/날/절삭, legacy 지지·발 기록, 받침.3/반사on/1, 보통 AI 롱소드 상대, 간격1.85m·벽 없음이다. 양손 후보·선택형 날/기립 변경을 결합하지 않았다.

입력은18초 전체에 같은4.4초 주기의 가드→내려베기→놓기→올려베기→가로 준비/베기→잡고 유지→재입력 변화량을 예약했다. 탭 요청은2.2/6.6/11/15.4초, 이동은 처음2초 전진.25 이후 가드 구간.08·나머지0이다. 실제 피격 시점에 입력을 다시 예약하지 않는다. 첫 손 패드는(.02,.52)m이며, 외부 변화량·실제 손 패드·탭 수락은 별도 기록이다.

실행 엔진은 게임에 설치된 **published npm `@dimforge/rapier3d-compat`0.19.3**이다. 별도로 복원·검사한 native API 연구 엔진0.19.2와33fixture 결과는 이10행에 사용하지 않았다.

## 요청 변화량0인 전투 회귀

아래는 첫 추가 활성 이후 양쪽이 살아서 무기를 든 공통 구간에서 `hold/release`에 해당하는 **요청 변화량0** 표본만 집계했다. 세이버193frame·1.608초, 팔쉬온241frame·2.008초다. 상대 AI·후속 충돌·몸 회전과 앞선 찌르기는 계속될 수 있다. 몸과 검이 멈춘 동일 상태의 순수 제동 비교가 아니다.

| 검 최대 K(J) | 5.20→9.46 | 7.25→8.30 |

손 추종은 개선됐으나 세이버는 방향 추종·K·관절 간격·발 접점 속도가 함께 후퇴했다. 팔쉬온은 추종/간격 개선과 발 접점 속도·검 K 증가가 함께 남는다. K는 상태 운동 에너지이며 근육 일이나 같은 접촉의 에너지 전달 효율이 아니다. 후보가 회복 중 주팔의 허용 활성을 높이는 변경이라는 점도 유지한다.

첫 활성 이후의 전체 공통 전투 회귀는 세이버823frame·6.858초, 팔쉬온1094frame·9.117초다. 세이버의 살아서 든 검 peak는40.108→62.153rad/s, 전체 회전 적분31.551→34.074rad로 증가했다. 팔쉬온은 peak40.365→37.849rad/s·회전 적분36.356→32.190rad로 줄었다. 접촉 분기 이후 수치의 혼합 결과를 동일 피격의 우수성·승률·낙검 방지 효과로 바꾸지 않는다.

발 수치는 fixed-ground manifold의 마지막 solver substep 접점 속도다. 위 표를 하중을 받는 발의 미끄럼이라고 부르지 않는다. 보조 집계로 manifold 정상 impulse 합이 `1e-6Ns`보다 크고 solver 거리`.01m` 이하인 점만 고르면, 요청0 구간 최대 속도는 세이버.3055→.6619m/s·선택 점 없는 frame0→4, 팔쉬온.5615→.6216m/s였다. 이것도 개별 점의 하중이나 COP를 증명하지 않는다. 두 숫자는 사후 관찰 필터이며 게임에 넣은 숨은 한도가 아니다.

검 전체 회전 적분은 `Σ|ω|DT`이며 `totalRotationIntegralRad`로 저장한다. 검 축 방향 이동거리나 전완에 대한 상대 손목 회전량이 아니다. 별도 twist 적분은 세계 각속도를 현재 검 축에 투영한 절댓값이다. 손 오차는 현재 runtime 손 목표, 자체 검 오차는 필터된 목표, 외부 검 오차는 고정 입력의 원래 매핑이므로 서로 같은 목표의 오차로 취급하지 않는다.

120Hz 물리시계의 실제 게임 코드 실행이며 렌더링·브라우저 hit-stop/slowMo/가변rAF·실물 폰 조작·사용자 자연스러움은 이 회차에서 검사하지 않았다. 본 회차의 공개 보류는 이미 전달한 사운드와 다른 네 선택형의 전달 완료를 취소하는 판정이 아니다.
