# 저체력 숨소리 음량 조정

2026-10-01 사용자 요청인 10~15% 감소의 중간값을 적용했다. 기준 HEAD는 `1eaa1e25497a12f121fcb054f5921cd100867f07`이며, 이 변경은 `Sound.breath()`의 이벤트 gain에만 `0.875`를 곱한다. 위험도 0~1에서 기존 `0.25~0.35`가 `0.21875~0.30625`가 된다. 재생 빈도·속도, master/bus gain, 타격·신음·죽음·부활 소리는 변경하지 않았다. 이는 진폭 gain의 12.5% 감소이며 체감 음량의 비율을 확정한 것은 아니다.

## 실제 발생 조건과 경로

- `main.js:426`에서 플레이어용 `BodySounds(..., true)`를 만들고 `main.js:1426`에서 프레임마다 갱신한다.
- `sound.js:3519`의 조건은 살아 있는 플레이어의 `blood < VITALS.weakBlood(0.8)`이고, `bleed > 0.002` 또는 `blood < 0.6`이다. 위험도는 혈액량으로 계산한다. `vigor` 자체가 직접 트리거는 아니다.
- `sound.js:2424`의 숨 전용 경로는 `breath/breath1` 녹음을 flesh bus의 이벤트로 재생한다. 녹음이 없으면 바로 반환하며 합성 fallback은 없다. 부활의 숨 들이켬은 별도 경로이므로 이번 조정에 포함하지 않았다.

## 브라우저 검증

최신 소스를 Vite 임시 서버 `127.0.0.1:4176`에서 열어 실제 Chromium 844×390 터치로 싸움을 시작하고 AudioContext의 `running`을 확인했다. 무기는 양쪽 롱소드, 상대는 default이며 이벤트를 분리하기 위해 AI update만 비활성화했다. 이벤트 함수를 관찰하는 래퍼는 원래 함수를 그대로 실행하고 생성된 실제 GainNode 값을 읽었다.

- 위험도 0/1의 GainNode 값은 각각 `0.21875` / `0.3062500059604645`, 각 이벤트의 BufferSource는 1개였다. 녹음은 101,368 프레임으로 로드됐다.
- 실제 플레이어 혈액량을 `0.55`, 출혈을 `0`으로 설정한 뒤 main의 BodySounds 경로가 위험도 `0.7142857142857142`의 숨을 자동 호출했고 GainNode 값은 `0.28125`였다.
- 녹음이 없는 경우 이벤트를 생성하지 않았고 master gain은 검사 전후 `0.800000011920929`로 같았다. JavaScript/console 오류는 없었다.
- 첫 검사에서는 일반 URL의 무기 뽑기(draw) 상태라 시뮬레이션이 진행되지 않았다. 검사 URL에 무기를 명시하고 fight 상태를 기다린 후 통과했다. 공개 배포 검증과 실제 휴대폰 체감 청취는 아직 수행하지 않았다.

임시 검사: 저장소 밖 작업공간의 도구 `halfsword-review-tools/breath-gain-browser.mjs`. 결과: `halfsword-hybrid-evidence/breath-gain-browser.json`. 물리 벤치마크나 별도 구현 미러 단위 테스트는 추가하지 않았다.
