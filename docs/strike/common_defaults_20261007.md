# 기능에 따른 일반판 공통 적용

사용자는 “무기 이름으로 제한하기보다 해당 기능을 사용하는 무기에 공통 적용하고 실제 예외만 제외”하도록 승인했다. 기준 커밋은 `c6f3ffc7526e3efc4178eaf2fbea933f244a2026`이다. 앞선 회복/타격/재베기 승격의 이름 목록을 없애며 물리식·힘·피해·시간 상수는 변경하지 않는다.

| 기능 | 일반 플레이어의 적용 조건 | 현재 공개 무기 수 |
|---|---|---:|
| 회복 B | 공개 일반 무기: 같은 다리의 재기립 기록 정리 | 15 |
| 재베기 B | 총이 아닌 근접 무기: 같은 손목 방향 제어 | 14 |
| 타격 B | 총이 아니고 edged인 무기: 실제 관통·절삭 저항 경로 | 11 |

새 무기가 이 조건을 만족하면 이름 목록 추가 없이 적용된다. 총의 다리는 회복 기능을 쓰지만 총구 조준에는 재베기 보정을 추가하지 않는다. 둔기에도 기존 손목 방향 제어가 있으므로 재베기 처리를 공유한다. 날 없는 무기의 둔타·총알에 절삭 저항을 만들어 넣지는 않는다. 별도 연구 진입·trialOnly·적 제어·저장 선호는 기존 조건을 유지한다. 실제 근력 비활성/낙검 이력 초기화, edgeIntent/transported 우회도 그대로다.

검술 보정 v2 자체의 12종 범위는 별도 기능이다. 모노호시자오·라이트세이버에 새 공통 기능이 켜져도 보류된 v2가 켜지는 것은 아니다. 재베기 개입 후 실제 능동 절삭 위력과 잔여 전투 회전은 이전 사용자 지시대로 유보한다. 이번의 짧은 연결 회귀를 그 연구의 통과로 바꾸지 않는다.

검증은 이름을 바꿔도 결과가 같고 새 능력 조합에 맞춰 설치되는지, 이전 A/B를 침범하지 않는지, 대표 계열의 실제 입력/유한성/파지와 모바일 공개 실행을 확인한다. 전 무기 모든 상황의 자연스러움·공격 위력 보장은 아니다. 실제 실행 수·명령·소스/원자료 해시·미노출·공개 상태는 [영수증](common_defaults_release.json)을 따른다. 완료한 이전 실험을 다시 분모에 합산하지 않는다.

팔다리 절단은 이 세 기능과 별개다. 구현돼 있지만 일반판에서는 꺼져 있는 상태를 [별도 조사](limb_general_status_20261007.md)로 정정한다. 이번에는 절단 스위치·상처 문턱·절단 뒤 관절 제어를 변경하지 않는다.

## 실행 결과와 한계

능력 조합·이름 변경 동등성·기존 연구 격리231계약과 기존 진입3검사를 통과했다.


실제 게임은 세이버·레이피어·츠바이핸더·고무닭·모노호시자오·라이트세이버·권총7종의 이전/공통 정책14행과 세이버의 정상 AI 접근2행, 총16실행·7,950step(물리 계산16.54초)을 확인했다. 같은 생성과 입력, 수치 유한성·생존·파지·무장·서기 계약을 통과했다. 권총은 사격1회 포함 전체 native 궤적이 같았다. 직접 Gait.enter 하중기록 주입16검사는 기능 계약이며 자연 피격 후 회복의 효능 실험이 아니다.

추가 접근은240step 잠금 뒤 정상 이동, 기준 간격2.8m 도달 tick423에 같은444step 입력을 썼다. 실제 상대 접촉은 있었지만 중심선 반작용 호출은 양쪽0이었다. 이 한손 장면으로 새 중심선 실개입·효과·상대 적용 격리를 통과했다고 쓰지 않는다. 기존 공통식 검증은 재사용하며 거리/seed 탐색은 하지 않는다.

**잔여 관측:** 세이버 접촉행의 검 전체 각속도 최고치는40.76→91.92rad/s, 목표오차 최대는0.766→0.950rad였다. 피격 callback 이전부터 native 경계 표본이 달랐지만 최고치의tick/phase와 AI 분기시각은 미기록이므로 원인을 단정하지 않는다. 자유 입력의 전체 최고 각속도는 각 무기에서 증가하지 않았으나 release 끝 한 시점은 세이버2.26→10.57, 모노호시자오3.72→16.79rad/s로 증가했다. 지속 회전량·인간 자연스러움 수락이나 모든 동작 개선의 증거가 아니다. 사용자 유보 항목에 연결하고 추가 회전/능동 절삭 위력 연구는 실행하지 않았다. 후속에는 최고치 시각·입력·접촉 맥락을 먼저 기록해야 한다.

초기14행의 생산 코드가 호출하지 않는 roll 관찰 필드0은 개입 측정으로 사용할 수 없다. 원본과 소스 해시를 보존했고 후속2행 생산기에서 해당 무효 관찰자를 제거했다. 유한성·native·입력·파지 검사는 이 필드에 의존하지 않는다. 한도를 숨기거나 표본을 버리지 않는다.

재현: `node tools/sim/experiments/combat_defaults_functional_20261007.mjs --out=/absolute/fresh/native`, 접촉2행은 같은 명령에 `--contact`를 붙인다. 각 실행 당시 소스와 원자료 SHA는 전달 영수증의 native 기록을 따른다. 브라우저·공개 전달은 별도 판정한다.

## 공개 전달

게임 커밋 `2aab7e5`를 [일반판](https://yoonjl-svg.github.io/halfsword-codex/)에 반영했다. Actions 성공과 공개8파일의 실제 바이트 일치, 폰 크기 실행 계획의 가로·세로 표시를 확인했다.

공개 브라우저 common13행은 기능 계약을 통과했지만 카드 진입의 발소리 `sfx/step/stone2.mp3`에서HTTP503이1회 발생하여 최초 전체 결과는FAIL로 보존했다. 해당 파일을 별도로 읽어HTTP200·로컬과의 정확한 바이트 일치를 확인하고, 게임을 바꾸지 않은 채 카드 진입1행(시작2회·카드2회)만 다시 실행하여 오류0으로 통과했다. 최종 수락은 최초의 영향 없는12행+카드 보완1행이다. 새13행 전수PASS로 바꾸거나503을 필터링하지 않았다. 두 실행의 차이는 도구의 카드 전용 scope 추가뿐이며 src/public/dist는 동일하다.

실제 확인 범위는 일반 카드 선택/재시작, 세이버 전체 터치·반전·찌르기·재시작·복귀, 레이피어/고무닭/권총 입력, v2 보류2종 메뉴와 기존 비교6메뉴다. 실물폰 성능·모든 무기의 전투 효능 검사는 아니다. 실제 소스·오류·보완·원자료 SHA는 [영수증](common_defaults_release.json)을 따른다.
