# 절삭 비교 설정·자세 회귀 2차

2026-10-02. 최신 사용자 평가는 절삭 비교에서 자세·이동이 무너지고 이득보다 손실이 컸다는 부정적 결과다. 앞선 미세 개선의 잠정 평가는 이 최신 평가로 대체한다. 순간 에너지·운동량 검사를 통과했다는 이유로 선택형 후보를 수락하거나 일반 기본값으로 올리지 않는다.

기준 HEAD `7b72c4e3bc4a50fc56786362de6509c9d2270757`. 원자료와 source/engine 해시·명령·관문은 [JSON](cut_posture_round2.json)에 남겼다. 런타임·엔진·기존 도구·빌드·커밋 변경 없음.

## 시험 설정이 달랐는가

공개 기준 `e5d2f081de320e42634526e27a68804baf754993`의 `public/feature-lab.html`을 git object로 읽고 현재 파일과 대조했다. 팔/절삭 링크의 아래 쿼리는 동일하다. 신규 미공개 기립 링크의 존재와 분리한다. 사용자의 실제 브라우저 저장값·실제 선택 버튼·입력 궤적은 확보하지 못했다.

| 비교 링크 | 주인공 / 상대 무기 | 팔 제어 양쪽 | 절삭 | 받침 / 반사 / 세기 |
|---|---|---|---|---|
| 팔 한손 A / B | sabre / longsword | legacy / sharedCap | 둘 다 legacy | .3 / on / 1 |
| 팔 양손 A / B | zweihander / longsword | legacy / sharedCap | 둘 다 legacy | .3 / on / 1 |
| 절삭 A / B | zweihander / longsword | 둘 다 legacy | legacy / budgeted | .3 / on / 1 |

**절삭 A↔B 내부에서 명시된 차이는 `cutTrial`뿐이다.** 그러나 팔 B→절삭 B로 이동하면 팔 후보 sharedCap이 유지되지 않고 legacy로 돌아간다. 팔 한손→절삭으로 이동하면 무기도 달라진다. `armTrial`은 저장 옵션이 아니라 접속 URL 옵션이며 절삭 링크는 이를 지정하지 않았다. 절삭 B를 팔 B와 결합한 시험으로 안내하면 안 된다.

둘 다 `foe=default`로 이전 기본 상대 외형을 쓰지만 AI의 성격은 판마다 무작위다. 난이도와 검술 보정은 링크로 고정하지 않는다. `src/main.js`는 기본 `difficulty=normal`, `skill=.7` 위에 브라우저 `localStorage['gladiator-settings']`를 덮고, 새 판의 플레이어에 `settings.skill`을 설정한다. 메뉴 변경은 저장된다. 보정 끔=0 / 약=.4 / 보통=.7 / 강=1이다. 따라서 같은 브라우저에서 끔으로 바꾸면 다음 비교 링크에도 끔이 이어질 수 있다. 실제 사용자가 어느 값으로 플레이했는지는 단정하지 않는다. 저장된 이동 방식·기울기 반전도 링크에서 초기화하지 않는다.

팔/절삭 모두 `supportProbe=1&assist=.3&catch=on&catchScale=1`, `weapon=...&foeWeapon=longsword&foe=default`다. 양쪽은 paired 그립·legacy 지지, 현재 코드에서도 stanceMemory legacy다. 일반 접속은 무기 카드·무대 상대를 쓸 수 있어 비교 링크와 동일 장면이라는 보장이 없다. 지지 연구 철회판·새 기립 후보를 이 링크의 차이 원인으로 보지 않는다.

## 기존 검사의 한계

[상호작용 1차](arm_cut_interaction_round1.md)의 20행은 순간 절삭 pair 에너지 차감·P/L 보존·관찰/동일 준비·실제 dispatch를 확인했다. 당시 추가 방어선은 baseline 대비 속도×3+10m/s, 골반 높이+.75m, 관절 gap+.1m라는 큰 발사·벌어짐 관찰 문턱이었다. 이 조건의 통과는 몸통 자세, 손 입력 보존, 정상적인 회전·발 이동, 부상 후 제동의 통과가 아니다. 모바일 URL·터치·재시작 검사는 연결을 확인했으며 자연스러움 수락을 대신하지 않는다.

새 2차는 자세와 회전의 반례를 찾는 첫 회귀다. 사용자 장면 자체를 재현했다거나 모든 원인을 확정했다는 뜻은 아니다.

원래 `harness_m.newRound`·Fighter/AI/Combat/Rapier를 실행했다. 공개 절삭 링크와 같은 zweihander→longsword·기본 상대 외형·normal 난이도·벽 켬·paired 그립·legacy 팔/지지·.3/on/1이다. seed7/17 × 플레이어 보정0/.4/.7 × 절삭legacy/budgeted **12행**, 관찰 없는 seed7/보정0의 두 절삭 대조 **2행**, 준비1초+관찰20초다. 플레이어도 원래 AI가 입력을 생성하며 AI2 생성 뒤 보정값을 지정하고 autoGuard를 켰다. 사람의 터치 입력·감정/히트스톱 브라우저 경로를 재현한 것은 아니다. 몸 고정·속도 덮어쓰기·상처 주입·합성 knockdown은 없다.

## 판단과 다음 실험

최신 부정적 플레이 평가는 수락 기준에서 우선한다. budgeted의 순간 장부 수정은 남아 있는 공학적 이득이며 자세·이동·제동의 이득으로 확장하지 않는다. 일반판 승격 없음. 팔 B가 빠지는 링크 구성과 저장 보정값은 비교 해석의 실제 교란 요소지만 사용자 체감의 원인으로 확정하지 않는다.

다음은 실제 첫 절삭 접촉의 동일 상태에서 legacy/budgeted를 짧게 분기하고, AI가 다른 입력을 내기 전 공통점 impulse가 검→그립→손목/몸통에 주는 응답과 손 목표 오차를 분해하는 것이다. 팔 sharedCap 개별·결합도 같은 무기/보정/입력에서 별도 비교한다. 큰 순간 예산 위반이 없어도 목표 이탈·전신 회전·발 이동이 늘면 후보를 다시 설계한다. 전신 제어를 임의로 강하게 하거나 피해 배율을 올려 후퇴를 숨기지 않는다.

```sh
node tools/sim/experiments/cut_posture_round2.mjs --seconds=20 --seeds=7,17 --out=/workspace/halfsword-hybrid-evidence/cut-posture-round2.json
```

기존 결과를 덮어쓰지 않으므로 재실행은 새 `--out` 경로를 사용한다. 원자료의 모든 프레임 물리/controller·입력 해시와 10Hz 자세 sample은 저장소 밖 JSON/JSONL에 보존하고, 저장소 JSON에는 해시·비교·원래 사건·요약을 남겼다.
