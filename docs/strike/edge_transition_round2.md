# 날 평면 전환 2차: 입력 경계 수정과 실제 날 정렬의 한계

2026-10-03 KST. **84회 실제 게임 실행을 마쳤다. C1 입력 연결은 연구 런타임에 구현했으나 일반 채택·공개 연결은 보류한다.** 정지 중 검의 축 회전과 다음 베기의 급회전은 줄었지만 실제 이동 방향에 대한 날 정렬·찌르기 중 비틀림이 남았다. 손 이동까지 포함한 후속 후보도 구현·검사했으며 다른 전환에서 후퇴해 채택하지 않는다. 팔꿈치 협응·전신 힘 전달·부상 회복이 해결됐다는 뜻이 아니다.

## 같은 prefix에서 무엇을 분리했나

기존 no-tap 격리 경로를 재사용했다. 보정0/자동 가드false, paired grip, 기존 팔/절삭, 건강한 세이버·양손검, seed7, 시작 거리6m, 상대 AI·수동 이동0. 실제 게임과 Rapier의 고정120Hz 실행이며 자세·속도를 덮어쓰지 않는다. 3.6초 이전의 전체 native snapshot/제어 상태 해시를 유지한 채 이후 목표 평면·위치항·제동항을 따로 바꿨다.

양손검 3.6–4.4초 peak는 기존5.38, 명령 평면24.18rad/s였다. 명령 평면을 직전 값에 고정하면1.52, 위치항만 없애면.15, 제동항을 없애면128.65rad/s였다. 위치항 제거는 최대 날 목표 오차1.55rad를 허용하므로 해결책이 아니다. 평면 고정도 다음 베기를 제대로 수행한다는 뜻이 아니다. 기존 제동은 필요한 기능이며 일괄 제거하지 않는다.

실제 입력 높이 `y=.1`에서 원래 검 방향 매핑의 기울기가1.1→3.3으로 바뀐다. 문제 구간에서 y가.09891→.10330을 지나자 갱신 비중이.089→.581로 커지고 기억 평면이 한 스텝에 약.499rad(28.6°) 이동했다. 같은 시각 위치 토크는1.47→6.19Nm였다. 이 연결부가 명령 평면 전환을 증폭하는 경로임을 확인했으며 유일한 결함으로 단정하지 않는다.

`τ·ω·dt`는 검에 가한 명시적 twist의 근사 일이다. 이 구간 적분이 음수여도 급회전은 존재했다. 자유 강체 `τ/I` 응답이나 이 근사 일을 실제 결합 solver의 총 일·근력으로 해석하지 않는다.

## 구현: 좁은 구간에서 기울기를 연속으로 연결

`src/edge_intent.js`의 `smoothIntentElevation`과 `Fighter.driveSword`의 `edgeIntentModel='commandedPlaneC1'`를 추가했다(`bc69b22`). 일반 생성자·메뉴·URL에는 연결하지 않았다. 기존 `commandedPlane`도 그대로 보존한다.

`.05<y<.15`에서 `t=(y-.05)/.1`, `elevation=-.055+.11t+.11t²`를 쓴다. 양끝 위치와 기울기를 잇고 구간 밖 목표는 그대로다. 내부 목표 높이각은 원래보다 최대.0275rad(1.58°) 다르다. 입력 손 위치·중력·질량·관성·근력 계수는 변경하지 않는다. 목표가 달라져 실제 토크와 일은 달라진다.

이는 공간적 C1 연결이다. 실행 도중 옵션을 켜는 전환, guard/thrust 혼합, 전체 평면이나 토크의 시간 연속성을 보장하지 않는다. 현재 검증한 런타임 적용은 생성부터다.

## 정지 비용을 포함한 비교

`회전량=Σ|ω검·검축|dt`: 세계 각속도의 검 축 투영 절댓값 적분이다. 전완에 대한 손목 상대 회전이나 최종 자세 차이는 아니다. 정수120Hz tick으로 구간 경계를 나눠 중복 표본을 막았다.

| 무기 / 모드 | 다음 베기3.6–4.4초 peak rad/s | 전체0–6초 peak rad/s | 전체 축 회전량 rad |
|---|---:|---:|---:|
| 세이버 / 기존 | 5.01 | 24.60 | 8.003 |
| 세이버 / 명령 평면 | 19.78 | 19.78 | 4.941 |
| 세이버 / C1 명령 평면 | 11.04 | 18.14 | 4.924 |
| 양손검 / 기존 | 5.38 | 21.61 | 10.473 |
| 양손검 / 명령 평면 | 24.18 | 24.21 | 5.636 |
| 양손검 / C1 명령 평면 | 12.20 | 21.38 | 5.531 |

기존 방식은 직전 정지3–3.6초에 이미 세이버1.656/양손2.510rad를 돌려 놓았다. C1 후보는.081/.145rad다. 따라서 재입력 peak만 비교하면 회전 비용의 시점이 편향된다. 반대로 전체 회전량이 줄었다고 날 정렬을 잘했다고 단정해서도 안 된다. C1의 재입력 회전량은1.475/1.557rad로 기존 명령 평면1.486/1.559와 거의 같다. 여기서의 효과는 회전량 제거보다 급격한 회전의 완화다.

## 실제 이동 방향에 대한 날 정렬: 아직 채택 불가

후보 자신의 목표가 아니라 `n=normalize(blade×v_cached)`와 실제 flat의 각도 `acos(|flat·n|)`를 측정했다. 횡속도.5m/s 초과 표본을 속도로 가중한 평균이며2.5m/s 대조도 JSON에 남겼다. `v_cached`는 기존 hitPointVel의 위치 차분 기록으로 한 스텝 지연이 있다. 순간 native 점 속도·상대 접촉 속도·절삭 에너지 손실을 측정한 것은 아니다. `abs(dot)`이므로 앞날/뒷날은 구별하지 않는다. 모드별 실제 속도와 유효 표본 수가 달라지므로 완전히 같은 운동의 비교도 아니다.

| 무기 | 재입력 기존 오차 rad | C1 명령 평면 | 손 이동 포함 후속 후보 |
|---|---:|---:|---:|
| 세이버 | .0847 | .1988 | .0673 |
| 양손검 | .1042 | .1840 | .0863 |

C1 후보는 급회전을 줄였어도 기존보다 실제 날 정렬이 나쁜 구간이 남는다. 전체0–6초 오차도 세이버.0707→.0829, 양손.0860→.1478rad다.

손 이동을 넣기 전 실제 운동 평면을 기억하는 `motionMemory`도 같은3.6초 prefix에서 검사했다. 양손 재입력 회전량이1.559→1.966rad로 늘어 단순 대체안으로 채택하지 않았다. 외란·기존 제어가 만든 운동도 따라가므로 명령 의도의 보존을 보장하지 않는다.

후속 `pointIntent`(`9a58185`)는 yaw 좌표에서 `p=handLocal+L·u`, `v_cmd=(p-p_prev)/dt`, `n=u×v_cmd`로 손 목표 이동까지 포함한다. `L=hiltLength+.7bladeLength`이며 속도에 L을 두 번 곱하지 않는다. 손 목표가 고정됐을 때 기존 회전식과 같은 기하다. 가슴 병진·몸 yaw의 세계 운동은 빠져 있고 도달 불가능한 목표도 들어갈 수 있다. 실제 물리 속도로 부르지 않는다.

이 후보는 위 표의 재입력 정렬은 좋아졌지만2.2초 사선 준비에서 peak가 세이버27.29/양손32.94rad/s로 커졌다. 전체 회전량5.973/6.870rad, 전체 정렬 오차.0555/.1432rad로 무기별 결과도 달랐다. **한 구간 개선을 근거로 채택하지 않는다.** 임시 연구 클래스에만 남겼다.

## 기존 날 제어에 C1만 적용한 대조

새 평면 기억을 제외하고 기존 날 제어에 입력 경계 수정만 적용한 `legacyC1`도10행으로 분리했다(`6e86ca6`, 임시 연구 클래스). 재입력 peak는 세이버5.01→3.34, 양손5.38→4.51rad/s로 줄었다. 하지만 전체 peak는24.60→25.75/21.61→21.98rad/s, 세이버 전체 회전량8.003→8.210rad로 늘었다. 실제 평면 오차도 세이버.0707→.0735, 양손.0860→.0862rad로 조금 커졌다. 기울기 경계를 잇는 수정 자체도 전 구간 개선을 보장하지 않아 일반판에 단독 반영하지 않는다. 이 대조는 평면 기억과 입력 매핑 수정을 한 효과로 섞지 않기 위해 추가했다.

## 실제 찌르기·접촉·검증 범위

6초 무접촉 찌르기 시험4행+observer1행에서 각 무기는 실제2.2초 탭을1회 수락했다. 접촉/상처0, 관찰 동등성·유한성을 통과했다. 찌르기 활성 중 peak는 세이버32.52→34.00, 양손8.93→32.15rad/s다. C1이 찌르기 비틀림을 해결하지 못했다. 이후 재입력 peak는11.04/12.24로 내려왔지만 찌르기 실패를 덮지 않는다.

실제 AI 교전은 두 무기×seed7/19×기존/C1 8행+observer1행이다. sourceStable·native/controller/상처/입력 관찰 동등성·유한성을 통과했고 양측 유효 관절 최대 틈은3.705mm 미만이었다. 살아서 무기를 든 플레이어 peak는 세이버 seed19에서109.35→111.87rad/s, 양손 seed19에서26.76→32.66rad/s로 늘었다. 후자는 기존2.742물리초에 라운드가 끝나지만 후보는18초여서 동일 사건 비교가 아니다. 접촉·AI·상처·종료 궤적이 달라 수치 차이를 승률이나 조작감 향상으로 해석하지 않는다. hitStop/decisive slowMo/가변rAF를 생략한 기존 종료 창 한계도 유지한다.

- 수학 검사3개: 바깥/끝점 그대로, 양끝·중앙 C1 기울기, 내부 단위길이/방위각/단조성/최대 변화.
- 런타임10행: 두 무기에서 연구 C1과 실제 옵션의 전체 native trace 및 기록된 물리/목표 frame exact. 모드 이름이 달라 전체 controller hash까지 같다고 말하지 않는다.
- runtime 추가 전후8행(기존·명령 평면·관찰·연구 C1×두 무기)의 전체 native/controller trace exact.
- 기존 평면 관찰10행도 legacy/명령 평면 각각 observer native/controller exact. 관찰이 동작을 바꾸지 않는지 확인했다.
- 독립 감사는 구현 및 첫74실행 집계의 단위·원자료·비용을 확인했다. 마지막 legacyC1 10행은 같은 실행/집계 관문으로 별도 검증했다.
- Vite build 통과(기존 큰 chunk 경고). 독립 코드/결과 감사에서 기본값 누출이나 새 blocker를 발견하지 않았다. 휴대폰 플레이 수락은 미검증이다.
