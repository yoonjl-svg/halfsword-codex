# 몸 회전·가드 전환 4차와 팔 상처 후속

2026-10-03. **중장기 2단계의 상체 제어 검증이며 전신 힘 전달의 완성 판정은 아니다.** [연속 날 토크3차](edge_plane_torque_round3.md)의 다음 작업을 실행했다. 몸 회전·가드 전환의 건강 조건을 마쳤고, 이어 팔 상처 처리의 첫 대조로 넘어갔다. 게임 런타임·일반 기본값·공개 배포는 이번 회차에서 변경하지 않았다.

## 실제 입력 계약과 비교 범위

두 무기(세이버/양손검), 보정 끔/약(.4), 정지 중 가드 전환/높은 자세 유지하며 옆 이동/이동하며 가드 전환, 기존/연속 날 토크를 비교했다. 실제 게임의 `newRound`·Fighter·Rapier·Combat을 120Hz로 실행한다. 첫3초 준비 뒤6초 관찰한다. seed7, 시작6m, 벽 없음, paired grip, 기존 팔/절삭이다. 적 AI는 끄고 두 몸은 실제 물리로 움직인다.

몸 회전은 횡이동 스틱 +.7→−.7→0과 상대 골반을 보는 기존 heading 제어로 만든다. 몸 위치·속도·yaw를 덮어쓰거나 G.park로 적을 옮기지 않는다. 손은 오른 어깨 위→왼 아래 베기→놓기→왼 황소 자세→유지→오른 옆→놓기→가운데 유지로 이동한다. 별도 가드 버튼/guardTarget은 없으며 보정0은 같은 입력의 원래 매핑, 약은 실제 .64 자세표 혼합이다.

**놓은 뒤 재입력은 현재 손 목표에 터치 변화량을 더한다.** 초기4실행 smoke는 과거 절대 끝점으로 다시 지정하여 실제 자동 복귀 후의 입력 계약과 달랐다. 원자료·소스를 보존하고 수락 근거에서 제외한 뒤 main과 같은 누적 변화량으로 수정했다. 입력 중단 시 원래 요청은 마지막 외부 요청 위치에 남겨 자동 복귀와 구별하고, 필터/자세표를 거친 자체 목표 오차도 함께 기록한다. 고정 물리 tick 입력이며 가변 브라우저 rAF의 완전 복제는 아니다.

## 같은 초기 상태에서 후퇴 재현과 원인 분리

두 무기/약 보정에서 첫3초를 전부 기존 방식으로 실행하고, 같은 native/controller/input prefix 뒤 연속 토크만 켠6실행에서도 양손검 회전량 후퇴가 유지됐다. 이는 준비 자세 차이만으로 설명되지 않는다. 실행 도중 옵션 전환은 인과 분리 도구이며 사용자 UI의 기능이 아니다.

다음8실행은 연속 후보로6초까지 똑같이 진행한 양손검 약 조건에서 위치항·제동을 분리했다. 표는 **개입 뒤6–9초만**이며, 표본 수가 다른 속도 가중·지연된 점 속도 평면 오차를 사용한다.

| 6초 뒤 개입 | 축 회전량 rad | peak rad/s | 실제 이동 평면에 대한 날 오차 rad |
|---|---:|---:|---:|
| 연속 토크 유지 | 12.444 | 16.75 | .365 |
| 기존 위치 토크로 복귀 | 10.466 | 29.88 | .321 |

위치항 제거는 돌아가는 양만 줄이고 날 정렬을 잃어 기각했다. 상대 제동은 정렬은 조금 좋아졌지만 회전량·peak가 후퇴해 기각했다. 동일한 준비 상태여도 이후 실제 속도/유효 정렬 표본은 각각264/228/266/269개로 달라진다.

상대 제동은 단순 전완 기준이 아니다. 실제 반작용이 전완 축 a에 수직인 성분은 전완, 평행한 성분은 가슴에 전달되므로 `ωref = ω전완 + a((ω가슴−ω전완)·a)`를 사용했다. `δ=(ω검−ωref)·검축`, `τD=−dδ 검축`이면 세 몸을 합한 **순간 명시적 D power는 −dδ²**다. 독립 감사가 수식·부호·실제 전완 로컬+X 축을 확인했다. 이 수학적 성질만으로 움직임이 좋아지지는 않았다. 전체 스텝 ΔK·native 모터 일·전신 수동성을 증명한 것도 아니다.

## 두 평면을 섞는 후속 후보도 일반 채택하지 않음

기존 목표는 몸 기준 정지 normal과 운동 normal의 앞뒤를 각각 고른 뒤 벡터로 섞는다. 혼합중 normal 부호 전환이 남아 있어, 후속 연구는 부호 선택 대신 두 평면의 잠재함수 토크를 직접 가중합했다. 이 경우 특정 혼합 목표 normal 하나에 대한 오차를 새 성공 점수로 쓰지 않고 같은 실제 이동 평면 오차를 유지한다.

같은6초 prefix4실행에서 후속은 회전량12.444→10.502rad로 줄였지만 실제 날 오차 .365→.545rad로 후퇴했다. 생성부터 적용한 두 무기/끔·약8조건+관찰2에서도 세이버 끔 peak14.00→16.49rad/s, 양손검 끔 peak15.57→16.47rad/s의 반례가 남았다. 양손검 약의 회전량18.458→15.726rad 개선만으로 채택하지 않는다. 추가 gain 탐색을 중단하고 두 후속 후보는 연구 도구에만 남겼다. 일반판·기존 모바일 A/B에는 연결하지 않았다.

## 팔 상처 후속: 다음 검증으로 진행

몸 회전의 추가 조정 뒤 대기하지 않고, 실제 `applyWound` API를 통한 제한된 팔 상처 대조12실행을 마쳤다. 첫3초 같은 준비 상태에서 주손 전완에 severity .6/76 게임J의 합성 베기 payload를 넣었다. 직접 armHealth 값을 바꾸지 않고 기존 상처·통증·출혈·기능 저하 처리를 통과한다. 즉시 native 자세/속도는 변하지 않았고 상처1개·절단 없음·살아서 검 보유를 확인했다. **실제 칼 접촉 재현이 아니라 상처 API를 호출한 통제 조건**이다.

## 마지막 입력 경계 정정과 재검증

마지막 입력 계약 검사에서 5.1초 구간 끝의 변화량이0인 한 tick을 움직임 구간이라는 이유로 active=true로 두는 오류를 찾았다. 실제 변화량으로 inputActive를 계산하도록 도구를 고쳤다(`60edb76`). 건강 이동/가드 8행+관찰2와 팔 상처4행+관찰2, 총16회 재검증을 추가했다. [보존 비교](edge_turn_input_boundary.json)의12개 관찰 행은 이전과 **전체 native trace 및 명시한 물리/목표 frame이 exact**였고, 새 입력 플래그는 전 프레임에서 변화량과 일치했다. idle 제어 이력은 바뀌므로 이전과 controller hash까지 같다고 주장하지 않는다. 각 새 실행 내 observer 동등성은 별도로 통과했다. 이 반복을 신규 독립 성공 표본으로 세지 않는다.

## 보존·비용·판정 범위

[몸 회전 JSON](edge_turn_guard_round4.json)은6원자료 SHA256·보존 소스·명령·파일 일치·prefix/observer 관문을 담는다. 몸 회전58실행에는 초기 입력 계약을 고친4회와 관찰·기준 반복이 포함되며 독립 성공 표본58개가 아니다. 상처 후속12회와 아래 입력 경계 재검증16회를 더해 이번 회차는 총86실행, 실행 wall time 합221.721초(몸 회전148.708+상처32.757+경계 재검증40.257)다. 개발·감사 전체 시간이나 토큰 비용이 아니다.

소스 `d0b56d8`(초기 절대 입력), `3451fcf`(누적 변화량/생성부터·같은3초), `716b100`(위치/상대 제동), `0573f07`(두 평면 혼합), `26fd635`(상처 API 후속), `60edb76`(입력 활성 경계 정정). 몸 회전 초기4회 외54실행은 누적 변화량 계약이다. 뒤 연구 코드 추가 후에도 원래 연속 후보6행의 전체 native/controller/input trace가 이전 소스와 exact였다. 일반/연속 후보는 계측 자체 on/off를, 추가 개입 후보는 개입 코드가 공통인 상태에서 frame 관찰 on/off를 비교한 범위를 구별한다.

원자료는 저장소 밖 `halfsword-hybrid-evidence`에 보존한다. 실제 날 오차는 지연된 hitPointVel 차분과 abs(dot)의 평면각으로, 순간 native 점 속도·앞날/뒷날·절삭 에너지와 같지 않다. 몸 회전·상처 API 검사가 기존 실패한 절삭 후보의 수락을 되살리지 않는다. GitHub 인증은 지원 답변 대기이며 새 공개 배포는 없다. 비교판/실행 계획/승인 사운드는 전송 뒤 공개 바이트와 폰 실행을 확인하기 전까지 사용자 플레이 가능으로 보고하지 않는다.
