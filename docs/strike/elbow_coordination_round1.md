# 팔꿈치 협응 진단 1차

검술 보정을 끈 현재 손 목표 매핑은 검사한 여섯 베기 모두에서 팔꿈치 목표를 같은 각도로 고정했다. 팔꿈치 모터는 작동하지만, 손 요청이 팔 도달 길이를 계속 넘어 IK가 펴짐 한도에 붙어 있었다. 사용자의 ‘막대 같은 팔’ 관찰을 이 조건에서 재현했다. 보정 켬은 팔꿈치 움직임을 되살리지만 입력·위상 간섭이 남아 있으므로 해결이나 보정 켬 권고로 처리하지 않는다. **런타임·엔진·제어 기본값 변경 없음, 진단 회차의 일반 후보 적용 없음.**

기준 HEAD `7b72c4e3bc4a50fc56786362de6509c9d2270757`. [관찰 도구](../../tools/sim/experiments/elbow_coordination_probe.mjs), [설정·SHA·36행 요약](elbow_coordination_round1.json). 기존 [native 팔꿈치·제동 2차](native_elbow_followthrough_round2.md), [팔 근력 1차](arm_capacity_round1.md), [신체 모델 조사](body_model_assessment.md)를 재사용했다. 실패한 자유 두 강체 모터 교체를 재실행하지 않았다. native 결합 solver를 대체한 이전 후보는 cap에 닿기 전 추종이 후퇴했으므로 이번 매핑 진단과 다르다.

## 실제 구동 경로

`driveSword`가 손 위치와 검 방향을 같은 필터 입력에서 각각 만든다. 보정 꺼짐 손 깊이는 `0.12 + 0.5*sqrt(1-(off.x²+off.y²)/reach²)`, `reach=.62m`다. 손 좌우·높이를 함께 쓰지만 어깨에서 요청한 거리가 실제 팔 길이 안에 들어오는지는 이 단계에서 맞추지 않는다.

`armIK`는 같은 손 위치에 대해 어깨 목표와 팔꿈치 목표를 동시에 계산한다. IK 상완/전완은 .300/.270m이고 .005m 여유를 빼 최대 d=.565m다. `d`가 포화되면 코사인 법칙으로 정한 팔꿈치 굽힘이 **.265470614rad(15.21°)**로 고정된다. 실제 연결 길이 .300/.265m의 5mm 차이는 기존 조사에서 확인됐고 이번에 수정하지 않았다.

`driveJoints`는 실제 farmS native hinge에 매 스텝 목표 위치/속도·k/d를 전달한다. 팔꿈치 상대 각속도에 따른 Hill 위치오차 제한, ±15rad/s 목표속도 제한이 있다. `elbowGravity`는 상완/전완에 같은 크기 반대 토크를 보탠다. 검 방향은 yaw 기준 별도 손목 토크로 움직이고 반작용은 전완과 가슴으로 간다. 목표 호출 순서만으로 상완→전완→검의 순차 증폭이나 실제 에너지 전달이 구현됐다고 판단할 수 없다.

## 실제 관찰 관문과 결과

sabre/zweihander × down/up/cross × hold/release × 보정0/.4/.7: **36조건, baseline/observe 실제 실행72행**. 각 조건의 준비 native/controller·요청 입력 일치, 관찰 설치 순간 native 불변, 기존 전체 physical/control trace exact, 실제 farmS configure210회, source/엔진 SHA 동결 관문을 통과했다. 같은 drag 뒤 hold/release는 독립 stroke가 아니며 별도 seed 반복도 없다. 원자료는 `/tmp/elbow-coordination-level{0,0.4,0.7}-round1.json`; SHA256·명령·임시 입력 helper SHA는 JSON에 있다. 기본이 아닌 skill은 기존 시험 helper의 실제 `newRound`에 skill 옵션 하나만 임시로 추가해 3초 준비부터 사용했다. 게임 클래스/G.step/엔진은 동일하다. 첫 cheap와 이전 기본 회차는 중복이므로 이36조건에 포함하지 않는다.

보정 꺼짐은 여섯 독립 drag 모두 **66/66프레임 포화**, 목표 flex의 최소/최대가 완전히 같다. 예를 들어 sabre down 손 요청 거리는 .61949–.65703m로 .565m IK 한도를 계속 넘고, 실제 flex는 .208–.325rad(11.92–18.65°)였다. 목표가 시간에 따라 펴지고 굽히는 경로가 없다. 보통의 같은 무기/down 실제 flex는 .819–1.927rad로 범위가1.107rad였다. 약은 일부 츠바이핸더 베기에서 계속 포화됐다.

아래 속도 투영은 실제 관절 각속도의 **기하학적 검끝 속도 몫**이다. 힘·일·효율 점수가 아니다. 상완은 가슴에 대한 상대 회전, 팔꿈치는 전완–상완 상대 회전, 손목은 검–전완 상대 회전이다. 각 회전에서 distal tip까지 레버를 써 검끝 실제 속도 방향에 투영했다. base 항과 closure residual은 원자료에 따로 남겼다. peak→검끝의 양수는 해당 분절 peak가 검끝 peak보다 먼저였다는 뜻이며 인체의 적절한 순서를 입증하지 않는다.

보통 sabre down/cross의 상완 상대 swing 최고점은 검끝보다 .117/.125초 늦었다. 반대로 츠바이핸더는 상완 최고점이 검끝보다 .35–.425초 먼저였다. 같은 고정된 협응 패턴이 아니라 입력 자세·무기·별도 검 방향 제어에 의존한다. 츠바이핸더 up/cross는 검끝 peak에서 팔꿈치 투영이 −9.609/−7.435m/s, 손목은 +18.603/+19.251m/s였다. 전완과 검이 서로 다른 회전으로 상쇄하는 구간을 관찰했지만, 이 수치만으로 에너지 손실·근육 일 낭비나 모터 고장을 선언하지 않는다. 검끝 peak가 stroke 마지막 프레임인 행은 최고점이 관찰창 밖에 있을 수 있다.

전체 joint anchor gap 최대는 .001760m, 속도 decomposition closure residual 최대는 .590956m/s였다. 검끝 peak의 residual과 모든 프레임 값을 보존했다. solver/앵커 속도 차이가 있으므로 분절 몫의 합을 절대적인 힘 전달 장부로 해석하지 않는다. 전완의 hinge 축 밖 상대각속도도 기록했고 축 방향 flex rate와 구별한다.

원자료는 각 phase의 실제 명시적 `manualMuscle`·`driveSword`·`elbowGravity` midpoint signed work를 보존한다. 각 경로에는 해당 반작용의 body work도 들어 있다. 예를 들어 꺼짐 sabre down stroke는 어깨 경로 −16.573J, 검 경로 +2.444J, elbowGravity +.148J였지만 **native 팔꿈치/constraint/contact work가 빠져 있어 총근육 일이나 전달 효율로 합산 비교하지 않는다.** native configure k/d/목표에서 가상의 토크를 추정해 각속도와 곱하지 않았다. 실제 applyWound·상대 접촉·힘 한도 후보·폰 체감은 이번 검사에 없다.

## 다음 가장 작은 개입과 판정

1. **보정 꺼짐 손 위치를 shoulder-relative 도달 범위와 유효 radial 변화에 맞추는 후보 하나.** 기존 검 방향·입력 계속성·강도·근력 budget·native 관절을 보존하고, 사용자의 큰 stroke가 팔을 접었다 펴는 실제 목표 변화로 이어지게 한다. 단순 구면 투영은 이미 IK가 하는 clamp와 같아 flex 고정을 해결하지 못한다. 이전 끝점 도달범위2차 실패를 반복하지 않는다. 최소 기준은 실제 .300+.265m 연결 길이이고, 입력 가장자리/중앙에서 팔을 적절히 접고 펴도록 radial 경로를 별도 설계해야 한다. 이번 보고는 어떤 radial 경로가 인간답다는 수락도, 후보 적용 승인도 아니다.
2. **위상은 매핑 해결 뒤 actual shoulder lag·elbow flex/rate·검 aim과 함께 비교.** 상완을 먼저 쓰고 팔꿈치를 뒤에 펴는 방향은 사용자 목표지만, 고정 시간 애니메이션이나 외부 각속도 부여로 증폭하지 않는다. actual tracking/부하에 반응하는 작은 target coupling으로 시험한다. 빠른 검끝만 통과점수로 쓰지 않는다.
3. 첫 smoke는 같은 준비·입력의 sabre/zweihander down, 보정0/.4와 hold/release다. observer exact·실제 target 개입·설치 상태보존·기존 torque budget 유지 관문 뒤 목표/실제 flex 변화, 검 aim/손 오차, 종료 회전량, native cap 마지막 substep(해당 native 후보를 쓸 때만), 실제 명시적 일·검 중력 일을 함께 본다. 유효 이득이 있을 때 up/cross·실제 상처·접촉·모바일로 넓힌다.

재현(저장소 루트, 출력은 기존 파일을 덮지 않는다):

```sh
node tools/sim/experiments/elbow_coordination_probe.mjs --level=0 --out=/tmp/elbow-coordination-off-rerun.json
node tools/sim/experiments/elbow_coordination_probe.mjs --level=0.4 --out=/tmp/elbow-coordination-weak-rerun.json
node tools/sim/experiments/elbow_coordination_probe.mjs --level=0.7 --out=/tmp/elbow-coordination-normal-rerun.json
```

이 회차는 현재 입력 매핑의 결함 재현과 다음 개입 근거를 확보했다. 전신 증폭·기립·전투·사용자 체감의 완료 판정은 유지한다.

후속 [radial 후보1차](elbow_reach_round1.md)는 위 진단 뒤 연구 전용으로 구현했으나 추종/종료 후퇴·경계 overflex로 기각했다. 진단과 후속 후보의 실행 source SHA는 각 JSON에서 따로 확인한다.

후속 연구 재사용을 위해 도구에 observer/summarize export와 isMain guard를 보탰다. 진단 실행 당시 도구 SHA는 원자료 manifest에 그대로 보존하며 현재 파일 SHA로 과거 실행을 대표하지 않는다. 게임 제어 변경은 아니다.
