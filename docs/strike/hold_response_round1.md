# 입력 유지 뒤 목표·감쇠·관성의 구분 · 1차

**게임 판단:** 손가락을 멈춘 뒤 검이 늦게 따라오고 멈추기 어려운 것은 유한한 근력으로 검의 관성을 다루는 의도된 경험일 수 있다. 지연이나 큰 방향 오차만으로 결함이라고 판단하지 않는다. 이번 비교는 기존 제어를 바꿀 근거를 확보하지 못했다. 일반판·선택형 공개·한손 회복 후보의 보류 상태를 유지한다.

사용자가 관성의 의미를 지적하여 연구의 수락 기준을 정정했다. 빠른 정지·낮은 운동에너지를 개선 목표로 삼지 않는다. 입력→걸러진 목표→근육 요청→관절과 검의 실제 응답을 구분하고, 힘 한도와 관성을 유지하는 제어의 일관성을 평가한다. 입력 필터의 지연도 자동 결함이 아니며, 자연스러운 감각을 구현했다는 검증도 아직 없다.

[재현 집계 JSON](hold_response_round1.json)과 실제 게임 실행 도구를 보존했다. 추가 물리 코드는 게임 `src`에 넣지 않았다. 음량 조정 `d023cf8` 이후 게임 코드·npm 엔진·일반 설정은 같다.

## 실제 장면과 관찰

앞선 세이버19의 실제 전투 이력을 생성부터 재생했다. 주팔 건강1, 빈팔 건강.73185의 회복 중11.8초 경계이며 전신 건강이나 실제 주팔 부상 효능 사례가 아니다. 손가락 요청은 계속 잡은 상태에서 변화량0이다. 필터·가드·찌르기·AI·물리의 기존 업데이트를 그대로 실행했다. 검술 보정0, thrust 혼합0이며 검술 보정을 꺼도 목표 필터는 작동한다.

원래 한손 독립 활성 소비와 모든 주팔 경로의 ordinary 소비 대조, 각각 관찰off를 포함해4실행했다. ordinary는 같은 independent 생성 이력 이후의 진단이며 생성부터 일반판인 대조가 아니다. 모든 원래 메서드는 매step1회, prefix/분기 상태·입력/사건과 관찰on/off trace가 일치했다.

최초 실제 호출에서 손가락은 정지했지만 걸러진 손 목표의 속도는1.427m/s이고, 검의 world 목표변화율은2.556rad/s였다. yaw만 변했다고 가정한 변화율.134와 로컬 목표만 변했다고 가정한2.422rad/s를 따로 계산했다. 두 유한각 반사실 계산은 합산 가능한 분해가 아니다. 손가락·목표·실제 손과 검은 서로 다른 상태다.

기존 full 경로의 최초 방향 오차.786rad, 위치 토크 요구47.141Nm, 전체 요구80.446Nm, Hill 이후 실제cap14.860Nm였다. .5초60step 모두 pre-twist 요청이 cap에 걸렸고,52step은 기본 감쇠11, 나머지8step은 놓아주기 감쇠1.5를 사용했다. 제동 latch 진입0은 감쇠가 없다는 뜻이 아니다. 감쇠 토크의 검에서의 순간 `T·ω`가 음수인step은57개였다. 이것은 native 전체 제동 일이 아니다.

## 놓아주기 정책을 바꾼 원인 비교

연구 도구 안에서만, 입력 유지 구간의 원래 player `driveSword`가 `releaseDamping=aimDamping`인 임시 설정 사본을 읽도록 했다. 근력·stiffness·설정된 최대토크·목표·native 상태는 그대로이고 감쇠 계수만 바뀐다. 원래 설정 객체와 활성 flag는 finally에서 복원한다. 이 정책은 목표의 잔여 움직임을 없애거나 검을 순간 정지시키지 않는다.

관찰on/off2실행은 exact였고, 기록된 원래 full과52step까지 native/controller/입력/사건이 일치했다. 첫 실제 변경은1468tick/12.233333초의 놓아주기 호출이다. **그 호출 전 실제 상태는 동일**하며 감쇠1.5→11로 바뀌었다. 요청 벡터·Hill이 달라 cap도11.750→12.155Nm로 변했다. 같은 설정된 최대토크는 같은 전달 토크나 동일 예산을 뜻하지 않는다. 이후8step의 접촉 사건 기록은 같지만 solver 접촉기하나 힘이 같다고 가정하지 않는다.

표의52step은 정책이 실제로 바꾸지 않은 구간이다. 최초 변경 뒤8step의 평균 방향 오차는.72679→.74253rad, 최종 오차는.59200→.63132rad이며 평균 검K는2.97135→1.76216J다. 최초 응답의 검 전체 각속도는25.405→26.383rad/s로 오히려 높아졌다. 전체 각속도·목표 방향으로의 속도·운동에너지는 다른 양이다. **에너지는 줄어도 검 방향 추종 오차는 더 커졌다.** 낮은 에너지나 낮은 속도를 개선으로 수락하지 않는다. 기존 놓아주기가 잘못됐다고 단정하거나, 고감쇠 정책을 공개할 근거가 없다. 같은 peak가 유지된 발/gap 수치는 전체 안전성을 입증하지 않는다. 사람의 관성 체감·다른 무기·다른 부상·긴 전투는 이 비교에서 검증하지 않았다.

## 검증과 다음 코드 결정

첫4실행 소스는 `ac1cbcd22a8c3f7a6239447df5475c1ab10e17ca`, 정책2실행은 `58fc62fff8acb48393e81836080ae785fbbb6fb3`다. 물리 실행 wall 합61.485초이며 설계·감사·배포 시간이 아니고6개 독립 부상 표본도 아니다. 원자료 두 개의 SHA·Git 소스 객체·엔진·기록trace를 다시 검증했다. 오래된 기준raw와 다른 게임 파일은 승인된 사운드2개뿐이며 지정 커밋의blob 해시로 제한한다.

각 호출 전값을 읽어 원래 코드의 계산 순서로 목표속도·감쇠/위치/중력·Hill/cap을 재구성하고, 원래 출력과cap/Hill/제동bool/pre-twist 벡터를 비교했다. 첫raw의 검사에서 누락된 finite/latch angle은 원본180행을 덮어쓰지 않고 후처리로 검증했다. 신규 도구는 이 항목을 실행 중에도 검사한다. 독립 읽기 감사도150개 소스 해시·trace·180행·52step 동일구간·첫 실제 토크/solver 응답과 위8step 집계를 재검산해 일치했다. 출력 일치는 모든 중간항의 독립 native 계측을 뜻하지 않는다. 상대목표 잔차 power는 제어 진단이며 물리 수신체 일이 아니다.
