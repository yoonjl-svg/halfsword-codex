# 큰 베기 뒤 관성·제동 비교 1차

2026-10-03. 목적은 **힘을 실은 베기와 급한 방향 변경 뒤, 검을 거두는 부담과 빈틈이 더 설득력 있게 나타나는 결투**다. 느린 정지·큰 오차는 그 자체로 실패가 아니며, 검의 비정상적인 축 회전은 원하는 무게감과 구별한다.

**판정:** 검 자체의 수동 회전 저항 제거는 개선 후보로 선택하지 않는다. 제동 계획의 여유 축소도 새 공개 비교판을 보류한다. 실제 개입은 확인했지만, 같은 입력에서의 게임 이득과 전투 회전의 사람다운 범위를 확보하지 못했다. 일반 게임 물리·기본값은 바꾸지 않았다. 이번 결과로 사용자에게 추가 플레이 시험을 요청하지 않는다.

[수치·원자료 SHA·소스·브라우저 영수증](inertia_followthrough_round1.json)에 근거를 보존했다. 실제 물리 실행은 **56회**이며 첫 두 비교24회씩과 원인 검증8회를 포함한다. 반복 기준·관찰off를 독립 조건 수로 세지 않는다. 2단계 연구 완료나 인간 동작 수락이 아니다.

## 비교 경로와 게임에서의 의미

| 경로 | 바꾼 것 | 결과와 판정 |
|---|---|---|
| 수동 저항 | player 검의 native angularDamping만0.3→0 | 모형화하지 않은 전역 저항을 뺀 짧은 동작의 극한 대조. 관성·질량·근력은 그대로다. 목표 부담 증가가 일관되지 않아 미선택 |
| 제동 계획 | player releaseMargin만1.4→1.0 | 기존 정지각 추정에 붙인 여유를 축소. 물리 계산과 연결된 계획 후보이며 고정 입력 지연이 아니다. 실제 전투에서 제동을 늦췄지만 공개 수락 근거 부족 |

두 후보는 따로 실행했다. arm/body damping, 목표 필터, aim/release damping, 질량·COM·관성, gravity, native 관절·그립·근력 한도·상대 설정은 그대로다. 선택 사본은 연구 도구에서만 적용했고 게임 URL/UI에 연결하지 않았다. 수동 저항0은 측정된 공기 저항값이 아니다.

## 정해진 동작: 효과와 무효 비교를 구별

실제 Fighter/Combat/Rapier의 세이버·큰 양손검을 같은3초 준비 뒤 .55초 내려베기,1.2초 유지/놓기/방향 전환으로 비교했다. 기존 `G.park()`로 상대를 격리한 장면이며 실제 전투 효능이 아니다. player 자세·속도·상처 수정이나 native snapshot 복원은 없다. 입력/제어 상태 초기화는 time0에 명시했다.

수동 저항14실행에서 hold/release가 같은 native 궤적이므로 **고유 native 궤적8개**다. 보정 후 내려베기 끝의1.2초 검 방향 이동량은 다음과 같다.

| 무기 / 입력 | 기존 → 저항0, rad |
|---|---:|
| 세이버 / 유지·놓기 | 0.185939824 → 0.185930951 |
| 세이버 / 방향 전환 | 2.078924992 → 2.079435290 |
| 큰 양손검 / 유지·놓기 | 0.414974018 → 0.399235386 |
| 큰 양손검 / 방향 전환 | 2.465112663 → 2.479409141 |

내려베기 최대 칼끝 속도는 세이버+0.13%, 양손검+0.64%였다. 방향 전환의 이후 실제 손목 토크 크기 적분도 무기별 증감이 섞였다. 더 큰 제동 부담이나 몸의 비용을 일관되게 만들었다는 근거가 없다.

제동 여유14실행에서는 여섯 original/candidate 쌍의 **native·실제 토크·brake latch가 모두 exact**였다. 파라미터가 제어 hash에 들어간 차이는 물리 효과가 아니다. 고유 native 궤적은4개다. 후속 양손검 reverse4실행의420회 원래 출력 재구성도 효과 부재를 확인했다. 첫 latch의 잔여각0.334543rad가 양쪽 문턱0.497420/0.355300rad보다 작아 두 판 모두 같은 제동을 골랐다.

처음 도구의 `acos(dot)`는 native f32 quaternion 때문에 축 길이가 정확히1이 아닌 경우 작은 각도 누적을 왜곡했다. 원자료를 덮어쓰지 않고 `atan2(|cross|,dot)`로 재집계했다. 처음 세이버의 미세 진행 증가 주장은 이 보정 뒤 사라졌다. 이후 도구는 이 계산을 사용한다.

## 생성부터 켠 실제 전투와 첫 개입

각 경로는 두 reactive AI·실제 접촉에서 세이버/큰 양손검 × seed7/19 × 두 모드를 생성 직후·첫 AI/스텝 전에 설정했다.18초 또는 첫 사망까지8회와 관찰off2회씩이다. 상대는 기존 longsword이며 park·AI 동결·합성 부상·자세/속도 변경은 없다. 원래 driveSword/driveJoints/elbowGravity는 매 step1회씩 실행했다.

제동 계획의 세이버19는 실제 첫 변경을 좁은4실행과4,320회 원래 손목 출력 재구성으로 확인했다. call94의 입력·몸·필터 관련 기록과 해결된 aim·목표 각속도는 exact였다. 호출 전0.783333초, 이후0.791667초다.

| 첫 차이 | 기존 | 후보 |
|---|---:|---:|
| 잔여각 / 명목 정지각 | 0.586385 / 0.434434rad | 같음 |
| 선택 문턱 | 0.608208rad | 0.434434rad |
| 선택 감쇠 | 11 | 1.5 |
| 명목 base cap | 22N·m | 같음 |
| 방향에 따른 Hill 갱신 뒤 cap | 13.201378N·m | 8.432315N·m |
| 실제 검 토크의 순간 power | −157.525015W | +93.707588W |

기존은 제동하고 후보는 계속 힘을 실었다. 수동 저항을 뺀 것처럼 해석하지 않는다. 토크 방향 변화가 Hill 응답과 가용 cap도 바꿨다. 순간 power는 native가 적분한 전체 일이나 전신 근력 예산이 아니다.

명목 정지각은 pre-Hill cap×brakeEcc=28.6N·m와 고정 손 기준 검 관성을 사용한다. 여기서 실제 가용 한도와 차이가 컸다. 움직이는 손·팔 관성·중력·접촉까지 반영한 실제 정지 거리가 아니므로1.0을 인간의 올바른 예측값이라고 부르지 않는다. 즉시 반대 입력에서 release gate가 닫히면 양쪽 모두 원래 aimDamping을 쓰므로 모든 방향 변경을 직접 늦추는 후보도 아니다.

후속 AI 입력과 접촉은 달라졌다. 사망/생존·상처·끝 상태와 전체 구간 peak는 반응하는 장면 결과이며 같은 입력의 제동 효율·승률 개선이 아니다. 세이버19의 blade-axis 최대 회전61.26→110.60rad/s, gap2.500→5.375mm, 양손검7의 골반 위 속도0.859→1.637m/s는 검토 우려로 남긴다.10Hz 표본이 순간 peak를 놓쳐 지속 시간/접촉 맥락은 미확정이다. 이것만으로 붕괴를 확정하거나 finite/stand로 자연스러움을 선언하지 않는다.

초기 전투 도구의 inputActive는 AI에서 undefined여서 `afterClashInputSteps=0`을 입력 없음으로 쓰지 않았다. 초기 기록은10Hz player hand 변화와 두 AI 합산 input hash로 하한/상한만 복구했다. 이후 도구는 실제 손 명령 변화 step을 첫 clash 다음 step부터 센다. severity0 콜백은 실제 양의 상처와 구별한다.

## 화면과 감사

완성 빌드의 실제 touch12조건을 확인했다. 수동 저항 기본 카메라4조건, 실제 조이스틱 접근 뒤 수동 저항4조건·제동 계획4조건이다. 후자의8조건은 기존 freeCam을 사용해 live pelvis 기준으로 카메라만 옮겨 팔·몸통·다리를 함께 보았다. AI/접촉을 유지했고 설정은 player의 첫 actuator 호출 전에 적용했다. native 자세·속도·물성 보존, trusted touch, 입력 소비·실행, finite·page error0을 확인했다. 헤드리스와 브라우저 입력이 exact라는 증거나 실제 휴대폰 사용자 체감은 아니다.

디렉터는 정지 화면과 생성된 영상 프레임을 검토했다. 들어 올리기·내려베기·방향 전환·접촉 뒤 조작은 확인했으나, 두 후보가 더 설득력 있는 회복 빈틈을 보여 준다는 판단 근거는 부족했다. 극단적인 축 회전의 지속 시간/자세는 이 화면 표본에서 해결되지 않았다. 새 후보 공개를 보류하며 더 좋은 느낌인지 사용자에게 원인 진단을 맡기지 않는다.

독립 감사는 각 frozen source/엔진 manifest, 기준 재현, 원자료/누적 trace SHA, 관찰 불변성, 토크·반작용·power·각도와 첫 개입 계산을 확인했다. 재구성 cap/Hill/pre-twist 출력 오차는0, latch/angle은 exact였다. reaction closure는 선택한 explicit 경로의 순 토크만이며 native 모터·offHand/grip/contact work·전신 전달 효율은 미검증이다.

## 다음 개발: 실제 제동 부담과 몸의 비용

이번 두 파라미터를 더 훑지 않는다. 다음30–60분 과제는 **실제 전투 준비에서 강한 베기→멈춤/되돌리기의 가용 제동력과 검·전완·몸통 반작용**을 같은 입력으로 좁게 비교하는 것이다. 명목 정지각과 실제 가용 힘의 차이를 읽고, 검만의 속도를 바꾸는 대신 부담의 경로를 설명할 수 있는 작은 후보를 고른다. 빠른 정지·오차 감소를 목표로 삼지 않는다.

같은 입력에서 의도한 부담/빈틈이 실제로 달라지고 회전·관절·발 지지·화면 관문이 통과하면 폰 두 판으로 짧게 체감을 묻는다. 전신 물리 완성을 그 시험의 선행 조건으로 삼지 않는다. 새 근거가 없으면 이 둘을 재권유하지 않고 실제 근력 한도 경로로 이동한다. 한손 회복 활성 후보의 공개 보류, 실패한 projected 지지·budgeted 절삭 철회와 메이저 일반 적용의 사용자 확인은 유지한다.

재현 도구는 `tools/sim/experiments/sword_drag_probe.mjs`, `sword_drag_duel_probe.mjs`, `summarize_sword_drag.py`다. 기본은 첫 저항 대조이며 `--trial=brake`가 별도 계획 후보다. `--weapons=zweihander --endings=reverse --response=on`/`--weapons=sabre --seeds=19 --response=on`은 이번 원인 검증의 좁은 설정이다. 항상 새 `--out` 경로를 사용한다. `tools/browser/inertia_research_screen.mjs NEW_OUTPUT`은4197포트 로컬 완성 빌드용이고 `--engage-side`/`--brake-side`가 각각 실제 접근·측면 관찰이다. Playwright/Chromium/영상용 ffmpeg를 준비해야 하며 공개 플레이 링크가 아니다. 원자료/브라우저 영상은 저장소 밖에 보존했고 집계/해시만 공개한다.
