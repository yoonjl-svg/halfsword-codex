# 검 날 방향 기억 1차: 정지는 개선, 연속 베기는 후퇴

2026-10-03 KST. **연구 후보이며 공개 연결·기본 적용을 보류한다.** 한손·양손6베기에서 정지 뒤 축 둘레 회전이 줄었지만, 실제 찌르기와 방향 전환에서 새로운 후퇴가 나왔다. 팔꿈치 포화·전신 전달·부상 회복 해결로 해석하지 않는다.

## 구현과 발견

현재 게임은 움직일 때 실제 칼 중간점 속도로 날 방향을 정하고, 느려지면 몸 오른쪽을 보는 평면으로 돌아간다. 이 목표 혼합을 조사하다가 입력 종료 뒤 불필요한 날 회전을 확인했다. 후보는 입력이 만든 베기 평면을 기억하고 정지 때 유지한다.

`src/edge_intent.js`와 `Fighter.driveSword`의 명시적 `edgeIntentModel='commandedPlane'` 분기를 구현했다(`92fe406`). 일반 생성자·메뉴·URL에서는 설정하지 않는다. 몸 자세/속도를 덮어쓰지 않으며 기존 손목 torque·cap·반작용 **공식**을 그대로 쓴다. 목표가 달라져 실제 토크·일은 달라진다.

몸의 yaw 좌표에서 이전/현재 목표 방향을 u₀,u₁이라 할 때 `n=(u₀×u₁)/dt`, 명령 속도 상당량은 `|n|×(hiltLength+0.7×bladeLength)`다. 기존 수치 문턱 .5~2.5의 smoothstep으로 기억 평면을 갱신한다. 원래의 실제 중간점 속도와는 다른 입력이다. 정지하면 저장 평면을 유지하고 실제 검 축에 수직으로 투영한다. 세계 좌표에서 고정된 평면은 아니다. 첫 프레임은 원래 목표로 seed해 초기 점프를 막았다. seed 이전 첫 시도는 작은 yaw 잔여 속도 때문에1.107rad 목표 점프가 생겨 기각했다.

## 같은 준비·외부 입력의 여섯 베기

보정0, paired grip, 건강 상태, 열린 공간, seed7. 3초 준비 뒤 .55초 베기와1.2초 정지다. 실제 게임/Rapier를 실행한다. 다음 값은 `Σ|ω검·검축|dt`: **세계 각속도의 검 축 투영 절댓값 적분**이며 손목 상대 회전이나 최종 자세 차이가 아니다.

| 무기 / 베기 | 기존 정지 뒤 회전 rad | 후보 rad | 감소 |
|---|---:|---:|---:|
| 세이버 내려베기 | .04524 | .00598 | 86.8% |
| 세이버 올려베기 | .12434 | .03302 | 73.4% |
| 세이버 사선 | .92362 | .08643 | 90.6% |
| 양손검 내려베기 | .20973 | .00751 | 96.4% |
| 양손검 올려베기 | .28516 | .05338 | 81.3% |
| 양손검 사선 | 1.25764 | .07544 | 94.0% |

검의 긴 축 방향 추종은 거의 같지만 모두 좋아진 것은 아니다. 양손 사선의 종료 뒤 축 방향 이동은 .620039→.624362rad, 마지막 방향 오차 .079971→.080236rad로 소폭 증가했다. 전체 구간 최대 비틀림 속도도12.664→14.670rad/s로 늘어 정지 구간 개선과 구분한다. 팔꿈치 swivel과 결합한 한 사선의 정지 개선은 별도로 기록했으나 팔꿈치 후보 자체는 다른 베기에서 실패했다.

연구18행의 baseline/observe/edge 전체 samples가 runtime 분기 추가 후에도 동일했다. runtime24행에서6조건 모두 연구 후보와 실제 분기의 trace가 정확히 같았다. release8행도 관찰·동등성 관문을 통과했지만 보정0에서 hold와 실제 동역학이 같아 독립적인 새 성공 표본으로 세지 않는다.

## 실제 교전: 숫자 유한성은 통과, 동작 수락은 아님

기존 실제 게임 headless 교전 도구를 재사용했다. 두 무기×seed7/19×기존/후보8행과 observer1행. 플레이어 보정0/autoGuardfalse, 두 팔 legacy, 절삭 legacy, paired grip, 시작부터 후보를 적용한다. 실제 AI·접촉·부상·탭 명령·release/reinput·라운드 종료 창을 사용했다. sourceStable·observer native/controller/AI/상처/입력 동등성을 통과했다. 살아 있는 양측 관절의 최대 틈은 모두4mm 미만이었다.

그렇지만 양손검 seed19의 살아서 무기를 든 플레이어 비틀림 peak가26.76→35.47rad/s로 증가했다. 기존 peak는2.433초 찌르기, 후보는2.692초 찌르기 뒤 사선 복귀였다. 상대는 이미 사망한 상태다. 두 행은2.742물리초에 종료하므로3.6초부터의 명명된 reinput 구간에 도달하지 않았다. 이 행을 재입력 통과 근거로 쓰지 않는다.

다른 교전은 피격/AI 궤적과 종료 시간이 달라졌다. 같은 seed로 같은 적중을 재현한 비교가 아니므로 상처·생존 수치로 승률/조작 개선을 주장하지 않는다. hitStop·decisive slowMo·가변rAF를 생략한 종료 창이어서 브라우저 완전 동등 replay도 아니다.

## 무접촉 찌르기 / 찌르기 없는 대조: 방향 전환 반례

추가로 두 무기를6m 떨어뜨리고 적 AI.update와 수동 이동을0으로 했다. 적 몸은 동적이며 실제 foe가 남아 있어 원래 `Skill.thrust()`가 작동한다. park는 foe를 없애 찌르기를 거절하므로 사용하지 않았다. 6초 실행하며2.2초 실제 찌르기, 뒤의 사선·hold·재입력을 관찰했다. 찌르기를 아예 요청하지 않는 대조도 동일 손 경로로 실행했다. 각4행+observer1행, 두 자료 모두 접촉/상처0, 실제 tap 수락·관찰 동등성·유한성 확인.

| 조건 | 세이버 재입력 peak rad/s 기존→후보 | 양손검 기존→후보 |
|---|---:|---:|
| 실제 찌르기 후3.6–4.4초 재입력 | 5.03→19.78 | 6.06→24.12 |
| 찌르기 요청 없는 같은 손 경로 | 5.01→19.78 | 5.38→24.18 |

찌르기 활성 중 양손검 peak도8.93→32.60rad/s로 후퇴했다. 새 후보가 정지 뒤 보존한 평면을 다음 베기 방향으로 바꾸는 과정이 핵심 후속 조사 대상이다. **접촉이나 찌르기가 없어도 후퇴가 나타난다.** 다만 이 결과만으로 목표 급변의 어느 항이 유일한 원인인지는 확정하지 않는다. 원래 게임의 비틀림 문제도 별도로 남아 있다.
