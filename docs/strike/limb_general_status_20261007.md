# 사지 절단의 일반판 상태 · 2026-10-07 KST

## 후속 승인: 일반판 기본값 활성화

사용자의 **“팔다리 절단 바로 켜.”** 지시로 아래의 일반 적용 대기는 해소됐다. 기준 `86ddf11e5c8ff4f17d6e17ac7a54f96b235e3465`에서 `COMBAT.limbSeverTrial` 기본값과 실제 일반 진입을 켠다. 이름은 기존 URL 호환을 위해 유지한다. 플레이어·적 모두 적용하고 절단 조건·힘·피해·중력 공식은 바꾸지 않는다. 일반 v2·회복 fresh·재베기 bounded·타격 centerline과 함께 실행한다. 옛 연구 URL은 기존 OFF, 명시적 `limbTrial=1`만 ON이며 합성 시연은 명시적 시험 URL에서만 예약한다.

검증은 기존 절단 검사를 현재 일반 조합에 연결한 좁은 회귀, 공개 빌드 일치, 모바일 크기 진입·입력·재시작 및 시연 표시로 한정한다. **검사 결과·원자료 해시·공개 전달은 이번 영수증 `limb_default_release.json`에 기록한다.** 실제 절단 발생률·인간 자연스러움·0계수 모터의 자유 회전은 이 활성화 검사의 입증 범위가 아니다. 오래된 지지/절삭 실패 후보를 재활성화하지 않는다.

이번 native 실행은 **101검사 통과, 32개 통제 fixture·4,226스텝**이다. 양팔·양다리 각각 절단 뒤5초 동안 현재 일반 조합의 실제 입력/게임 stepping을 검사했고 분리 부위 재구동·중복 출혈·부활·없는 다리로 기립 재개를 막는 경로를 확인했다. 별도2장면은 인위적 초기 배치/속도에서 실제 Rapier 접촉→Combat→팔/다리 분리를 확인했다. 이2장면을 수동 자연 전투로 쓰지 않는다. 재현: `node tools/sim/limb_sever.test.mjs <새 JSON 경로>`. 소스·입력·원자료 해시는 영수증을 따른다.

**실제 전달 완료:** 게임 `4b8c81c41c1d85ed3844d6590ed72f13ef9cc406`, Actions `37504916842` 성공. [일반 게임](https://yoonjl-svg.github.io/halfsword-codex/)의 공개8파일이 동결 빌드와 byte-exact다. 모바일 크기 Chromium7흐름·실제 Start5회에서 일반ON·베기 입력·재시작, 명시ON/OFF와 옛 비교 격리, 합성 팔/다리 단면 표시, 다리 시연→일반 게임의 정상 새 부위를 확인했다. 오류0·소스 동결이며 실물 휴대폰/자연스러움 수락을 대신하지 않는다. 폰 계획의 가로·세로 표시도 확인했다. 브라우저 재현은 `tools/browser/swordsmanship_default.mjs --scope=limb --base=<일반URL> --out=<새 외부 결과 경로>`이며 환경·명령·해시는 영수증/원자료를 따른다.

## 활성화 지시 전 조사 기록

**사지 절단은 구현돼 있지만 일반판에서는 꺼져 있다. 참수는 일반판에서 켜져 있다.** 기준 HEAD는 `c6f3ffc7526e3efc4178eaf2fbea933f244a2026`이며 이번 확인은 코드·기록 대조다. 새 절단 실험, 절단 기본값 변경, 상대 자료 조회는 하지 않았다.

| 항목 | 실제 상태와 근거 |
|---|---|
| 팔다리 절단 | `src/config.js`의 `COMBAT.limbSeverTrial=false`. `src/main.js`는 `?limbTrial=1`일 때만 켠다. `src/limb_sever.js`의 첫 관문도 이 옵션을 요구하므로 일반판에서 낮은 확률로 작동하는 상태가 아니다. |
| 구현 범위 | 양쪽 팔꿈치 아래팔, 무릎 아래 정강이·발의 실제 관절 분리. 생존·비부활 상태의 통과 베기(`cut`, `pass`, `passing`, 비박힘), 심각도1.2 이상, 관절 앵커8.5cm 이내가 조건이다. 수치는 시험용 가정이며 조직 파괴 실측값이 아니다. |
| 참수 | 같은 설정의 `decapitate=true`. 팔다리 절단과 별개의 일반 기능이다. |
| 공개 시험 | `feature-lab.html`의 사지 절단 전투 링크는 실제 접촉 판정을 쓴다. `limbDemo=armS/legF`는1초 뒤 합성 상처를 주는 외형·후속 동작 시연이며 실제 베기의 위력이나 발생률 증거가 아니다. |

## 왜 일반판에 남지 않았는가

[10/01 구현·검증 기록](limb_sever_trial.md)과 당시 [결정 기록 A-008](../dev_exchange/notes/2026-10-01.md)은 선택형 공개, 일반판은 사용자 플레이 후 결정으로 남겼다. 구현 커밋은 `19beb12`이며88검사, 초기 위치·속도를 지정한 실제 Rapier 접촉→Combat 경로, 모바일 크기 Chromium 네 링크를 확인했다. 합성 상처·설정 접촉·사람 조작은 서로 다른 증거다. 당시 관절/출혈/무장 해제 결함은 수정했지만 자연스러운 낙상과 일반 전투 발생률의 수락은 남겼다.

그 뒤 일반 승격 기록은 확인하지 못했다. 이번 “성과 전체 일반판 적용”을 최근 회복·타격·재베기 세 묶음으로 처리하면서 이 오래된 선택형 기능의 상태를 설명하지 않은 것은 **범위 정리 누락**이다. 사지 절단을 실패한 기능이나 철회된 `budgeted` 절삭 반작용 후보로 분류할 근거는 없다. 최신 승인 범위와 과거 선택형 상태를 구별해 설명했어야 한다.

## 현재 남은 구체적 확인

기존 절단 URL은 `swordsmanship_default.js`의 연구 진입 표식이어서 일반v2를 자동 적용하지 않는다. 따라서 옛 시험 통과를 현재v2와 새 공통 기본값의 절단 후 제어·회복·접촉 통합 통과로 바꾸지 않는다.

또한 `limb_sever.js`의 `stopMotor`와 `disableMissingLegSupport`는 모터 계수를0으로 설정한다. 이후 [0계수의 실제 의미 검사](support_control_semantics_round1.md)에서 Rapier0.19.3의 이 호출이 자유 회전을 뜻하지 않음을 확인했다. 옛 절단 검사의 발목0호출/재호출 없음·유한 상태는 실제 자유 회전이나 골반 보조의 완전한 제거를 입증하지 않는다. 이번에는 이 연결을 정적으로 확인했을 뿐, 절단 장면의 실패나 원인을 새로 실증한 것은 아니다.

후속 최소 관문은 기존88검사와 접촉 자료를 재사용하며 현재 일반 조합에서 팔·다리 대표 각1장면의 상처→분리→무기/제어/출혈을 확인하고, 남는 발목·upright의 실제 제약을 좁게 대조하는 것이다. 전수 탐색이나 전신 기립 연구 재개를 선행 조건으로 추가하지 않는다. **이번 작업에서는 이 후속 실험과 사지 절단의 일반 승격을 실행하지 않는다.**

이번 전달 대상은 사용자가 지정한 회복·재베기·타격 반작용의 기능 기반 공통화다. 구현/검사/공개 완료 여부는 [공통화 전달 기록](common_defaults_release.json)을 따른다. 이 문서 자체는 공통화나 사지 절단의 새 배포 완료 증거가 아니다.
