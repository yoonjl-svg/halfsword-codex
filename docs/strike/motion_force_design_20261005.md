# 동작 보정 재설계: 연속 동작의 힘 전달

2026-10-05 KST. 기준 `e90193ac030ba291ceb5418c7029551cea292f59`. 사용자 제안: ‘최대 힘을 내기 위해 캐릭터 연속 동작에 개입’하는 관점으로 재설계한다. **이번 결과는 설계·현재 코드의 정적 검토이며 새 구현/물리 실행/배포가 아니다.** 현재 공개 B는 [기존 깊이·몸 협조15%](motion_assist_20261005.md)와 [전달 영수증](motion_assist_release.json)을 유지한다.

## 목적

플레이어가 요청한 베기의 방향·시점·크기를 바탕으로, 현재 자세·무기 관성·부상·지지 상태에서 몸→팔→검을 조율해 가용 힘을 의도한 동작에 유리하게 쓴다. 강한 베기의 힘 싣기와 다음 행동으로의 연결이 목적이다. 준비 없이 짧게 베면 짧은 동작을 수행하며, 강한 베기 뒤에는 실제 관성과 제동 부담이 남는다. 최대 근력을 매순간 명령하거나 사용자 대신 공격을 고르는 방식은 채택하지 않는다.

현15%는 입력 위치에 대한 작은 깊이·몸 협조다. 연속 베기의 단계·힘 전달 성과를 최적화한 구현이 아니다. 새 설계는 운동 기술을 돕는 층이며, 기존 검술 자세표·자동 내딛기·복귀 묶음의 이름을 바꾸는 것이 아니다.

## 입력과 연속 동작

입력의 위치·방향·변화 속도와 실제 몸/검 상태를 함께 사용한다. 빠르고 큰 드래그를 강한 베기 요청의 초기 근거로 삼되, 손 위치로 정한 방향을 임의로 상대에게 돌리지 않는다. 칼의 잔류 속도만으로 계속 공격하라는 의도를 추정하지 않는다.

| 단계 | 보정의 역할 | 입력 우선 규칙 |
|---|---|---|
| 준비 | 실제 준비 입력이 있을 때 팔의 도달 여유와 몸통 방향을 정돈 | 별도 준비 시간·반대 방향 장전 동작을 삽입하지 않음 |
| 힘 싣기 | 골반·가슴·어깨·팔의 목표 순서를 조율해 맞버팀을 줄임 | 원래 베기 방향과 손의 요청을 유지 |
| 이어가기 | 이어지는 입력에 맞춰 현재 자세·운동에서 다음 목표로 연결 | 새 베기·고정 콤보를 자동 생성하지 않음 |
| 멈춤·반전 | 이전 방향의 추가 추진 요청을 철회하고 새 제동/방향 목표를 조율 | 새 입력은 즉시 수용; 실제 몸·검 속도는 강제 정지하지 않음 |
| 피격·특수 명령 | 실제 접촉·부상·탭·마무리·down/getup에 맞춰 일반 도움 축소/양보 | 기존 명시적 명령과 회복 규칙 우선 |

추가 추진 요청의 철회와 실제 토크/잔류 운동의 소멸은 다르다. 기존 필터·제어의 잔여 요구도 측정한다. ‘손 멈춤’과 ‘손 떼기’는 구분하고 두 경우 모두 후속 공격을 새로 승인한 것으로 취급하지 않는다.

## 개입 강도와 물리 경계

강도는 추가 근력의 비율이 아니라 **허용하는 목표 조율량의 상한**이다. 실제 도움은 동작 단계·접촉·사용 가능한 팔/다리 기능에 따라 줄인다. 위기에서 강한 추진을 돕는 대신 균형과 다음 조작 가능성을 우선한다. 15/25%를 이 설계의 최적값으로 전용하지 않는다.

최적화 우선순위는 사용자 의도·신체/물리 제약 → 요청한 베기 구간의 의도 방향 운동/타격 → 후속 전환과 조작 비용이다. 힘, 일, 에너지, 충격량은 별도로 기록한다. 칼끝 최고속도 크기나 피해 수치 한 가지로 최대 힘 전달을 판정하지 않는다. 타격에서는 실제 접촉점의 상대속도·날 방향·양쪽 반응을 함께 본다.

질량·관성·세계 중력·근력 설정·모터 gain/cap·감쇠·중력 보상·반작용 수신자·그립·지지/절삭 방식을 비교에서 유지한다. 순간 속도/위치 덮어쓰기와 피해 배율로 목적 효과를 대신하지 않는다. 같은 cap 설정을 유지해도 움직임과 Hill 관계가 바뀌어 실제 토크/일은 달라질 수 있다. **동일 설정은 동일 총근력/총일의 증명이 아니다.**

현재 native 목표오차 제한은 목표속도·감쇠까지 합한 실제 힘 상한이 아니다. 골반 직접 받침·kinematic upright·발 pin의 미계측 일도 남는다. 따라서 현 엔진에서 얻은 효과를 ‘인간의 최대 힘’이나 ‘전신 효율 완성’으로 주장하지 않는다. 첫 개선은 이 구조 안의 국소 동작 조율로 판정한다.

## 첫 후보: 좌우·사선 연속 베기의 몸 협조 시점

처음부터 전신 제어기와 지지를 교체하지 않는다. 현재 정적15%와 같은 손 깊이 도움·최종 몸 참고각도·혼합 비중을 유지하고, **연속 입력 단계에 따른 골반/가슴 참고 목표의 진행 시점 한 경로**만 분리한다. 실제 현재 참고 상태에서 출발해 연속적으로 진행하며 큰 입력을 정해진 준비 동작으로 대체하지 않는다. 준비 입력이 없는 베기에 새 대기 시간을 붙이지 않는다.

필수 설계 관문:

- `bodyGuardWeight` 자체를 단계마다 켜고 끄지 않는다. `applyPose`의 `(1-gw)` 손 기반 가슴 항과 필터 잔여 목표가 함께 바뀌면 명령이 튈 수 있으므로 기준 혼합과 단계 진행을 분리한다.
- 참고각도의 최댓값이 같아도 목표 미분/native 목표속도는 달라진다. 단계 전환의 목표 연속성·속도와 실제 요구를 확인한다. 단계 반복으로 검을 펌프질하듯 가속하는 후보는 기각한다.
- 입력은 렌더 회차에서 한 번 소비되고 같은 입력으로 여러 물리 스텝을 실행한다. 소비된 입력의 식별/시각을 보존해 재사용을 새 추진으로 세지 않으며, 짧은 이벤트 공백을 손 멈춤으로 오인하지 않는다. 서로 다른 이벤트 간격/프레임률에서도 같은 의도를 유지한다.
- 현재 yaw 참고값은 손의 좌우 위치에서 나온다. 이 첫 후보는 좌우·사선 협조만 겨냥하며, 좌우 위치가 일정한 수직 베기의 최대 힘 개선을 주장하지 않는다. 수직 베기는 보존/후퇴 관문으로 둔다.
- current `flow`의 자동 통과 걸음, 과거 full/yaw 가슴 목표 운반, twist 목표속도 보정·제동 gain, 실패 모터/지지/절삭 후보를 함께 켜지 않는다.

### 최소 비교와 판정

실제 게임 npm Rapier와 동일 입력을 사용한다. 첫 선별은 청강검·세이버 × 정적 기준/단계 후보 **4실행**부터다. 현재 공개 도움은 청강검에만 연결돼 있으므로 세이버 활성은 격리 연구 설정으로 명시하며 공개 지원으로 부르지 않는다. 기존 `motion_assist_probe.mjs`의 준비→베기→멈춤→반전→탭→재베기 입력 기록과 계측을 재사용한다. 수직과 사선/횡베기 구간을 분리해 보고한다. 미래 실행 명령·분기 경계는 후보 도구를 구현한 뒤 기록하며 이번에는 실행하지 않았다.

첫30–45분에 실제 개입과 목적 효과를 판정하고 90분 안에 계속/기각한다. 손·칼 목표 편차/미분, 실제 몸·팔·검 회전, 의도 방향의 실제 검 속도, 최종 명시적 토크·반작용·일, native 요청, 지지/미끄러짐·관절 gap, 멈춤/반전/재베기 비용만 우선 수집한다. 새 계측에만 비간섭 대조를 추가한다. 목적 효과가 없으면 같은 gain/강도 전수 탐색으로 늘리지 않는다.

효과가 남은 후보만 실제 접촉·현재 알려진 주팔 절상·중단/재시작·브라우저 입력으로 넓힌다. 더 높은 속도나 `stand` 유지로 인간 동작을 수락하지 않는다. 실제 화면에서 전신 동작을 검토한 뒤 폰 A/B로 ‘힘이 잘 실리고 다음 동작이 이어지는가, 보정에 끌려가는가’ 한 질문을 묻는다. 일반 메이저 승격은 구체적 결과 뒤 사용자 확인을 받는다.
