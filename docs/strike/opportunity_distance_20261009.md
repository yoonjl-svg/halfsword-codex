# 간격을 맞춘 뒤 급소 찌르기 · 10/09

**칼 손가락 취소는 일반 교정, 거리 준비 B와 기립 B는 선택형으로 전달한다.** 사용자는 [검토한 입력·기립 방식](../dev_exchange/reviews/2026-10-09-peer.md)의 도입과 “가깝거나 멀면 먼저 간격을 맞춘 뒤 얼굴·목 찌르기”를 요청했다. 거리 준비는 구현했지만 모든 조건에서 개선되지는 않았다. **가까운 레이피어 B는 급소 피해가 없었고, 먼 에스톡은 A에서 난 급소 피해가 B에서는 나지 않았다.** 일반 승격이나 성공률 달성을 선언하지 않는다.

기준 HEAD `9171874a880024010a87ad793fd6fd58a7817f3e`. 거리 후보의 실제 게임 검사는 실패한 중간안과 최종 재실행을 포함해 **29실행·40,560step**, seed7이다. 기립의 별도 실행은 [기립 기록](getup_lead_20261009.md)을 따른다. **이 문서는 공개 전달 완료증이 아니다.** 최종 [전달 영수증](opportunity_distance_release.json)의 코드 일치·모바일 결과를 따른다.

## 구현과 통제 범위

- 칼 포인터의 cancel/lostcapture는 칼 누적량·탭·제스처만 지운다. 다른 손의 이동 스틱·캡처·키보드는 유지한다. blur/pause/새 경기의 전체 초기화는 유지하며, 손 초기화는 미실행 거리 준비도 취소한다. 이미 시작한 공격의 시간까지 지우지는 않는다.
- 기존 AI에도 무기별 접근·후퇴 거리가 있었다. 이번에는 급소 찌르기 직전에 **현재 손잡이–표적 거리, 무기 길이, 회전한 실제 어깨와 팔의 남은 뻗음, 실제 검축**을 함께 읽어 준비→발 이동→정렬→찌르기를 연결한다. 새 일반 최적거리 표나 모든 무기의 거리 운용 완성이 아니다.
- 너무 가까우면 뒤로, 멀면 앞으로 기존 이동 명령을 낸다. 실제 검축의 표적선 오차7cm 이하와20도 이내를 함께 검사한다. 준비 중 팔을 도달 반경85% 안에 두고, 양손은 손잡이를 표적 선에 맞춘다. 이 값들은 게임의 준비 여유이며 사람 실측 최적값이 아니다.
- 플레이어 준비는2초/이동1m 한도다. AI는 기존 위협 대응·접근 시간 한도를 유지한다. 새 스틱·드래그, 무장·생존·자세·상대 소유권 상실, 빈틈 소멸로 취소한다. 취소된 준비 자세는0.12초에 해제한다. 공격 시작 뒤 표적은 고정한다. AI는 지연 관측을 쓰며 실제 공격 시작 시에만 기존 최대2회 예산을 센다.
- 기존 공격의 aim/extend/hold/recover/reach·피해·갑옷 계수와 힘 상한은 바꾸지 않았다. **몸의 기존 협응을 준비 중 활성화하므로 실제 동작과 충격 에너지가 같다는 뜻은 아니다.** 준비 중 찌르기 추가 유효질량은 없고 새 피해 보너스도 없다.

## 실패 이력과 검사

run01은 레이피어 플레이어만 개선하고 AI 급소 피해는0이었다. run02는 AI 피해를 얻었지만 에스톡이 표적선 약19.7cm 밖에서2초 준비 제한에 걸렸다. 실제 회전한 어깨 좌표를 적용한run03에서도 에스톡 공격은0이었다. estoc04는 양손 손잡이 정렬을 연결해 첫 실제 목 찌르기를 얻었다. 이전 실패 소스·입력·원자료를 그대로 보존하며 결과가 나빴던 행을 삭제하지 않는다.

입력 수명주기15·거리 구성요소11·AI8 검사를 통과했다. 기존 표적/찌르기/경로 계약도 검사했으며 자세 fixture와 명령 검사를 실제 접촉 실행에 더해 세지 않는다. 거리 준비 요청은 공격 생성/힘 단계로 세지 않고, 취소 뒤 지연 발사가 없도록 검사한다.

별도 검토에서 팔 도달 구와 광선이 만나지 않는 음수 판별식을 발견해 `armTravel=0`으로 교정했고 구성요소 반례를 추가했다. **기록한 native 회차는 수정 전 동결본도 포함한다.** 최종 소스로B7행을 다시 실행했다. 별도 대조에서9,360프레임의 native hash와 입력·실제 시작·접촉 분석·받은 피해·적용 피해·충돌이 모두 각 기준과 동일했다. 시작 후 목표 변경은0이고 AI 시도는최대2였다. 근접 레이피어·먼 에스톡의 실패도 그대로 유지됐다. 근거는 기계 판독 기록의 `final-geometry-replay.json` 영수증이다.

최종 개발 회귀6묶음은 `halfsword-distance-regression-final02`에서 소스 안정성과 함께 통과했다. 앞선 `final` 실행은 검사 도중 안내문 “받치는 힘”을 “힘 설정”으로 고쳐 `sourceStable=false`로 거부됐다. 그 실행의10결투는 개별 검사·새 실패0이었으나 유효한 전체 회귀로 세지 않고 실패 영수증을 보존했다. 회귀의 결투 실행 수는 위 거리 후보29실행에 더하지 않았다.

## 재현과 한계

[기계 판독 기록](opportunity_distance_20261009.json)에 각 실행의 정확한 명령·동결 소스 경로·전체 소스 manifest SHA·엔진 SHA·원자료29행의 크기/SHA를 연결했다. 큰 프레임 자료는 `.json.gz`로 저장소 밖에 둔다. 현재 소스의 새 재현은 다음과 같고, 과거 회차의 정확한 재현은 해당 동결 소스를 별도 검사 checkout에 복원한 뒤 기록된 argv와 입력을 사용한다.

```sh
node tools/sim/experiments/opportunity_distance_20261009.mjs /tmp/halfsword-distance-NEW thrustGuard,aiThrustOpenLow,thrustGuardEstoc --models=v3,v4 --seeds=7
```

대상 다리 제어 기능을.2/.2로 설정하고 `knockDown(false)`한 **제조 장면**이다. AI 장면의 상대는 검을 내려놓는다. 실제 엔진 접촉과 상처는 실행했지만 자발적 부상·자연 결투가 아니다. 몸 위치·속도·외력·상처 강제 주입은 하지 않았다. 한 seed의 제한된 비교로30% 성공률, 전 무기 우위, 인간 검술 최적거리, 방어 가능성 전체나 실물 폰 체감을 판정하지 않는다. 다음은 두 반례의 원인 확인과 사용자 비교이며, 실패를 없애려고 무조건 명중이나 추가 피해 보너스를 넣지 않는다.
