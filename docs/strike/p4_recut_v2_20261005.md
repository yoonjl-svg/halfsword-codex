# P4 새 기본 보정의 재베기 경계: 두 후보 기각

목표는 날 면 선택의 급반전을 고치되 강한 베기·의도된 관성을 유지하는 것이다. 기준 `e0ed9e5af85037a7bdd2644e35090a8936da9f60`, 일반 unified-r2+manual을 고정했다. 이전 rest 반구·시간 연속·planePotential/직접 토크 혼합 실패는 재활성화하지 않았다.

첫 후보는 기존 면 목표를 연속된 방향으로 이어 마지막 actual-flat 부호 재선택만 없앴다. 과거23프레임 기하에서 최대 목표 변화94.76→43.09°였지만 긴 회전 위험이 남았다. 청강검/롱소드×기준/후보 **4실행·1776step·4.106초**의 실제 게임 검사에서 생성·제어/물리 prefix·공급 입력을 맞췄다. 건강·무접촉·실제 탭 검사는 통과했으나 **효과는 기각**했다.

| 롱소드 재베기 | 기준 → 후보 |
|---|---:|
| 실제 날 면 오차 | .176 → .575rad |
| 검 축 누적 회전 | 1.196 → 3.395rad |
| 칼끝 최고속도 | 7.859 → 6.920m/s |
| 놓은 뒤 축 회전 | .883 → 1.061rad |

첫 차이 tick325의 목표·최종 요청 토크·실제 응답을 보존했다. 청강검은 의미 있는 개선 분기 노출이 없었다. 후속 한 가지인 부호불변 평면 tensor의 주축 목표도 저장 상태에서만 확인했으나, 과거 청강검 경계에서 목표 점프94.76→125.68°로 실패가 옮겨가 기각했다. 추가 물리0이며 직교/퇴화 반례도 보존했다.

**P4 src·기본값·공개판 변경 없음.** 실패 코드는 `tools/sim/experiments/p4_*`에만 남긴다. [수치·소스·재현 지도](p4_recut_v2_20261005.json)는 외부 `/workspace/halfsword-handoff/p4-recut-v2` 원자료와 frozen runtime 사본을 연결한다. `pass=true`는 계측 유효성이며 `effectAccepted=false`다. 접촉·부상·폰 수락은 검사하지 않았다.

후속 속도 원인 분리는 같은 고정 소스의 기준만333step·.752초 재현했다. 원래 native 상태/적용 pad 전부 exact이며 첫 경계19프레임을 추가 관찰했다. `driveSword`가 `trackBlade`보다 먼저여서 차분 속도를 한step(8.33ms) 더 늦게 읽는 것은 확인했다. 순간 속도는 같은 .7blade점의 `vCOM+ω×r`와 최대1.61e−6m/s 차이였다. 그러나 동일 몸 상태의 목표 재계산에서 기존 차분/최신 차분/native 속도의 최대 목표 점프는42.06/41.81/52.98°였고, 뒤 두 가지는 경계를325→324로 옮겼다. 속도 교체도 해결책으로 채택하지 않았다. 합계는 **5실행·2109step**이며 추가 기준 재현은 독립 효능 표본이 아니다. 다음 후보에 앞서 이 경계에서 의도한 재베기를 지키는 회전 경로를 정해야 한다. 지연·힘 보상으로 점프 수치만 낮추지 않는다.

**다음 최소 계약(설계만):** 첫 324→325에서 손 입력은 같은 방향인데 실제 잔여 속도가 정의한 베기 면은 달라졌다. 다음에는 실제 속도와 독립적으로, 최종 손/겨눔 명령의 동일 검 지점 변위를 검축에 수직 투영해 의도한 베기 면을 관찰한다. 명령 변위가 없거나 축 방향이면 판정을 유보한다. 명령 면 자체가 급변하거나 동작 의도와 맞지 않으면 가설을 기각한다. 명령 면은 안정적인데 잔여 운동 때문에 목표만 갈라질 때에만 활동 중 참조 후보 한 개를 검토한다. 목적은 토크 점프 숫자 축소가 아니라 명령 방향의 베기와 날 정렬을 유지하면서 불필요한 축 회전·놓기 후퇴를 막는 것이다. 롱소드 한 쌍을 통과한 뒤 청강검·짧은 접촉으로 확장하며 자연스러움은 사람의 화면 판정으로 남긴다. 이 명세 때문에 새 실행을 추가하지 않았다.
