**대표 두 무기의 연결은 통과했으며 게임 수치를 바꾸지 않는다.** 기준 `ea6b1d3`의 일반판 v2·회복·재베기·중심선 반작용·사지 절단·중력9.81을 생성부터 사용했다. 기존 수동 입력 원자료를 재생하고 실제 `strike → applyWound → onWound`와 저항 충격을 따로 기록했다.

피해 적용에는 둔격도 포함한다. 반환 콜백21/15회를 상처 수로 세지 않는다. 모든 실제 적용이 해당 타격과 콜백에 연결됐고 새 절상9개는 상처 목록·출혈에 반영됐다. 얕은 허벅지/골반 베기는 `pass=false`여도 상처 문턱을 넘었으므로 정상이다. 예측 접촉의 `passing=true`와 완전 관통·절단도 다르다.

두 실행의 native 상태는 기존 기록1,908step과 일치한다. 롱소드 관찰OFF954step도 관찰ON과 물리·입력·제어·최종 피해가 exact였다. 플레이어 중심선 충격124회 모두 두 물체의 운동에너지를 줄였으며, 예측/실측 최대 잔차는 선운동량0.000000553Ns·각운동량0.000002794Nms·에너지0.000005076J였다. 이는 해당 순간 반작용 검증이며 살 조직의 실제 절삭 에너지 입증은 아니다.

옛 기록의 상한4회는 실제 충격보다 큰 요청값으로 저항 예산을 차감했다. 적용 충격으로 바꾸면 총0.036507J 차이지만 해당 두 기록의 마지막 저항에서도 예산이 남았다. 연속 예산으로 묶은 기록이며 별도의 접촉 종료 계측은 아니다. 이번 두 무기는 저항 예산 차감 중 상한0회였다. 첫 상처는 예산 초기화 전에 이미 계산된다. 예산·접촉점 속도·실제 운동에너지 감소를 같은 양으로 취급해 피해나 힘을 보상하지 않는다. 연구용 refund 모드는 실행·채택하지 않았다.

초기 계측의 미생성 `detachedParts` 처리 오류로585/473step 두 실행이 중단됐다. 이를 보존하고 계측만 수정한 새 동결본에서 성공3실행2,862step을 얻었다. 전체 호출 완료는3,920step이며, 예외 전 이미 실행된 native2step까지 물리 적분은3,922step이다. 실패를0회로 지우지 않는다. [명령·원자료·해시·수치](phase3_cut_link_20261007.json).

한계: 실제 게임 헤드리스이지만 플레이어 감정은 harness 중립값이고 사람이 그은 입력은 아니다. 현재 절상은 절단 조건에 못 미쳤다. 기존 [절단 검사·공개 영수증](limb_default_release.json)의 통제 접촉/표현 근거를 재사용하며 자연 전투 절단을 새로 확인했다고 쓰지 않는다. 화면 표시는 별도 브라우저 기록이 기준이다. 보조팔 파지 공백·실패한 저항 후보·일괄 배율 조정은 재개하지 않는다.
