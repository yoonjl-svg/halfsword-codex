## 표시 연결을 구별한 방법

`combat.js:596–598`의 원래 상처 적용과 main hook을 순서대로 감싸 반환값을 그대로 전달했다. `fighter.js:1129`의 실제 저장 상처, `main.js:609–615`가 붙인 자국, `effects.js:309–321`의 자국 부모·종류·기하를 읽었다. 새 자국 및 실제500-instance 피/불꽃 객체의 `onAfterRender`도 원래 콜백을 호출한 뒤 기록했다. 렌더 콜백은 제출 근거이며 가려지지 않은 화면 픽셀이나 해부학적 표현 품질의 자동 판정은 아니다.

보조 `renderWindows` 수집기는 미작동했지만 위 실제 객체 콜백은 작동했다. 따라서 이 항목은 계측 한계로 분리하고 재실행하지 않았다. hook 자국의 `draw` 필드는 종료까지 누적된 객체 콜백 기록을 참조한다. hook 당시의 호출 수로 읽으면 안 되며 `firstFrame`/`lastFrame`이 관측 구간이다. 원래 실행본도 외부 자료에 그대로 보존했다.

피 OFF는 소스만 읽었다. main은 열린 상처의 피 자국 대신 멍을 붙이고, `Particles.blood`는 회색 먼지를 만들며 `drip`은 일찍 반환한다. 이를 실제 OFF 전투 검증으로 세지 않는다. 이번 입력은 실제 브라우저 touch이며 렌더링·감정·프레임 순서가 있는 일반 게임이다. 기존 화면 없는 입력 테이프의 정확한 재연이라고 주장하지 않는다.
