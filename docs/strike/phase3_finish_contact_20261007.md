# 3단계 마무리의 실제 접촉 · 10/07

현재 플레이어 설정(v2/manual·fresh·bounded·centerline, 사지 절단 ON, 중력9.81)으로 롱소드/레이피어의 실제 Rapier→Combat 접촉을 검사했다. 기준 `552accf3c2f63817d73980293339fe9b1f713e18`과 후보 두 파일을 저장소 밖에 따로 고정했다. 자연 입력8실행·20,242step에서206회의 반환 접촉이 있었지만 살아 있는 상대 down/마무리 탭은0이었다. **상대는 하인리히 외형+기본 harness AI이며 공개판의 하인리히 성격/난도와 같지 않다.** 같은 seed7의 작은 고정 집합에서 나온 미노출이며 탐색을 늘리지 않았다.

따라서 **통제된 down 준비**를 분리했다: 생성 시 `knockDown(true)`, `downTime=1e9`, 상대 AI 입력 정지, 첫0.25초 가슴/머리 각각40Ns 충격. 이후 일반 이동·실제 `skill.thrust()`·`world.step`→접촉 판정이다. 위치/속도·상처 직접 주입은 없으며 자연 전투 성공으로 세지 않는다.

|---|---:|---|
| 롱소드 판금 tick567 | 36.283 /25 /47 | 즉사 → 둔격12.440J, 생존·상처0·판금 마모 |

같은 생성·입력·접촉 전 native/controller prefix에서 나온 결과다. 롱소드 예측은tick563, 실제 접촉은567이다. 예측은 보조 질량을 실은 찌르기, 실제 갑옷 막힘은 기존 비보조 둔격으로 돌아간다. `pass=false` 자체를 막힘으로 쓰지 않는다. 마무리 접촉의 실제 반동은 롱소드 .717565Ns/레이피어1.050174Ns로 A/B 동일했다. 양쪽에 판금이 남은 범위의 결과다. 새 armorGuard에서 두 상대는1초 뒤에도 생존했다. 생사·마모 차이에 따른 native 분기는 바로 다음step부터이며 이후 동작을 단일 반작용 개선으로 부르지 않는다.

독립 감사에서 v2 적용 뒤 probe가 `autoGuard=true`로 덮은 설정 오류를 찾았다. level0이라 해당 경로는 비활성이었지만 실제 기본값false로 바로잡았다. 통제8실행 전부와 자연 롱소드/판금2실행을 재검사해 입력·native/controller·접촉 trace exact를 확인했다. 이전 원자료를 보존하고 나머지 자연6행을 재실행한 것으로 쓰지 않는다. 전체34실행·41,974step 중10실행은 이 정정 대조이며 독립 효능 표본이 아니다.

[수치·고정 소스·원자료/실행 명령](phase3_finish_contact_20261007.json)에 실패·정정·해시를 남겼다. 기존61 구성요소 근거와 이번 런타임 변경 뒤 상위 회차의61+새63 재검사는 native 실행과 구분한다. 새 armorGuard의 맨몸 문턱 이하 경계, 투구/기절·보통 사망은 이 가슴 접촉에서 새로 노출하지 않았다. 자연 마무리·폰 체감·일반 규칙 채택은 별도이며 팔/파지 유보 과제는 재개하지 않았다.
