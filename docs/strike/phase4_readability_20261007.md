# 4단계 4-2 · 기존 손상 화면의 판독성

**대표 기존 화면의 판정은 완료했다. 새 갑옷 알림은 도입하지 않으며 게임·물리·제어 변경은0이다.** 기준 `aa7ddb5c7409954fb5c2efbfc69ba08ee0b504bb`. 2회차 공개 전투의 실제 PNG와 사건 기록,3회차 부상 중단 화면, 현재 HUD 코드를 읽었다. 새 브라우저/물리 실행·영상 추출·원자료 복사는 없다. 전체 가독성이나 실물 폰 체감의 완료 판정은 아니다.

## 현재 보이는 것과 한계

- HUD는 `main.js`와 `index.html`에 있으며 별도 `src/ui.js`는 없다. 붉은 가장자리는 통증·혈액 손실·출혈 맥동을 합친다. 낮은 의식은 가장자리 자체를 흐리게 한다. 갑옷 막힘/개별 상처의 별도 문구는 없다.
- 실제 타격에는 피·먼지·상처 자국·재질별 소리·진동·카메라 반동이 있다. 기절/사망은 슬로모션 뒤 승패와 결과 메뉴의 원인 설명으로 구별한다. 이번 PNG에서 실제 기절·사망 장면을 확인한 것은 아니다.
- 2회차6.3167초 판금 타격은10.297J·심각도0·새 상처0이며3×4.86cm 긁힘을 남겼다. 기존 불꽃 조건30J를 넘지 않고 원자료 설정은 소리OFF였다. 사건 뒤 `events-03.png`에서 작은 긁힘을 확신해 식별하기 어렵다. `events-02.png`는 사건 전5.55초대이므로 이 타격의 사후 근거로 쓰지 않는다.
- 12.9583초의 실제 골반 절상은4.37×12.07cm 찢김과 번짐으로 연결됐다. `events-05.png`에서는 발밑 피가 보이나 작은 상처 선은 구별하기 어렵다. 표면 자국의 크기와 어깨 뒤 카메라에서의 몸 겹침을 함께 보아야 한다. 렌더 제출을 가려지지 않은 픽셀의 식별성으로 바꾸지 않는다.

## 짧은 갑옷 알림을 보류한 이유

처음에는 약한 갑옷 타격 뒤 약0.9초의 비수치 알림을 고려했다. 그러나 `pass=false`는 별도의 관통 문턱 판정이고, 심각도0도 갑옷이 상처를 막은 원인이라는 뜻은 아니다. `r.plate/r.helmet`은 맞은 곳의 피복 표시이며 갑옷 무시 무기에서도 참일 수 있다.

일반판 결과의 유한한 `eff/thr`, `eff <= thr`, 판금/투구 접촉, `!ignoreArmor`, 비마무리, 최종 `blunt/severity=0`을 합치면 **갑옷에 닿은 날이 상처를 열지 못했다**는 사실까지 구별할 수 있다. 통증·균형·의식에 둔격 영향이 없다는 뜻은 아니다. 원래 둔기/칼면 접촉은 `eff/thr`가 없으므로 별도로 제외한다.

**갑옷 때문에** 막혔다고 하려면 갑옷 기여를 뺀 같은 타격의 문턱보다 실효 에너지가 높고, 갑옷 포함 문턱은 넘지 못했다는 대조가 필요하다. 일반 `legacy` 결과에는 이 `bareThreshold`가 없고 문턱에 못 미친 원래 cut/stab 종류도 최종 blunt로 바뀐다. 선택형의 `armorBlocked`는 마무리 자격이 있는 찌르기에 한정되어 일반 베기 HUD에 재사용할 수 없다. UI에서 판정식을 복제하면 복잡성과 유지 비용만 늘어난다.

따라서 ‘갑옷에 막힘’이라는 인과 문구는 보류한다. 중립적인 ‘날이 들지 않음’은 현재 필드로 가능하지만, 소리OFF인 대표 한 장면만으로 새 HUD 상태·중복 억제·메뉴/재시작 정리를 추가할 가치는 입증하지 못했다. 기존 소리/반동/표면 표현을 유지한다. 무상처를 무피해로 표시하거나 자유도·힘·물리를 바꾸지 않는다. [근거 경로·해시·정확한 범위](phase4_readability_20261007.json).

## 4-3의 다음 작업 하나

**일반 URL에서 무기 선택 직후 걷기 안내와 시작 발 고정이 첫 조작 실패처럼 보이는지 확인한다.** `beginFight`는 조이스틱과 걷기 안내를 즉시 보이지만 `feetHeld`는 처음2.0시뮬레이션초 동안 보행 입력을 막는다. 팔·칼은 계속 움직인다. ‘Battle’은0.9초 벽시계 타이머이므로 느린 기기에서 발 고정과 같은 시계가 아니다. 카드 준비/뒤집기/사라짐은 별도의 프레임dt 시간이며 이 값들을 단순 합산해 실제 폰 대기시간이라고 쓰지 않는다.

기존2·3회차 공개 부상 자료는 `weapon=longsword` 고정 URL로 카드 선택을 건너뛰었다. 조작·재시작 통과를 이 시작 구간의 사용자 이해도 통과로 바꾸지 않는다. 다음 검사는 한 번의 일반 진입에서 조이스틱이 보일 때 바로 걷기를 요청해 실제 이동 가능 시점과 안내를 대조하는 정도면 된다. 시작2초 고정과 소개 카메라는 기존 사용자 지정이므로 단축·삭제부터 하지 않는다. 현재는 소스상 오해 가능성을 찾았을 뿐 실제 첫 플레이 결함이나 과도한 대기를 입증하지 않았다.
