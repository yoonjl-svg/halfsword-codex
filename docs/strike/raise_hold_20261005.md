# P1/P3 · 현재 검술 보정의 올림과 버팀

**두 무기의 올림에서 중력이 실제로 반대 일을 하고, 버티는 동안에도 관절의 지지 토크가 남는 것을 확인했다.** 이번 관측만으로 바꿔야 할 결함은 나오지 않아 게임 수정 없이 닫는다. P1의 사람 체감·P3의 전신 native 힘 전달 전체 완료는 아니다. [수치·원자료 SHA·재현 명령](raise_hold_20261005.json).

기준 `c37220e520bc145719967406e15364646e769798`; 실행 사본의 HEAD는 문서만 추가된 `2e40b888d0607ed575f8d0256c0d269a4fe351af`이며 게임·harness·ledger·lockfile 차이 0과 실행 중 소스·의존성 SHA 고정을 확인했다. 실제 일반 Rapier 게임에서 플레이어에 현재 `unified-r2`와 manual 팔을 적용했다. seed 7, 롱소드/츠바이핸더, 기존 paired 보조손, 기존 절삭, 정상 중력·힘·모터 유지. 상대는 원래 AI이며 초기 간격만 14m인 무접촉 관측이다.

실제 입력 이벤트로 .5초 준비 → .75초 동안 손 패드 y를 +.40m → 1.5초 계속 누르고 멈췄다. 올림 90step은 모두 active/moving, 버팀은 모두 held/holding이며 양손 그립을 유지했다. 이는 제어된 올림이고 빠른 올려베기가 아니다(`swinging=0`). 버팀의 처음 .5초는 별도 정착 자료로 남기고 마지막 1초를 표에 썼다. 이전 [내려베기 원자료](v2_weight_work_20261005.md)는 재사용만 했으며, 서로 다른 일정의 위/아래 동작을 동일 조건 비교로 부르지 않는다.

| 실제 구간 | 검 COM 높이 변화 | 검에 한 중력 일 | 어깨 토크 RMS | 팔꿈치 중력보상 RMS | 검에 직접 준 손목 토크 RMS |
|---|---:|---:|---:|---:|---:|
| 롱소드 올림 .75초 | +.357m | −5.60J | 22.42Nm | 7.14Nm | 6.86Nm |
| 츠바이핸더 올림 .75초 | +.385m | −10.96J | 33.65Nm | 13.47Nm | 14.28Nm |
| 롱소드 버팀 1초 | −.013m | +.21J | 10.13Nm | 3.67Nm | 4.95Nm |
| 츠바이핸더 버팀 1초 | −.025m | +.71J | 18.37Nm | 7.52Nm | 10.47Nm |

버팀에서 검 COM 평균 속도는 .056/.097m/s, 손 목표 오차 평균은 3.03/3.32cm였다. 완전 정지는 아니지만 작은 이동에도 토크가 계속 필요했다. 일(J)이 작다고 지지 부담이 없다는 뜻은 아니다. 이 수치로 사람의 힘듦·피로를 측정하지는 않았다. 무기들은 질량뿐 아니라 길이·자세·제어값도 달라 차이 전부를 질량 효과로 돌릴 수 없다.

명시적으로 기록한 경로는 다음과 같다. 일은 물리 스텝 전후 속도의 중간값을 쓴 근사 적분이며, 호출 순간 속도 적분도 JSON에 별도로 남겼다.

| 경로와 실제 반작용 | 올림 중 경로 전체 순일: 롱소드 / 츠바이핸더 |
|---|---:|
| [어깨 직접 토크](../../src/fighter.js#L1941): 상완에 주고 흉곽에 반대 토크 | +11.18 / +18.18J |
| [팔꿈치 중력보상](../../src/fighter.js#L1924): 전완에 주고 상완에 반대 토크 | +4.62 / +8.58J |
| [손목 최종 토크](../../src/fighter.js#L2185): 검에 주고 전완·흉곽에 나눠 반대 토크 | −2.54 / −6.86J |
| [보조손](../../src/fighter.js#L2273): 공통점에서 검·반대 전완에 ±힘 | −.59 / −.89J |

손목은 검 자체에 +1.07/+2.32J를 주었지만, 전완·흉곽에 한 일까지 더하면 위처럼 음수가 된다. 각 경로의 힘·고정 원점 기준 토크 합은 계산 정밀도 안에서 0이었다(최대 순토크 약 5.4e−14Nm). **짝 반작용이 존재한다는 확인이지 전신 에너지 보존이나 수동 전달의 증명은 아니다.** 능동 제어 경로는 내부 일을 할 수 있다. native 팔꿈치 추종·반대 팔·척추 모터, 주손 구속, 감쇠와 지면 지지의 일은 측정하지 않았으며 검 운동에너지 잔차를 몸통의 기여로 계산하지 않았다. `gravityTorque` 원 반환값도 최종 제한 뒤 실제 보상분과 구분했다.

실제 비용은 **3실행·661step·물리 실행 2.43초**: 첫 시도는 tick 0 물성 고정 assertion에서 1step 후 중단했고, 정정한 2실행에서 4개 분석 구간을 얻었다. 정정 raw가 주팔 상완/전완의 첫 관성 초기화를 직접 기록했다. 준비 60step은 분석에서 제외하고 이후 올림/버팀의 물성 고정을 검사했다. 발의 가변 질량은 상체 분석 경계 밖이다. 실패 원자료는 그대로 보존했고, 첫 native snapshot은 실패/정정 실행 간 exact였다. 모든 입력·건강·무접촉·측정 구간 물성 관문 및 frozen 소스 해시는 통과했다. 관찰자 설치 전후 snapshot도 exact지만 새 observer-off 전체 궤적 검사는 반복하지 않았다.

새 후보·힘 보상 변경·기존 내려베기 재실행은 0이다. 이번으로 올림/버팀의 **관측 공백**은 닫는다. 다음은 실제 조작에서 무게/지지 결함이 드러났을 때 이 관절별 기록으로 좁혀 판단하는 것이며, 전신 전달을 주장하려면 누락된 native 관절의 실제 충격량/일을 직접 확인해야 한다. 당장 중력 보상 제거·가슴 추종·모터/gain 실패안을 다시 켤 근거는 없다.
