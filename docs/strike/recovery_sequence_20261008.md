# 기립 다리 순서 후보 · 10/08

**5개 후보를 실제 게임 코드로 비교했으나 모두 미채택했다.** 다리 순서, 발의 접점과 회전, 골반 높이 진행까지 연결했지만 지지 상실·미끄럼·기립 지연의 후퇴가 남았다. 실패한 후보를 활성화할 runtime 연결은 제거하고 정확한 실행 소스는 저장소 밖 frozen 경로에 보존한다. 내려찍기 개선과 이 기립 후보의 판정을 혼동하지 않는다.

기준 `4b010726c6e234de072786dbea7073eb1ccd36cc`. [전체 요약·명령·raw SHA](recovery_sequence_20261008.json). raw root는 `/workspace/halfsword-handoff/recovery-finish-fix-20261008/recovery/`다. r1–r5 각각 위 기준 HEAD 소스에 해당 회차의 fighter/helper/probe만 덧씌운 별도 runtime에서 실행했다. 병행 작업인 내려찍기의 변경 중 소스를 불러오지 않았다.

## 무엇을 바꾸고 비교했나

- r1: 지지발의 월드 발목을 기억하고 하중 수용 후 뒤발을 놓는 목표 순서. 기존 골반 높이곡선은 유지했다. 뒤발이 높은 발목 위치로 발끝 접촉한 순간 그 위치를 고정하고 발을 평평하게 요구하여 공중발이 늘었다.
- r2: 실제 지지발 회전을 보존하고 뒤발의 평평한 목표를 일치시켰다. 기존 무릎 준비의 마지막 구간부터 배치했다. 미끄럼·상향속도 후퇴와 지지발 상실이 남았다. 실패 순간 목표의 한 프레임 점프도 확인했다.
- r3: 무릎 목표와 골반 높이 진행을 같은 회복 단계로 묶고 도달 가능한 높이를 사용했다. 기존 힘 계산식·근력·중력·native 엔진은 유지했다. 배치 목표의 오차 문턱 때문에 실제 하중이 있어도 준비 자세에서 대기했다. 자연 장면은 기립 전 재피격 사망, 준비 장면은 시간초과 또는 지지 상실 후 복귀했다.
- r4: 요청 지점과 정확히 같지 않아도 실제 지속 접촉·양의 누적 충격량·다리 도달성을 갖춘 발의 현재 위치와 회전을 인계했다. 실패 시 높이 목표도 부드럽게 복귀하고 수평 도달 불가를 별도로 처리했다. 한 옆넘어짐의 실제 양발 인계는 이루어졌지만 다른 조건의 실패와 미끄럼 후퇴가 남았다.
- r5: 별도 대안으로 기존 Gait의 sense/plantAt/begin/target/pinFeet/poseLegs를 후반 getup에 재사용했다. 보행 active는 끄고 기존 무릎·골반 진행과 stand 시간을 유지했다. enter/update/touchdown과 질량 변경은 사용하지 않았다. 기존 마찰 한도 발 유지와 반대 방향 swingPull 힘이 포함되므로 목표만 바꾼 실험은 아니다. 뒤발 접촉의 부분 개선에 비해 앞 지지발의 접촉 상실이 네 조건 모두 늘었다.

4조건×5후보×baseline/candidate = **40실행·56,290 native step**이다. 같은 baseline의 반복을 독립 효능 표본으로 더하지 않는다. 모든 회차의 baseline 궤적은 조건별로 exact이며 자연 조건의 첫1,913step은 이전 현재 일반판 진단과도 exact다. 실행 전후 소스해시는 모두 동일했다.

## 보존·재현

`r1/runtime`부터 `r5/runtime`의 SOURCE.json, 실제 fighter/helper/probe와20개 결과의 실행 전후 해시를 대조했다. `candidate-preservation.json`에 일치 결과를 보존한 뒤 게임 runtime hook와 src helper를 제거했다. fighter.js와 gait.js는 위 기준 HEAD와 byte-identical이며 삭제 전 다섯 후보의 정확한 소스 보존을 확인했다. 저장소 도구는 외부 frozen source만 실행하는 launcher로, 반드시 `--source`를 지정해야 한다.

```sh
node tools/sim/experiments/recovery_sequence_20261008_probe.mjs \
  --source=/workspace/halfsword-handoff/recovery-finish-fix-20261008/recovery/r5/runtime \
  --mode=natural --out=/tmp/recovery-r5-fresh
```

raw의 `observed`는 baseline, `replay`는 실제 plant 후보다. 관찰OFF 동등성 실행이 아니다. r1 terminal의 `one_second` 문구는 실제240step=2초와 어긋난 옛 설명이고, 준비 조건에 대한 옛 metadata 문구도 위 계약으로 정정했다. frozen runtime에는 당시 실제 실행한 전체 probe가 남아 있다. 저장소 launcher는 `--validate-only`로 r5 manifest의 462개 파일을 검증했으며 이 검증의 native 실행 수는 0이다. 정리 뒤 새 native 실행이나 공개 폰 검증을 추가로 하지 않았다.
