# 유보한 잔여 회전의 후속 판정 · 2026-10-07

사용자가 한도 추가 후 유보 검증의 완료를 요청했다. 기준은 일반판 `f395a13`의 검술 보정 v2·회복 fresh·재베기 bounded·날 무기 centerline·팔다리 절단 ON·중력9.81이다. [기존 공통 적용 검사](common_defaults_20261007.md)의 입력과 정상 AI 접근을 그대로 재사용했다. 게임 소스는 수정하지 않았다.

## 결론

1. 세이버의 전투 최고 각속도40.76→91.92rad/s는 서로 다른 접촉의 최고치였다. bounded의 지속 가속 오류로 판정할 수 없다. 이전 정책의 최고는 첫 베기 tick582의 검끼리 접촉, 일반 정책의 최고는 tick700의 상대 머리 접촉이다. 실제 native 충돌이 얇은 칼축을 가속하며, 기존 손아귀 처리의 적용 대상도 검끼리 새 접촉과 신체 접촉에서 다르다.
2. 세이버·모노호시자오의 release 끝 각속도 증가는 **복귀 도중 한 시점**이었다. 같은 입력을 끝낸 뒤2초만 연장하자 양쪽 모두 안정됐다. 이 표본에서 지속적인 팽이 회전으로 이어지지 않았으므로 정상 복귀·관성을 줄이는 새 감쇠를 추가하지 않는다.
3. 기존 손아귀 처리의 신체 접촉 확대를 runtime 후보로 한 번 검토했지만 **일반판에 적용하지 않는다.** 한 스텝 뒤 각속도는 줄여도 이미 적분된 회전각을 되돌리지 못하며, 기존 근사의 각운동량 소실을 확대한다. 속도 최고치가 작아졌다는 이유만으로 더 사실적이라고 판단하지 않는다.

## 실제 발생 순서

정상 접근은 이전과 같은 tick423에444step 입력을 시작한다. 두 정책의 생성·입력이 같고, 첫 native 분기는 tick560의 첫 베기 목표 제한이다. AI 출력의 첫 수치 차이는 tick571이며, 접촉과 후속 판단이 분기한다. 따라서 tick700의 다른 접촉 최고치를 같은 상태에서 보정만 바꾼 인과 효과라고 부르지 않는다.

| 장면 | native 계산 전/후 전체 각속도 | Combat 후 | 실제 맥락 |
|---|---:|---:|---|
| 이전 정책 tick582 | 7.34→116.26 | 40.76 | 검끼리 충격3.458N·s, 기존 gripTwist가 축 성분115.99→40으로 제한 |
| 일반 정책 tick700 | 9.82→91.91 | 91.92 | 머리 충격3.461N·s, 축 성분−91.89, 횡방향 성분2.44 |

tick700에서 bounded 목표 제한은 개입하지 않았고 실제 면·목표 내적은0.992였다. 목표가90° 반대편에 남아 가속한다는 가설은 이 최고치에서 지지되지 않았다. 자유 입력3종의 일반 정책에서도 음의 면·목표 내적은0회였다. 다른 장면까지 해당 가설이 불가능하다는 증명은 아니다.

일반 정책의 |축 각속도|40.01 초과는 tick700의1step뿐이다. 다음step 전체 각속도는8.48rad/s로 돌아온다. native 전후 실제 자세 차이는0.512rad(29.34°)다. 관측 구간40.01은 기존40 규칙 근처를 세는 기록용 값이며 새 게임 한도가 아니다.

세이버·모노호시자오·라이트세이버의 주관성 프레임은 identity였고, 칼 길이축의 실제 유효 관성과 `pI.y`가 일치했다. 세이버 `I_y=0.0001010576743kg·m²`, `twistScale=0.0996918954`다. 이 세 생성 상태에서 관성축 선택 오류는 없었다.

## 놓은 뒤 연장 검사

원래444step까지 native 상태가 기존 자유 입력 검사와 매step 일치한다. 이후 손을 놓고 이동0을2초 유지했다. 생성 v2 보류 대상인 모노호시자오에 v2를 켜지 않았다.

| 무기 | 이전/일반, 기존 끝 각속도 | 연장 마지막1초 평균 각속도 | 연장 끝 |
|---|---:|---:|---:|
| 세이버 | 2.26 / 10.57 | 0.685 / 0.684 | 0.679 / 0.680 |
| 모노호시자오 | 3.72 / 16.79 | 0.00805 / 0.00808 | 양쪽 약0.002 |

세이버는 기존 끝에서 v2 `returning`, 이후 `ready`로 전환했다. 마지막1초 평균 |축 각속도|도0.12153/0.12221rad/s로 비슷했다. 모노호시자오 역시 복귀가 진행된 뒤 가라앉았다. 짧은 선택 장면의 지속 회전 우려를 해소한 것이며 인간 움직임·전체 무기·장기 전투의 수락은 아니다.

## 보존한 runtime 후보

원래 `rebound()` 실행 후, 새 비관통 신체 접촉이고 무장·cache가 있는 경우에만 기존 `gripTwist`와 같은 `max(충돌 전 축속도,40)` 규칙을 복제했다. 힘·일반 입력·피해식·전구간 속도 제한을 새로 만들지 않았다. 실패한 힘점·implicit grip 후보를 재사용하지 않았다.

일반 정책은 원판과 tick0–699 native가 완전히 같았다. tick700의 정상 무장 세이버/머리 신규 접촉에서1회 개입했다. 같은 호출이 rebound 결과를 새로 할당했는지 객체 identity와 접촉 key로 확인했다. cached 피해16.986976J·severity0 및 원래 반발 충격0.230547N·s는 동일하다. 그 뒤 축속도−91.8879→−40, 횡방향 각속도2.44253은 유지됐고 전체 최고는91.920→40.656으로 감소했다.

그러나 이미 적분된29.34° 회전은 그대로다. 제거한 축 각운동량을 팔·몸에 옮기지 않는 기존 `setAngvel` 근사를 넓히는 한계가 있다. 이후 입력·상대 반응과 피해는 달라졌다. 칼끝 중심선 속도의 동일성도 실제 절삭 위력 불변을 보장하지 않는다. **연구 보존, 일반 적용 없음**으로 판정한다. 새로운 신체 접촉 근사를 기본 승격하거나 기존 bounded를 되돌릴 근거로 사용하지 않는다.

## 재현과 기록 품질

- `node tools/sim/experiments/spin_followup_20261007.mjs --out=/absolute/fresh/contact --contact`
- 같은 명령에서 `--contact`를 생략하면 자유 입력3종, `--settle`이면 세이버·모노호시자오2초 연장.
- 보존 후보만 실행: `SPIN_CANDIDATE=body-grip node ... --out=/absolute/fresh/candidate --contact`.

read-only 관측2행은 원래 도구의 관측 없는2행과 native 전체 trace SHA가 정확히 일치했다. 토크 재구성은 생산 WeakMap 함수를 추가 호출하지 않으며 실제 `addTorque`와의 최대 오차1.33e-7N·m이다. 모든 완료 실행의 sourceStable을 확인했다. 초기 도구의 함수 이름 충돌2step 실패와 배열 투영 오류가 있던 torque 표본은 폐기 사유를 남기고 새 파일에 정정했다. native 표본을 숨기거나 성공 행으로 덮어쓰지 않았다.

[집계·원자료 SHA·소스 경계](spin_followup_20261007.json)에 실패·반복 대조·후보 재검사를 포함한 실제 실행 수를 남겼다. 이 수는 독립 전투 조건 수가 아니다. 게임/브라우저/배포는 변경하지 않았으며 이번의 끝은 원인 판별과 후보의 적용 여부 결정이다.
