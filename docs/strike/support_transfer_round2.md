## 목적과 구현

중력·체중·관성을 전신 타격으로 전달하려면 몸을 떠받치는 힘의 출처부터 바로잡아야 한다. 이번에는 높이 목표·기립 시간을 일괄 바꾸지 않고, 직접 수직 골반 힘을 접촉한 발과 골반 사이의 내부 힘쌍으로 옮겼다. 충분한 힘이 없을 때 부족분을 다른 외력으로 채우지 않는다.

- `support_contacts.js`: 발·정강이·빈손 전완의 실제 환경 접촉을 읽는다. 고정/kinematic 환경과 선수·동적 물체·센서·떨어진 팔다리를 구분하고, 예측 접촉·이동/삭제 뒤 낡은 접촉을 지지에서 제외한다. raw 충격량, 법선, solver 점은 별개 근거이며 임의 하중 보정을 적용하지 않는다.
- `support_transfer.js`: 현재 고관절/발목 앵커를 잇는 방향 `n`에서 골반에 `+Tn`, 발에 `−Tn`을 적용한다. 같은 직선의 반대 힘이므로 이 경로의 적용 순힘과 순토크는 0이다. 순간 일률은 `Tn·(vHip−vAnkle)`로 기록한다. 이는 **가상 다리 액추에이터**이며 실제 근육·관절 토크 모델 완성을 뜻하지 않는다.
- `T`는 기존 힘 요구 상한을 접촉한 다리의 하중 비중과 기능 값으로 나눈 용량 안에서 포화시킨다. 거의 수평인 다리에 큰 힘을 무한대로 주지 않는다. 부상 기능 값은 용량도 낮추며 정규화 과정에서 사라지지 않는다. 이 상한은 신규 경로만의 상한이며 기존 PD까지 합친 인간 근력 예산이 아니다.
- 발 지지가 없으면 수평 직접 구동과 발 고정 보조를 끈다. 발·정강이·전완 지지가 모두 없으면 kinematic 직립 보조의 강성/감쇠도 0이다. 절단으로 지지를 중단할 때 새 관찰 기록도 초기화한다.

지면이 있을 때의 수평 직접 구동, 발 고정 보조, kinematic 직립 보조, 기존 관절 PD와 움직이는 발 제어는 남아 있다. 이 후보가 지면 반력만으로 완성된 사람 몸, 완전한 에너지 보존계, 전신 강타 구현이라는 주장은 하지 않는다. 손가락/손 강체가 없으므로 빈손 전완 접촉을 손가락 힘으로 부르지 않는다.

## 먼저 기각한 경로

실제 legacy 제어의 수직 힘을 제거하고 관절별 `τ=JᵀF`로만 옮긴 초기 탐색은 기립에 실패했다. 8초 뒤 골반 높이 0.4393m, 추가 토크 최대 1,525.39Nm였고 960프레임 중 getup이 722프레임, stand가 238프레임이었다. 기존 PD와의 분담·합산 토크 제한 없이 수직 요구를 관절에 복사하는 방식은 채택하지 않았다. 이는 모든 관절 토크 기반 제어가 불가능하다는 증거가 아니다.

같은 탐색의 축 방향 힘쌍은 8초 뒤 0.8861m로 회복했다. 이 탐색은 기존 바닥 충격량으로 배분하고 부상/실접촉 제한이 덜한 초기 코드다. 출시 후보의 수치와 혼합하지 않는다. [탐색 코드·명령](../../tools/sim/experiments/README.md)의 vmc/axial/legacy를 현재 독립 소스에서 재실행해 최초 수치를 재현했다.

## 검증 원칙과 명령

정식 비교는 같은 seed7, B .1/on/1, paired, 롱소드, 실제 harness를 사용한다. 3초 legacy 준비 상태와 입력 SHA가 쌍마다 같고, 그 뒤 지지 방식만 바꾼다. 기립은 강체 순간이동이 아니라 실제 `knockDown(false)`로 시작한다. 한쪽 .45 / 양쪽 .2 손상은 합성 기능 값이며 실제 부상자의 재현으로 부르지 않는다. 바닥 제거는 실제 collider를 제거한다. 상대만 준비 단계에서 park한다.

```sh
node tools/sim/support_contacts.test.mjs /tmp/support-contacts.json
node tools/sim/support_transfer.test.mjs /tmp/support-forces.json
node tools/sim/support_transfer_probe.mjs --models=legacy,axial --seed=7 --ledger=1 --out=/tmp/support-transfer.json
node tools/sim/grip_reaction.test.mjs /tmp/grip-reaction.json
node tools/sim/support_transfer_duel.mjs --models=legacy,axial --seed=17 --out=/tmp/support-duel.json
```

`stand` 상태 진입과 실제로 높이·기울기·발 접촉을 회복한 시점을 구분한다. 관찰 문턱은 기존 게임의 `hNom−catchSag`, `fallTiltDeg`를 쓰며 새 인간 판정 문턱으로 게임 제어에 넣지 않는다. 기존 기립 넘겨받기 `levH` 종료 뒤도 관찰한다. 몸의 질량/COM/운동량/에너지, 실제 solver 접촉점 상대 속도, 관절 앵커 간격, 적용 외력과 내부 힘을 기록한다. native 관절/접촉 일과 변하는 발 추가 질량 때문에 완전한 일·에너지 장부를 닫았다고 주장하지 않는다.

## 공개 확인 동안 계속한 원인 분리

지지 판정 변화와 내부 힘 전달의 영향을 나누기 위해 전진6초의 A(legacy)/B(axial)/C(접촉·용량은 B 그대로, 내부 힘쌍을 제거하고 그 수직합만 골반 외력으로 치환)를 실행했다. **C는 진단 전용이며 공개 게임에 없다.** 같은 시작/입력, A/B 기존 trace exact, 전후 소스 동일, 모든 몸 유한을 확인했다.

실제 지지 stance 점속도 평균/p95/최대(m/s)는 A .04239/.23322/1.27955, B .07225/.55637/1.40847, C .05167/.32332/2.25853이었다. 순전진은13.357/12.366/13.541m다. C는 평균/p95를 일부 되돌리지만 최대값은 세 조건 중 가장 나빠 채택하지 않는다. 캡처한 양의 수직력과 원래 actuator 기록의 차이는 매 step0이고 내부 쌍 순힘0·순모멘트 최대2.28e-13Nm였다.

이 결과는 접촉 판정만으로 후퇴를 설명하기 어렵고 내부 힘 경로도 관여한다는 근거다. C는 수평 성분·골반 모멘트·발 부하·총외력을 함께 바꾸며 폐루프 수직 요구도 달라진다. 특정 항 하나의 인과나 해법을 확정하지 않는다. [결과/해시](support_pair_cause_metrics.json)와 [진단 재현](../../tools/sim/experiments/README.md)을 보존하고, 다음은 반작용의 수평 성분·골반 모멘트·접촉 하중의 기여를 더 분리한다.

## 다음 경로

이번 후보의 사용자 플레이 평가와 별개로, 지면이 있을 때 남는 수평 추진·직립 보조의 일과 검의 반작용을 분리한다. 이어 실제 가슴 회전과 세계 손 목표의 충돌을 같은 입력/힘 예산에서 측정한다. 손목 힘이나 피해 배율 증량을 온몸 타격의 대체물로 쓰지 않는다. 큰 지지 변경의 일반 적용은 비교 가능한 결과와 사용자 확인 뒤에 한다.
