**기존 한손 교정을 유지하면서 양손 회복의 보조 어깨 계산과 전완–몸통 통과를 교정한다. 라이트세이버는 실제 입력 중 공격 후퇴 때문에 예외로 남긴다.** 기준 HEAD `4201801de1d0ada0604ea7a5bdb00098bc5042be`. 사용자의 팔 뒤틀림 개선·계속 진행 지시 범위다. 공개 전달은 [영수증](twohand_recovery_release.json)을 따르며, 아래 검사는 전신 자연스러움·모든 관통의 해결을 뜻하지 않는다.

## 원인과 선택한 교정

1. 보조 어깨는 native 구면 모터인데 앱은 회전벡터 성분을 목표 위치로 전달했다. 실제 npm Rapier0.19.3은 canonical quaternion 각 성분의 `2 asin(q_i)`를 읽는다. 다축 2.3rad 단독 API 대조에서 기존 요청은 목표 각도 오차 .8213rad를 남겼고 올바른 좌표 요청은 .0000159rad까지 수렴했다. 부모 관절축에 맞춘 quaternion 목표 차분으로 속도를 전달하고 ±π 위치 차는 최단 방향으로 감싼다. 이 수정은 identity native frame을 사용하는 보조 어깨에만 연결한다.
2. 기울어진 몸의 뒤로 들어간 주팔 손 목표에는 기존 .16m 전방 여유와 목표 복귀까지의 인계를 양손에도 연결한다. 이 수치는 팔 전체 비관통이나 해부학 한계가 아니다. 길이 제한 뒤의 팔꿈치 경로는 손 목표만으로 안전해지지 않는다.
3. 낮은 근육 활성으로 팔이 떨어질 때 전완이 자기 몸통을 통과했다. 각 검객의 **전완2개×가슴·배·골반3개, 비인접6쌍만** native 충돌을 허용한다. 연결된 상완–가슴, 자기 칼, 자기 다리, 다른 검객/바닥의 기존 접촉은 바꾸지 않는다. 위치/속도 대입, 중력·근력·피해 계수 변경은 없다.

적용 기준은 `twoHand` 공통 기능이다. 현재 라이트세이버만 실측 예외다. 일반 보조팔 부상·절단 규칙, 파지 상한과 이전 한손 회복 교정은 유지한다. 자기 접촉은 Combat의 자기 피해 제외를 통과하며 절단된 팔의 충돌 그룹은 기존 파편 그룹으로 돌아간다.

## 공격·예외 판정

기존 보조팔 검사의 실제 수동 입력을 재사용했다. 롱소드·츠바이핸더·모노호시자오·라이트세이버 각각 건강/보조 전완 절단의 기준/후보16실행, 라이트 모터만의 원인 분리1실행을 독립 검토했다. 라이트는 현재 일반 legacy 정책, 모노는 일반 v2 정책으로 구분했다. 전원 유한값·생존/무장·stand, 정상 파지 유지와 절단 후 파지0, 관절 간격 최대2.16mm를 확인했다.

앞의 일반 채택3종의 첫/역/재베기＋hold 창 정점 속도 변화는 −2.52~＋9.44%, 무기 운동에너지는 −1.42~＋8.54%였다. 첫 베기 속도는 롱소드10.54→11.18, 츠바이핸더8.18→8.97m/s였다. 이 비접촉 검사는 모든 실제 타격 피해 불변을 보증하지 않는다.

나머지 에스톡·엑스칼리버·모조·참치도 건강 조건8실행을 추가했다. 모두 생존/stand/파지·유한값을 유지했고 관절 간격 최대2.05mm였다. 에스톡 역베기 입력 최대 속도는 −2.76%, 에너지는 −5.95%이고 첫/재베기는 증가했다. 엑스칼리버 계열 에너지 감소 최대 −1.82%, 참치 입력 창 속도/에너지는 상승했다. 전 공격 무감소를 선언하지 않으며 에스톡 주력 찌르기 접촉 피해는 이 베기 테이프의 범위 밖이다.

라이트세이버 실제 재베기 입력 창은 속도19.20→17.19m/s, 운동에너지14.08→12.24J로 줄었다. 역베기 정점도 입력 중이며 여러 프레임에 걸쳐 감소했다. 옛 단발 오류 급등이나 잔여 운동 정리로 설명할 근거가 없어 **일반 적용에서 제외**했다. 모터만의 분리에서도 재베기 입력 일부 감소가 있어 전완 충돌만 제외하는 것으로 우회하지 않는다. 주팔 목표·모터·자기 접촉 세 경로 모두 기존값을 보존한다. 힘 가중치로 덮지 않았고 현재 예외의 개선은 후속 과제다.
