# 전신 타격 제어 2차: 몸통 목표와 중력 보상을 분리

2026-10-02. [전체 P-01~P-06](physical_realism_plan.md)를 유지하면서 기립 연구와 병행했다. **가슴 회전을 그대로 따라가거나 수평 회전만 따라가는 후보, 중력 보상을 일괄 제거하는 후보 모두 일반 적용하지 않는다.** 실제 게임의 횡베기 속도 변화는 확인했지만 내려베기·목표 오차·입력 종료 후 제동까지 좋아지는 해법은 아니었다. 전신 강타의 해결 완료가 아니다.

## 실행 범위와 대조

기준 게임 소스는 `ca0809d098cbcb2b8526e94d0550ac526f3a9529`. 첫 42행을 실행한 도구와 전체 목표 추적표는 `566bd78`에 보존했다. 그 뒤 yaw 후보를 추가한 48행과 6검사를 수행했다. 정확한 실행별 소스 해시·전후 일치·원자료 해시·요약은 [metrics](whole_body_control_round2_metrics.json)에 있다. 원자료 파일은 작업공간 `halfsword-hybrid-evidence`에 있고 요약은 저장소에 보존한다.

- 실제 `G.step`·Rapier·Fighter·손 입력 경로를 사용한다. 상대 없는 롱소드/츠바이핸더 내려베기·올려베기·횡베기이며 충돌 시험은 아니다.
- 준비 3초의 legacy 그립은 기존 프로토콜을 유지한다. 측정 구간은 모든 조건에서 paired 그립·legacy 지지·받침 0.3·세계 중력 −9.81이다. 준비 후 native snapshot, 제어 상태, 입력 요청이 같다.
- 0.55초 입력 후 1.2초를 관찰한다. `release`도 자동 복귀 제어가 살아 있으며 자유 회전이 아니다. `target_hold`는 손 목표를 계속 유지하는 별도 조건이다.
- 42행: 무기 2 × 방향 3 × baseline/복제/full 가슴/세 보상 전체 제거/어깨만/팔꿈치만/손목만 제거. 48행: 무기 2 × 방향 3 × release/hold × baseline/복제/full/yaw.
- 관찰기 없음↔있음, 실제 원본↔미변경 복제 궤적이 일치했다. 모든 후보의 실제 dispatch를 확인했다. 반복된 18행도 두 배치의 궤적이 정확히 같았다. 따라서 90개의 독립 표본으로 계산하지 않는다.

가슴 후보는 체크포인트에서 목표 연속성을 맞춘 뒤 상대적인 가슴 회전을 손 목표·검 방향·대기 자세 목표에 전달한다. 준비 자세는 숙여질 수 있으므로 이 기준을 해부학적 중립이라고 부르지 않는다. yaw 후보는 수평 회전만 전달하며 수직 축 특이점에서는 기존 heading으로 돌아간다. 찌르기·마무리·총 조준은 기존 월드 조준을 유지한다. 실제 관절 구동·근력 한도·보상량은 바꾸지 않았다.

## 내려베기 중력은 일하고 있지만 제어 변경의 효과는 방향마다 다르다

아래 속도는 **입력 중 0.55초의 최대 칼끝 속도(m/s)**다. 관찰 전체 최고속도와 구별한다. 중력 일은 baseline 검의 실제 COM 위치에 따른 위치에너지 감소이며 같은 검 질량을 사용한다.

| 무기 / 입력 | 기준 | 가슴 전체 | 가슴 yaw | 중력 보상 전체 off | 기준 검 중력 일(J) |
|---|---:|---:|---:|---:|---:|
| longsword / down | 17.542 | 15.508 | 15.460 | 17.002 | +21.52 |
| longsword / up | 13.705 | 12.059 | 12.377 | 14.150 | −13.33 |
| longsword / cross | 14.769 | 18.764 | 17.542 | 14.620 | +13.68 |
| zweihander / down | 16.932 | 15.821 | 15.622 | 17.367 | +29.83 |
| zweihander / up | 10.143 | 9.511 | 9.847 | 9.758 | −18.24 |

중력 보상 off는 세계 중력을 지운 것이 아니다. 실제 `gravityTorque`의 어깨·팔꿈치·손목 반환값만 0으로 바꾼다. 구동 PD·별도 토크·native 모터는 남는다. 내려베기의 중력 이점이 사용자의 손에 충분히 느껴지는지는 이 표로 확정할 수 없다. 서로 다른 무기를 같은 질량 분포에서 질량만 바꾼 인과 실험으로 취급하지도 않는다.

## 횡베기 속도 증가만으로 채택할 수 없는 이유

full/yaw 모두 횡베기 속도를 높였지만 내려베기는 느려졌다. 롱소드 내려베기의 최대 손 목표 오차는 기준 0.371m에서 full 0.499m, yaw 0.498m로 커졌다. 같은 조건 실제 지지 접촉점의 최대 수평 상대속도도 약 0.012→0.060/0.054m/s로 증가했다. 모든 행에서 stand 상태는 유지했지만 그것이 자세 품질 합격은 아니다.

횡베기 입력 종료 후 검 축의 누적 이동각은 release에서 롱소드 3.67→4.40/4.07rad, 츠바이핸더 3.21→4.61/4.21rad였다. hold에서도 롱소드 1.45→2.33/2.04rad, 츠바이핸더 1.38→2.09/2.12rad로 커졌다. 이는 회전축 궤적의 누적 길이이지 순 회전량·정지 거리·사람의 회복 시간과 같지 않다.

명시적 어깨 `manualMuscle` 경로도 변했다. 롱소드 횡베기의 입력 중 순 일은 약 −1.80→+36.84J, 츠바이핸더는 −19.07→+31.12J였다. 가슴과 상완 각 몫도 요약에 보존했다. 더 큰 근육 일이 들어가므로 속도 상승을 ‘같은 힘으로 몸통의 에너지만 더 잘 전달한 결과’라고 할 수 없다. 다음 후보는 이 추가 일과 제동 부담을 동시에 다뤄야 한다.

## 계측 한계와 다음 구현

- native 모터·관절 제약·완전한 접촉 일을 아직 분리하지 못했다. 운동량 잔차를 native의 실제 힘 측정값이라 부르지 않는다. 총 질량에는 발 추가 질량 변화도 남는다.
- `byPath.positiveWorkApproxJ/negativeWorkApproxJ`는 스텝별 **경로의 순 일**을 양/음으로 나눈 누적이다. 개별 근육 양의 일의 총합과 다르다. 몸 전체 중력 일은 중점 속도 근사이고, 위 검 중력 일은 실제 위치에너지 차이다.
- raw `bodyPJ` 필드는 이름과 달리 선운동량 벡터(kg·m/s)다. 최대 손 목표 오차는 실제 손↔제어 목표이며 파지 관절 벌어짐이 아니다. 실제 지지 solver point의 상대속도를 쓰며 발 COM 속도로 바꾸지 않는다.
- 인위적 가슴 회전 fixture는 좌표식 검증이다. 사람이 그 자세로 타격한 실측이나 native가 만들어 낸 회전이 아니다.

다음 타격 후보는 입력 의도를 유지하는 목표와 몸통의 상대속도를 함께 다루고, 실제 어깨·팔꿈치·손목의 합산 토크/일을 기록한다. 동일 목표 비교와 동일 토크 예산 비교를 따로 둔다. 회복은 [자세별 관절 응답](recovery_joint_response_round4.md)의 접촉 상태 의존성을 반영한다. 접촉 끝단은 별도의 절삭 반작용·에너지 예산 후보로 검증하며 무조건 더 강한 피해 배율로 대체하지 않는다.
