무기별 동작 차이를 지금 만드는 장치는 흩어져 있다. 이름표 없이 따로 붙은 스위치들이다.
- `oneHandStance`: 한손 자세표. 라이트세이버만 예외로 뺐다.
- `thrustStyle`: 에스톡·레이피어.
- `enterParry`: 세이버·팔쉬온·청강검.
- `techReachScale`: 팔쉬온·참치.
- `schools.js`: 세이버·팔쉬온은 찌르기를 약하게(`weakThrust`), 청강검·복제품은 기술별 사거리 표.
- `gun`: 리볼버.
- 무기별 간격표 `WEAPON_MEASURES` / ai.js `MEASURED`.

새 무기를 넣을 때마다 어떤 스위치를 켤지 사람이 기억해야 한다.

## 2. 제안: 두 축으로 나누고, 길이는 연속값으로 둔다

동작은 두 가지가 정한다. 하나는 **몸이 무기를 어떻게 다루느냐(몸 틀)**, 다른 하나는 **무엇으로 상처를 내느냐(싸움 방식)**다. 길이는 유형으로 나누지 않고 지금처럼 실측 간격(`measure`)으로 연속 보정한다. 칸을 나누면 경계에 걸친 무기(에스톡 1.29, 롱소드 1.18)가 억지로 갈린다.

### 축 1 — 몸 틀 (자세표·빈손·걸음·되돌리기 속도를 정한다)
| 몸 틀 | 기준 (숫자로 자동 판정) | 무기 | 동작의 핵심 |
|---|---|---|---|
| **A. 양손 보통** | 양손·한손반, 관성 I < 0.4, 무게중심 < 0.3 m | 롱소드, 엑스칼리버, 복제품, 에스톡, 라이트세이버 | 지금 기본. 12 자세(지붕·황소·쟁기·바보…), 빈손이 자루 끝을 잡는다 |
| **B. 양손 앞무게** | 양손, I ≥ 0.3 이면서 무게중심 ≥ 0.33 m (또는 I ≥ 0.6) | 츠바이핸더, 모노호시자오, 냉동 참치 | 칼을 **미리 높이 들고 기다린다**(상단·팔상·어깨). 되돌리지 말고 **멈추지 않는 물레 베기**, 최대 사거리에서 **먼저 세우기**. 되돌림이 느리다 |
| **C. 한손** | 한손 | 세이버, 팔쉬온, 청강검, 레이피어, 나뭇가지, 고무 닭 | 한손 자세표(칼 든 어깨 앞, 손 더 뻗기), 빈손은 뒤로, 몸을 옆으로 세운다. 손목 중심의 작은 동작, 빠른 되돌림 |
| **D. 사격** | `gun` | 리볼버 | 사격 자세(디렉터가 자동 조준 작업 중) |

### 축 2 — 싸움 방식 (기술 목록·AI 선택·판정 쪽을 정한다)
| 싸움 방식 | 기준 | 무기 | 기술·AI |
|---|---|---|---|
| **① 두루** | 베기·찌르기 배율이 둘 다 1 안팎 | 롱소드, 엑스칼리버(둘), 청강검, 라이트세이버 | 지금 기술 목록 그대로 |
| **② 베기** | 베기 ≥ 1.1, 찌르기 ≤ 0.85 | 츠바이핸더, 모노호시자오, 세이버, 팔쉬온 | 찌르기 비중 ↓, 사선·손목 베기 ↑. 한손이면 들어가며 막고 베기 |
| **③ 찌르기** | 찌르기 ≥ 1.3, 베기 ≤ 0.55 | 에스톡, 레이피어 | 겨눔 자세(긴 자세·3번 자세), 칼 길 잡고 찌르기, 찌르기 장점(`thrustStyle`), 런지 |
| **④ 때리기(둔기)** | 날 없음 | 나뭇가지, 고무 닭, 냉동 참치 | **동작은 베기와 같다**(§4-3 결정). 다른 것은 판정뿐이다: 어느 면으로 맞아도 둔기로 치고 날 세움 점수가 없다. AI 는 찌르기 기술을 쓰지 않는다. 둘 다 이미 되어 있다 |
| **⑤ 사격** | `gun` | 리볼버 | 쏘기만 한다 |

### 두 축을 겹치면 — 실제로 쓰이는 칸은 8개
| | ① 두루 | ② 베기 | ③ 찌르기 | ④ 때리기 | ⑤ 사격 |
|---|---|---|---|---|---|
| **A 양손 보통** | 롱소드·엑스칼리버·복제품·라이트세이버 | | 에스톡 | | |
| **B 양손 앞무게** | | 츠바이핸더·모노호시자오 | | 냉동 참치 | |
| **C 한손** | 청강검 | 세이버·팔쉬온 | 레이피어 | 나뭇가지·고무 닭 | |
| **D 사격** | | | | | 리볼버 |

- 동작은 틀(4벌)과 방식(5벌)을 만들면 조합으로 나온다. 무기마다 따로 만들지 않는다.
- 새 무기는 수치만 넣으면 칸이 자동으로 정해진다. 예) 도끼 = 한손·앞무게 날 → C②. 메이스 = C④. 창 = A③(길이 보정).
- **코드로 확인**(`src/weapon_class.js`, `node tools/sim/weapon_classes.mjs`). 가상의 새 무기를 부품 질량만 넣어 판정하면:

| 무기 | 판정 |
|---|---|
| 한손 도끼 | C 한손 · ② 베기 |
| 메이스 | C 한손 · ④ 때리기 |
| 양손 대형 도끼 | B 앞무게 · ② 베기 |
| 창 | E 자루 무기 · ③ 찌르기 |
| 할버드 | E 자루 무기 · ① 두루 |
| 카타나 | A 양손 보통 · ① 두루 |
| 단검 | C 한손 · ① 두루 |

  찌르기 방식은 베기 배율 0.6 이하일 때만이라, 베기 0.8 인 단검은 두루가 된다. 스펙에 `style: 'thrust'` 를 적으면 바뀐다.

### 창 같은 자루 무기는? — 몸 틀 하나(E)를 더한다 (사장님 질문)
창은 싸움 방식으로는 ③ 찌르기에 그대로 들어간다. 그런데 몸 틀은 A~D 어디에도 맞지 않는다. 몸 틀을 가르는 것은 "손이 몇 개냐"가 아니라 **"손과 무기가 어떻게 붙어 있냐"**이기 때문이다.

| | 칼 (A~C) | 창·자루 무기 |
|---|---|---|
| 손 위치 | 자루 끝 한 곳. 두 손이어도 0.14~0.22 m 붙어 있다 | 두 손이 자루 가운데쯤에 **0.5~0.8 m 벌어져** 있다 |
| 손 뒤쪽 | 폼멜뿐 | 자루가 뒤로 길게 남는다(물미·뒷날로 치기도 한다) |
| 무게중심 | 손 앞 0.05~0.45 m | **두 손 사이**. 지렛대처럼 앞손을 받침으로 돌린다 |
| 찌르기 | 팔을 뻗는다 | **자루를 앞손으로 미끄러뜨려** 뻗는다(뒷손이 민다). 사거리 2~2.5 m |
| 가까워지면 | 칼자루·폼멜 | 자루를 짧게 잡거나(손 옮기기) 자루로 막고 밀친다 |

→ **E. 자루 무기(장병기)** 틀을 둔다. 자동 판정 기준은 "두 손 간격 ≥ 0.4 m 또는 손 뒤 길이 ≥ 0.4 m"다.
  - 코드(`weapon_class.js`): 스펙에 `handGap` 이 없으면 두손 무기의 뒷손 자리(`gripAlong`)로 잰다. 로스터 칼은 0.14~0.22 m 라 그대로이고, 봉·창 시제품(`tools/sim/pole_specs.mjs`, 뒷손 0.6 m)은 E 로 들어간다.
- 창 = E③(찌르기).
- 할버드·폴액스 = E②/④(내려찍기·끌어당기기), 쿼터스태프 = E④.
- 두 축은 그대로 쓰고, 틀 칸만 하나 는다. 새 무기가 새 몸놀림을 요구할 때만 틀이 늘어나는 구조다.

**만들 때 드는 일 (지금 로스터에는 없어 당장 할 일은 아니다):**
- 지금 물리는 "손 = 자루 원점, 무기는 손 앞으로만"을 가정한다.
- 창을 넣으려면 네 가지가 필요하다: ① 손 뒤로 뻗은 자루(콜라이더·질량), ② 앞손을 0.5 m 넘게 떨어진 자리에 쥐기, ③ 찌를 때 자루가 손 안에서 미끄러지는 동작, ④ 간격표 2 m 넘게.
- fighter.js 손 잡기와 얽혀 칼 무기 추가보다 한 단계 크다(추정: 새 동작 한 벌 + fighter.js 이음 몇 줄).

## 4. 결정이 필요한 것
1. **두 축(몸 틀 4 × 싸움 방식 5)으로 갈까요?** 스펙에 `frame`·`style` 두 칸을 두고, 적지 않으면 위 기준으로 자동 판정한다. 지금 흩어진 스위치(`oneHandStance`, `enterParry`, `weakThrust`, `thrustStyle` 켜기 등)는 이 둘에서 따라 나오게 정리한다.
2. **라이트세이버의 몸 틀 — 결정: A 양손 보통 × ① 두루** (사장님 "찾아보고 정해", 무기 PM 결정).
   - **근거:**
     - 영화의 기본 칼놀림은 밥 앤더슨(올림픽 에페 선수)의 안무다. 에페와 검도를 바탕으로 긴 자루를 두 손으로 쥐고 크게 내려친다.
     - 한 손 칼놀림(마카시, 두쿠 백작)은 손바닥에 맞는 **휜 자루**를 쓰는 특수한 유파다. 우리 라이트세이버는 곧은 자루다.
     - 우리 자루는 폼멜~이미터 0.27 m라 두 손이 들어간다.
     - 칼날이 가벼워 두 손의 힘보다 두 손의 **제어**가 쓸모 있다(설정상 자이로 효과를 두 손으로 다잡는다).
   - **바꾼 것:** `grip: 'one-hand' → 'two-hand'` 한 줄. 빈손이 자루를 함께 쥔다. 자세표는 원래 양손표였다.
   - **잰 값:**
     - ability_test 롱소드 상대 48판: 한 손 63%(95% 48~75) → 두 손 65%(50~77), 에픽 목표 안.
     - 간격 실측: contact 1.46 → 1.45, reach 1.65 → 1.69로 거의 같아 AI 간격표는 그대로 둔다.
     - 브라우저 콘솔 에러 0.
     - fights12·live_battery 에는 라이트세이버가 없어 영향이 없다.
   - 출처(2차 자료): Wookieepedia "Lightsaber combat", Form II(Makashi) 항목, ESPN 밥 앤더슨 부고 기사.
3. **날 없는 무기(④)의 동작 — 결정: 베기와 호환(같은 동작), 새로 만들지 않는다** (사장님 "찾아보고 정해", 무기 PM 결정).
   - **동작이 같은 까닭:**
     - 베는 선(위에서, 사선, 아래에서, 옆으로)과 자세는 무기가 아니라 **몸이 휘두르는 길**이다. [해석]
     - 곤봉·몽둥이도 같은 길로 친다. 마이어(1570)는 짧은 막대를 자루 무기 수련 도구로 쓴다. 칼과 막대가 같은 몸 기본기를 나눈다는 뜻이다. [원전 2차 요약]
   - **다른 것은 네 가지이고, 모두 판정층의 일이다:**
     1. 날 세움이 필요 없다. 칼은 면으로 맞으면 튕긴다.
     2. 당겨 베기가 없다.
     3. 힘이 머리(무거운 끝)에 실린다.
     4. 갑옷 위로도 충격이 들어간다.
   - **우리 코드는 이미 그렇게 한다:**
     - 날 없는 무기는 늘 둔기 판정이다(`combat.js` isBlade). 날 세움 점수가 없어 어느 면으로 맞아도 제 힘이 든다.
     - 머리 무게는 질량 분포가 물리로 반영한다(참치 무게중심 0.40 m).
     - 둔기 배율은 `mBlunt` 가 맡는다.
     - AI 찌르기 기술은 `schools.js` 에서 이미 뺐다.
     - 남은 것은 손목이 칼 면을 맞추려고 비트는 힘뿐이다. 판정에 영향이 없고 겉으로도 거의 안 보여 그대로 둔다.
   - **결론:**
     - ④는 "동작 한 벌"이 아니라 "판정·기술 거르기" 칸이다. 새 동작도 밸런스 재측정도 없다.
     - 우선순위에서 빠지고, 다음은 B 물레 베기다.
4. **순서 제안**:
   1. 분류 칸 추가. 동작은 그대로라 칼 싸움 결과가 바이트 동일해야 한다.
   2. B 물레 베기.
   3. C③ 런지·C② 손목 베기.
   - 단계마다 fights12·hybrid·live_battery 회귀와 롱소드 상대 승률(95% 구간)을 재서 보고한다.
