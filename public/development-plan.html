비용과 실험 규칙

  1. 시작마다 예상 시간을 보고하고, 30~60분 안에 원인/실제 실행/막힌 지점 중 하나를 남긴다. 환경·검증 문제로 예상이 달라지면 갱신한다.
  2. 첫 검사는 같은 상태의 건강/손상 두 조건·후보 최대 2개로 좁힌다. clone/계측/실제 dispatch 관문을 먼저 확인하고, 개선 근거가 있을 때만 무기·외란·입력을 넓힌다. 이미 byte-identical인 seed 반복은 새 독립 표본으로 세지 않는다.
  3. 기존 ledger·native API 교정·관절/모델 조사·실패 trace를 재사용한다. source/엔진/입력 계약이 바뀌었을 때만 해당 근거를 다시 검증한다. 오래된 조사 내용을 현재 결함으로 가정하지 않는다. PM별 소유 파일과 격리 후보를 지정하고, 비교 배치 중 공용 core·엔진·기존 도구를 동결한다. 통합은 디렉터가 순차 수행한다. 다른 PM의 수정 때문에 sourceStable이 깨진 실행을 유효 비교로 쓰지 않는다.
  4. 원자료는 새 경로에 쓰고 소스·설정·명령·벽시계 시간·실패를 보존한다. 명시적 힘/일, native 마지막 substep, 접촉 충격량, 사용자 체감을 혼동하지 않는다. 전체 native work를 현재 측정할 수 있다고 가정하지 않는다. 질량/관성을 바꾸는 실험은 허용한 물성 차이를 명시하고 자세·속도·입력의 동등성을 따로 검사한다. 서로 다른 물성에 native snapshot 전체 일치를 요구하거나, 다른 무기 비교를 질량만 바꾼 실험으로 부르지 않는다. Q04는 실제 검 질량·COM·관성 및 적용 한도를 기록하고 동일 목표/입력 비교와 동일 토크 예산 비교를 별도로 판정한다. 서로 다른 검의 속도 차이 하나로 관성 개선을 선언하지 않는다.
  5. 같은 구조 가설이 두 번 실패하면 gain/시간값 전수 검색을 멈추고 첫 실패 원인의 관측 또는 다른 경로로 이동한다. 새 증거가 있어야 실패 가설을 다시 연다.
  6. 디렉터는 목표/인터페이스를 조율하고 난도가 높은 원인 분리와 통합을 직접 맡는다. 단순 표 정리와 같은 로그 반복 읽기에 독립 구현 PM을 소모하지 않는다.
