운영자가 한 번 연결하면,
게이머는 바로 시작합니다.

이 페이지는 게이머 가입 절차가 아니라 운영자 준비 안내입니다. 현재 실제 서버는 없습니다.

1. 프로젝트 생성

Supabase 대시보드에 로그인하고 New project를 선택하세요. 이름은 stillness, 지역은 이용자와 가까운 지역을 고르면 됩니다. 데이터베이스 비밀번호는 본인이 안전하게 보관하세요.

2. 공개 연결 정보 전달

프로젝트의 Connect/API 설정에서 Project URL과 publishable key를 찾아 개발 채팅에 알려주세요. 이 두 값은 브라우저에 넣는 공개 정보입니다.

데이터베이스 비밀번호, secret key, service_role 키, 개인 access token은 채팅에 보내지 마세요.

3. 저장소 준비

새 프로젝트의 SQL Editor에서 아래 SQL을 붙여넣고 Run을 한 번 누르세요. 계정별 설정·성장 데이터와 권한을 만듭니다.

SQL 파일 받기

이전에 계정 테이블을 만든 프로젝트라면 전체 SQL을 다시 실행하지 말고 개발자에게 알려주세요. 기존 자료를 덮어쓰지 않는 추가 적용 경로를 사용합니다.

4. 간단한 가입 켜기

Authentication 설정에서 Anonymous sign-ins와 Manual identity linking을 켜세요. Email provider도 활성화합니다. Site URL에는 실제 게임 주소를 넣습니다.

5. 계정 복구용 이메일

기본 발송은 수신자·발송량에 제한이 있으므로 일반 게이머에게 인증 메일을 보내려면 운영용 SMTP 발송 설정이 필요합니다. 이메일 템플릿의 Magic Link와 Change Email에는 인증번호 {{ .Token }}을 표시합니다. 메일 발송 서비스가 정해지면 그 서비스 기준으로 연결을 마무리하겠습니다.

게스트 저장부터 시험할 수 있지만, 이메일 복구가 검증되기 전에는 기기 변경·데이터 삭제 후 복원을 보장하지 않습니다. 현재 CAPTCHA 입력은 구현하지 않았으므로 CAPTCHA를 켜려면 먼저 해당 화면을 연결해야 합니다.

제가 이어서 할 일

프로젝트 연결 후 실제 계정 2개로 데이터 분리, 승리 보상·구매·강화, 동시 요청·재접속·다른 기기 복원을 검사합니다. 시험 보상은 시험 계정 공간에만 적용되며, 일반판 수치는 별도로 결정합니다.

이번 서버는 거래의 중복·음수 잔액을 막지만, 휴대폰이 보고한 승리를 실제 경기로 검증하는 서버 심판은 아닙니다. 유료 재화·경쟁 순위·사용자 간 거래는 현재 범위에 없습니다.
